# Daoris (道衍) — open work

Open work only: a finished row moves to `docs/task-archive.md`, a release change goes to `CHANGELOG.md`, and parked rows stay
whole in `docs/backlog-parked.md` until one is moved back here. A row says what is open and why; its contract is its design or its
area document under `docs/areas/`. Each row's earlier full text is in git at `7a8961f2ab:TASKS.md`.

**Standing direction.**

- The order now (2026-11-14), replacing 2026-11-13's, itself 2026-11-05's replacement, whose builders ran no tests and whose merges carried
  no gates (D180's note). **P0** land and publish what is built (the integration, a scan for private names, the push, the install
  republished with its debug port). **P1** the foundation that ends the merge gate's cost: LAYERS1 f with the repository port, then
  REACHREPLAY1, MERGEFLOW1b, ADMIT1, MERGETS1's rest and GITLIB2 (LAYERS1's packages, D286, whose dependency tests run only when their
  package changes). **P2** every development gate green and inside its budget (a unit test in seconds, a Process case under 2 minutes,
  a gate under 5, a suite under 10), the full set green and measured, and publishes gated again (HOMEBENCH1, TESTSLOW1, TESTDIET1,
  TESTHOSTEND1, BUILDRACE1, CIEND1, FULLSET1). **P3** rows run through the installed Daoris and Lyntai and measured (RCASE1, DOGFOOD1, then
  SELFLAND1, QUESTLIST1, STAFFSIGNIN1, SCANCPU1, the memory and Codex measures). A defect found on the way is fixed when found;
  the owner-named defects (NOTIFYDIET1, BANNERS1, ASKANSWER1) are fixed when reached; new features wait until P1 and P2 hold.
- The product's optimization (ROADMAP's priority 12) comes after the foundation, the structure and the agents' work; the tests' own
  time is the order's second step. A defect found on the way is fixed when found (2026-11-01).
- The steward carries the backlog with as little of the owner's input as the grants allow, and treats development speed, token
  cost and branches or processes left behind as defects Daoris must handle (2026-10-30, D193).
- Keeping knowledge current is a focus (D220): a fresh fact replaces the one it updates, and tests pin rules rather than counts.
- Development moves into the install's driven sessions wherever a row allows. Codex's short allowance serves brainstorming,
  cross-reads and tests of Daoris's Codex paths, not building; its owed reads are Opus reads while its spend cap holds (D240 point 9).
  The parent republishes the install when a batch is worth running, restarting it rather than staging under running sessions (2026-10-27).
- Spend ordinary subscription allowance only: checkpoint at a limit and resume when it returns; no extra or reset credits, no
  API-billed fallback, no duplicate workers or repeated checks (2026-10-27). A proof that needs an account's model runs once, at the
  least that proves it, and its spend is reported (D240 point 7).
- A method that proves itself in the steward's development (a co-design pass from a purpose brief, a prior-art survey and a comparison; a scope built in waves and verified once; an independent review before landing; a day's failures turned into class rows) is adopted by Daoris itself in the same scope: in `canon/` for every repository it serves, and as a feature where Daoris runs the work (a workflow, a role's routine, Ask Daoris), so its own sessions work the way the steward does (2026-11-16, METHODS1).
- Every time breach has its why (2026-11-17): a test or gate over its time is classed by cause (a process or real git in a unit test, disk beyond its temp folder, the network, a wall-clock wait, a full source scan, or load alone) and taken down that cause's path: a unit test is fast and pure, so one that is not moves to an adapter's package behind a twin-proved fake, a heavy domain separates into a package of its own, and one that is fast alone but still times out is reviewed for separation too.
- A dependency a row names ("after X") completes before the row starts. Installed proofs are batched against one staged build.
  Owner-only work (downloads, account spending, installation, publication, decisions) keeps its grants and holds.
