## AGENTLYNTAI1 — Codex’s proposal

**Lyntai should own the reusable agent machinery. Daoris should adapt that machinery to its existing records, selection policy, permissions and window. Move one working facility or door at a time, preserving its behavior; request missing library capabilities before replacing their working implementations.**

The destination is one implementation of agent protocols, failure decoding, restriction reduction and execution capabilities in Lyntai. It is not two provider frameworks kept equivalent, and it is not Daoris adopting a less capable transport because that transport already exists in a package.

### 5. What is known and what admits a run

`AgentAbility` is sufficient for a library claim. It is not sufficient for Daoris’s measured admission.

Daoris retains the eight-fact applicability envelope:

1. Door.
2. Agent version.
3. Adapter version.
4. Posture.
5. Writable-root kinds.
6. Network and loopback reach.
7. Operating system.
8. Settings digest.

These are the accepted comparisons, including roots compared by kind rather than a session’s literal path (`docs/2026-10-26-agent-provider-design.md:329`; S §1).

The adapter reads library source, evidence, support and version without upgrading their strength. Host measurement evidence remains beside the library object. A prior opening’s negotiation can narrow a candidate; it cannot admit a new opening.

Stated absence keeps its existing explicit fallback. It does not become `Supported` because the library guard only refuses `Unsupported`: the library’s `Unknown` may reach negotiation, but Daoris’s admission still requires the evidence appropriate to the requested operation (`Lyntai/Core/Agents/AgentProviderDescriptor.cs:103`).

COAGENT1e builds one effective sheet from these sources. A mismatch in any applicable measurement fact prevents measured admission. This is host evidence management, not a second library ability registry.

### 6. The run: preserve live behavior before moving it

Do **not** replace the existing conversation with repeated one-turn calls.

Lyntai currently defines one `StreamAsync` call as one turn and starts ACP’s process for that turn. Daoris keeps a live ACP connection, queueing and steering, model/posture changes and held requests; its native conversation also keeps stdin open. These are incompatible lifetimes, not an implementation detail (S §8; `Agents/Acp.cs:299`, `:639`, `:2091`, `:3444`; `Lyntai/Core/Agents/IAgentSession.cs:9`; `Lyntai/Basic/Acp/AcpAgentSession.cs:14`).

**Ask for Q-L now.** D233’s trigger is already met by a host that needs words taken mid-turn. The request carries the existing evidence and asks Lyntai to measure, separately:

- Native Claude framing and keeping-stop.
- Claude ACP queueing, steering and background wake.
- Codex ACP’s actual supported operations.
- `dsh`’s supported protocol operations.
- Permission waiting and cancellation while held.

No common capability is inferred from one of those measurements.

Until the released capability passes parity:

| Door | Execution during transition |
|---|---|
| Claude native | Existing Daoris native conversation and reader. |
| Claude ACP | Existing `AcpSession`. |
| Codex ACP | Existing `AcpSession`. |
| `dsh` and plugin ACP | Existing transport and declarations. |
| Existing stand-ins | Existing behavior; both remain in the meter. |
| New alternate stand-in | Library-backed supported subset, with unsupported operations explicitly refused and remaining cases pending by name. |

Failure or allowance decoding may move before transport ownership because Q-F and `IAgentUsageSource` do not require changing the conversation.

The eventual live adapter exposes open, exact resume, apply-choice, send, steer, stop-turn, stop-task and close only where the library capability supports them. Course retains the kept conversation, word references and movement decision. Each adopted door must start, take multiple turns, resume its own conversation, cool and end before its legacy implementation is deleted.

Reject “restart the process each turn”: it would lose measured live behavior. Reject “implement the missing live framework here and move it later”: D213’s direction expressly rules that out.

### 7. Accounts, holds and the one walk

**Initially take the restriction vocabulary. Adopt the library’s reduction through Q-R when it has a supported host-state seam. Do not take today’s operational `AgentAccountPool` as Daoris’s selector.**

The current pool chooses one seat per turn, writes through its own key-value representation, and explicitly excludes several processes sharing a pool. Its reducer and hold rows are internal. Daoris’s roster supports several processes on one home and its start selection has different lifetime and reservation rules (S §8; `Lyntai/Core/Agents/AgentAccountPool.cs:18`, `:32`, `:61`; `AgentPoolReducer.cs:8`, `:28`).

Q-R requests reusable reduction without a second walk:

- Roles supplies candidates in D205’s order.
- The roster supplies D197’s account ordering and use policy.
- The library evaluates applicable restrictions.
- The host commits the chosen reservation and any probe lease atomically.
- The settled selection reaches the launcher once.
- No provider selects again at open or at every turn of the existing conversation.

Daoris implements storage and transaction ports over its own store. It does not reproduce reducer logic or use reflection to call internals.

**Legacy cooling remains legacy cooling.** Read `cooling.json` by owner and profile, including the empty own-home account, with its current fields and fallback behavior. Do not import it into a second writable authority. New restrictions first live in new isolated-home tables; a legacy cooling entry can be projected as legacy evidence without changing its old writer’s meaning.

The AGENTINFRA1 mapping is:

| Infrastructure fact | Library fact and host remainder |
|---|---|
| Cause | `RestrictionCause`, directly. |
| Account / shared pool / model / endpoint | `RestrictionSubject`, with an explicit host binding to the evidenced subject key. Never parse display `Scope`. |
| `model-on-binding` | Library model restriction plus the host’s binding/composition identity; do not silently widen it to every execution using that model string. |
| Reset / retry-not-before / unknown | `RestrictionRecovery`, with original provenance retained. |
| Owner-action reason | Library `OwnerAction` plus host reason such as refill, sign-in or configuration change. A clear is not proof that the action happened. |
| Restriction id and revision | Preserve the library’s supported reduction identity/revision together with the host record revision; they serve different purposes. |
| Observed time, evidence, dialect version | Host evidence envelope over the library restriction. |

The difference is concrete: `AgentRestriction` has three members, while `AgentHold` carries id/revision and observed time (`Lyntai/Core/Agents/AgentFailure.cs:104`; `AgentPoolModels.cs:109`). They are not member-for-member equivalents of the infrastructure record.

D197, D205, D206 and D125 therefore stand for ordinary homes. In an isolated new-semantics home, Q-R uses D227’s all-restrictions rule, revision-checked release and single probe. Compatibility policy supplies a sixty-minute unknown-limit probe only where the accepted Daoris policy calls for it; explicit owner action remains held. No claim of cross-process atomicity is made until the two-process proof passes.

### 8. Failures, recorded sentences and words

A failure is classified **once**, then consumed everywhere.

During transition, an unmoved door uses `AgentErrors.Read`; a moved decoder returns `AgentFailure`. A single adapter converts its result into Daoris’s existing outcome. Do not run both classifiers in production and choose the more convenient answer.

Q-F must preserve:

- Trusted failure source before classification.
- Harness stderr read for credential refusal alone.
- D210’s limit, access, transient, fatal precedence.
- Door-specific codes, including authentication codes, before inherited interpretations where the existing rules require it.
- Own-table shadowing of owner entries.
- Recorded reset semantics and negative near-matches.
- Fatal for an unread failure.

These are implemented at `Agents/AgentErrors.cs:133`; Lyntai’s current shared sentence reader is `Lyntai/Core/Inference/ProviderVerdictClassifier.cs:69`, while ACP’s reader is internal (`Lyntai/Basic/Acp/AcpFailure.cs:41`; S §8). Merely calling the shared sentence reader does not reproduce D210.

Vendor sentences belong in the library’s relevant scoped decoder. A newly recorded Daoris sentence is sent as a quest containing its sanitized trusted frame, version, phase, expected result and near-negative. Until a released decoder accepts it, that door remains on the old reader. Do not install a process-wide `AddErrorTextMatcher`: its string-only hook cannot preserve door/source distinctions and could change the service’s unrelated classification.

Keep three concepts separate:

1. **Failure kind** decides retry, cooling or conclusion.
2. **Delivery disposition** constrains repetition.

### 17. Unreleased builds: D22 stands
