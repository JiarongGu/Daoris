## 2. The shape

### 2.1 In one paragraph

**The layer is what a door is; Daoris is what is done with doors** (O §1.1). A door in the layer's sense (a process started for a turn,
spoken to and read, with its descriptor and claims, its events, its typed failure with restriction and delivery, its usage reading and the
account home it is handed) is Lyntai's, built and released there, and Daoris writes none of it again. What a host does with doors stays
Daoris's: ids and records, the account rule, the walk and the cool-off, the start plan, the shell that completes a spawn with Daoris's
variables and the launcher that contains it, the readings and their sink, reach, the programs' pins, the rule language, connectors, plugins
and the meter. `Agents/Contract` stays Daoris's host contract and shrinks as doors move. Each door is **Daoris-run**, on today's transports
and unchanged, or **layer-run**, bound to one Lyntai provider and door and reading every fact the layer states from that provider's
descriptor. A door, or one run kind of it, becomes layer-run in one row, when a Lyntai release carries every reading and operation Daoris
uses on it today and the two paths, compared in one commit, show it case for case (§6.3); a transport retires when its last door has left. The adapter is one folder,
`Agents/Layer/`; the census and `StructureTests` hold every Lyntai type there and in the providers' folders.

### 2.2 The line, and when a door moves

Rows that change **how Daoris calls a door** (d, e's host half, f, g, h's shell, l's sink, m's executors over `AgentRun`, n, o, p, q, r, u
and every correction) are needed whatever runs beneath, and they make a later move invisible to the callers: they stay Daoris's and build as
accepted (O §1.2); m's first part, m-i, lands before 1b-i, since every layer path is reached through an executor holding `AgentRun`
*(O1-F1)*. Rows that change **what a door does inside** (i, j's seam, k, l's four readers made one, e's usage readers and stream
words) have their counterpart in the layer and would be retired the day their door moves: they are not built (both). **A door, or a run kind
of it, moves when** (the brief §10 point 2): its release carries each reading and operation the door uses today; in the moving row's own
commit, every case that drives it runs on its old path and on the layer's and §6.3's oracle finds what each observed equal, a regression
planted on the layer path failing it, its pending file not growing; its spawn table (the resolved program, the argument vector compared flag
by flag, every variable, the working directory) equals today's (the brief §10 point 3); and its model-free real-process proofs run through the
new path (§1.1 row 19). **A move row states no difference** (D213 point 10, kept for every row this design adds) *(O1-F4)*: each one found
is a correction row of its own, landed on today's path before the move, or a request to Lyntai the move waits for, and the row that would
carry it waits; round 1's *a decision note or a request* inside a move is withdrawn. A door that would lose a reading, an operation or a
posture does not move.

### 2.3 Not a copy

Four rules keep the adapter from being the copy D213's note rejects, each held by a test (O §1.3, X §3):

1. **No Daoris type mirrors a layer type.** Where a Daoris type already holds the fact for Daoris-run doors (`KnownBy`, `Transport`,
   `Eligibility`, `DoorFailure`), the adapter maps the layer's value into it at the boundary; nothing above `Agents/Layer/` sees the layer's.
2. **A layer-run door declares nothing the layer states, per run kind** *(O1-F3)*: for each kind its binding covers, its ability names
   and failure tables are read from the bound descriptor and reader; its home variable and its account key are read from the descriptor
   for every kind once one kind is bound, the Daoris-run kind included, so the door states each once *(O2-F9)*; a kind still Daoris-run states its spawn, dialect
   and tables as today, and they serve that kind alone. A registration declaring a fact beside a binding that covers it is refused by
   `ProviderFilesTests`, naming the fact and the kind.
3. **One home per fact, counted per kind**: the census counts a fact a layer-run kind restates as a site with no allowance, and a fact the
   Daoris-run kind of the same door states as that kind's.
4. **What the layer replaces is deleted** (X §3): a door's transport readers go in the commit that moves the last run kind reading them,
   on every door that references them, never kept as a second implementation (so Claude Code's driven spawn and reader go in whichever of
   1d and OPENROUTER1's move lands last, its tables at 1f-i once no Daoris-run door reads them, §9.3) *(O1-F12)*, and a library upgrade edits
   `Agents/Layer/` and the providers' folders alone.
