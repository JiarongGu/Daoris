## D231 — Code is kept in small, cohesive units: new behaviour goes in a unit of its own, a file over the budget does not grow, and comments say why, not what happened (2026-11-04)

**Decision (CODESHAPE1, the owner's direction of 2026-11-04).** 267 source files are over 40 KB. The largest are the
composition roots and their tests (`Loop/Driver.cs` at 360 KB, `tools/merge-branch.mjs` at 524 KB and its test at 563 KB), and in
those, comments are 36 to 50% of the bytes. The cause is how the work was run, not the code's contracts:
- each row was briefed against the file that already held its area, and added a method and a paragraph to it;
- no design and no read judged a unit's size or cohesion;
- "one way" (D228) was read as one class;
- the structure gates checked layers, not size.

1. **New behaviour goes in a unit of its own,** a named type for its job, in the subdomain that owns it: never a `partial` of the
   hub (PART1, `tools/partials.mjs`), which only moves the hub's bytes into a second file. A composition root (`Driver`,
   `ChatRunner`, the host's `Program`, the service's `Program`) wires units and holds no rule of its own (the structure design's
   Loop rule, applied to every root).
2. **A file over the budget does not grow.** The budget is 40 KB with LF endings. `tools/size-ratchet.mjs` holds each file over it at
   its size (`tools/size-ratchet.json`); a new file may not start over it, and the list only tightens. It runs in `npm run verify`.
3. **Comments say what the code cannot:** why a choice was made, a trap, a boundary's contract. Row ids, decision numbers, design
   section references and what a unit used to do belong in the decisions, the commits and the FIX-LOG, which the knowledge index
   already serves.
4. **The existing hubs are split and their comments cut** as one chunk (CODESHAPE1) once the current scope's development is done and
   before its one verification (D180's note of 2026-11-04), so that verification covers it. The generated outlines
   (`docs/index/outlines/`, ORIENT1) are judged again after it: a file small enough to read whole needs none.

**Rejected:** a budget enforced only on new files (the hubs are where the cost is); deleting comments wholesale (a boundary's
contract and a trap's why are kept); splitting by line count alone (a unit is split by responsibility).
