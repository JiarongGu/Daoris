## D344 — Daoris's releases are GitHub releases of its public repository that installs read; an update installs when idle and is never the owner's question (2026-11-20)

**Decision (UISH11, UIST5, UIST12, UIST14, the window redesign `docs/2026-11-19-window-design.md` §14; the owner's direction of
2026-11-19; amending D139).**

1. Daoris publishes its own releases as GitHub releases of its public repository, and an install's updater reads them and stages
   a new one by itself. The first release waits for the owner's go (a Release wait); later releases follow the release workflow's
   declaration.
2. An install's update mode is *when idle* by default, with no word from the owner; the drain and its bound stay as D139 and D327
   say. The status strip's item and Settings › Install and updates say in one sentence per state what the update does (staged,
   holding new work and until when, installing, installed, rolled back, refused); *Install now* stays; a history keeps the last
   installs with what each cut.
3. An update is never a wait: a rolled-back or refused install is a *Since you left* line, and a Failed wait only when it is
   refused again after the agents' retry. The update banner goes.

**Why.** The owner: Daoris publishes its own releases, which an install's updater reads, the first on their go. An update the
owner must approve each time holds the company on a question that is not theirs; one that installs when idle and says what it did
keeps the pace.

**Rejected.**

- *Publishing to this machine only*: the owner's answer; an install elsewhere would never update.
- *An update as a question to the owner*: not on the closed list of owner things.
- *Keeping the banner beside the status strip's item*: one fact in two places.
