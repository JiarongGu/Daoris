## D344 — An update installs when idle and is never the owner's question; the window says it in one place (2026-11-20)

**Decision (UISH11, UIST5, UIST12, UIST14, the window redesign `docs/2026-11-19-window-design.md` §14; the owner's direction of
2026-11-19; amending D139's banner).**

1. **Where releases come from is RELEASEFEED1's decision (D329)**: Daoris publishes its own releases from its public repository
   and an install reads them. This decision takes it as given. What RELEASEFEED1 leaves to the window (UIST14, after it): the first
   release waits for the owner's go, as a Release wait, and the running app looks for a new release by itself and says when it last
   looked.
2. **No word from the owner.** The install's update mode is already *when idle* by default (install-home-update rule 37); the drain
   and its bound stay as D139 and D327 say. What changes is how the window says it: the status strip's item and Settings › Install
   and updates say in one sentence per state, from one key, what the update does (staged, holding new work and until when,
   installing, installed, rolled back, refused); *Install now* stays; a history keeps the last installs with what each cut. The
   update banner goes.
3. **An update is never a wait.** A rolled-back or refused install is a *Since you left* line; refused again after the agents'
   retry, it is a *gave up* line with what was tried (D336), never a question.

**Why.** An update the owner must approve each time holds the company on a question that is not theirs; one that installs when
idle and says what it did keeps the pace. One fact belongs in one place, and the banner repeated the strip.

**Rejected.**

- *Deciding the release source here*: RELEASEFEED1 decides it (D329); two decisions for one source.
- *An update as a question to the owner*: not on the closed list of owner things.
- *Keeping the banner beside the status strip's item*: one fact in two places.
