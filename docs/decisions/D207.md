## D207 — A modular CI: each merge waits on a scoped run of what it reaches, in minutes, on a candidate commit in a tree of its own; the full set runs in the background on its own schedule, never blocks a merge, and is what a republish of the install waits for; the rehearsals leave the per-merge path and run side by side; every test's value is measured and the git half cut to fit (2026-10-24)

**Decision (CISCOPE1, proposed 2026-10-24).** **Status: proposed**, round 2 (the note at the end), to be read again. Written by Claude Opus under D191; it
changes a foundation (what a merge and a stage wait for, which D115, D180, CI1, GATESLIM1 and PROCREACH1 rest on), so Codex reads it
and an independent Opus reader reads it as a foundation, and the steward accepts after both. The contract is
`docs/2026-10-24-ci-scope-design.md`. Its §2 gives the measurements this rests on, and its §10 the questions for the readers.

The owner directed on 2026-10-24 that CI be scoped to what a change needs, module by module; that the full run go to the background
and never block development; and that the tests are too many and too verbose. Measured on this machine: a `--ci` run took 38 to 74
minutes. Its wall was the git half (24 to 44 minutes, whole whenever a merge reached `Trees`) and the family and deployment
rehearsals one after the other (`6ce6235`: 74 minutes with almost nothing else to run). One run (`f296996`) spent 31.5 minutes on a
git half whose every class already had a standing pass.

1. **Modules and a census of every test unit.** A module is a source area (a project's first folder, a CLI module folder, a page
   folder, a tool file). Every test unit (a .NET class in either half, a `node --test` file, a vitest file, a spec, a rehearsal) has a
   **reach** and a **subject**. The reach is PROCREACH1's census at the area grain, extended to the fast halves, the TypeScript
   suites (their import closure, and the files their strings name) and the rehearsals. The subject is the module its file sits under.
   Fixture and twin rules are derived from the strings and held by a census check that fails on any unit, file or hand rule the
   census and the runners disagree on (design §3).
2. **A scoped run per merge.** The merge tool makes the merge as a candidate commit (`write-tree`, `commit-tree`) and lets the main
   checkout go. It runs the scoped set in `local/scope-tree` and fast-forwards main only on green. The scoped set is the cheap checks
   (universal, code map, index, censuses, records, words), every reached unit of the fast suites, and every reached class of the
   driver's other Process half and the modules'. The git half runs its reached classes whose subject changed, in value order, within
   a declared budget (eight minutes). The rest are recorded as **owed** to the background run. Expected: 10 to 16 minutes for a
   driver merge, 3 to 6 for a page, CLI or tools merge, 2 to 3 for records (design §4).
3. **The full set in the background.** `--ci --watch` runs every gate whole in `local/gate-tree`, as a guest on the machine. It
   runs when the machine stays idle, nightly (PROCREACH1's sweep) and before a public release. It never holds the scope tree and never
   blocks a merge. Its failures go to `local/ci-findings.json`, are filed as rows and fixed forward. A filed failure is **known red**:
   a scoped run that reaches it says so without counting it against the merge, and a scoped pass of it clears it (design §5).
4. **What a republish stages.** The owner's install may be staged from a scoped-green or `owed` commit (`--from-scoped`). It is
   never staged on that alone when the commit reaches the install's own update path (the deployment rehearsal runs for that stage),
   when the census could not be read, or when a cheap check failed. A public release needs the background run green on that exact
   commit with nothing owed, swept or known red (design §5.3).
5. **The rehearsals.** No scoped run runs one, but for the deployment rehearsal under point 4. In the background each runs in a
   worktree of its own, beside the others. Their ports, homes, pipes, builds and memory are already apart (design §6.2), and what
   kept them in turn was the CLI folder's pack in a shared tree. Load beside each other is measured before it is relied on, with
   REHLANE2b's pairs as the fallback.
6. **Each test's value** (TESTVALUE1 folded in). Measured per unit: runtime, an append-only failure history whose **catches** are
   failures fixed by a non-test change, and unique coverage (one coverage run per class or file, in the background). A unit with no
   unique coverage and no catch over the window is removed; units covering the same lines become one table; a Process case a
   fast-half stand-in can reach moves down a tier; a sentence that is not a test's subject is asserted by its key. No line or branch
   loses its last cover. The target is the git half under 40 minutes of class time (158 today), so the budget covers a whole `Trees`
   change and the git half becomes exact, and the fast suites' redundant set removed as measured (design §7).
7. **Rows in build order** (design §8): CIFAST1 first, as filed (the fastest win); CISCOPE1b, a half whose classes all stand passes
   without running, the sweep moved to the background; CISCOPE1c, the census; CISCOPE1d, the scoped run; CISCOPE1e, the background
   run and the rehearsals side by side; CISCOPE1f, the value measures; then TESTVALUE1's passes, the git half first.

**Why.** A merge's real reach is minutes everywhere but the git half (design §2.2: 4.7 minutes of the driver's other half and 1.3 of
the modules' by reach, a mean over 31 merges). What made the CI slow was coalescing many merges into one wide delta, two rehearsals
in turn that every driver change reaches, and a git half that is one module's integration suite. The grain was not the cause: the
module-closed and area grains cost the same, and the file grain saves a third only by dropping a module's own calls (design §2.3).
So the fix is tiers and a smaller git half, not a finer reach.

**Rejected.**
- **A finer reach as the fix** (the file, or the type): measured to save a third while missing calls inside a module, which
  PROCREACH1 rejected for the same reason.
- **The git half exact per merge now**: a median of 12 and a p90 of 37 minutes a merge, not minutes. It becomes exact once
  TESTVALUE1 brings it under its target.
- **The scoped run in the main checkout**: D180's reason holds, since a merge there held every dispatch.
- **The scoped run in the gate tree**: it would wait on, or end, the background run.
- **Blocking a merge on a known-red test it reaches**: one broken test on main would stop every merge near it, which is the blocking
  D180 removed.
- **Staging the install only on the full set** (today): the wait this removes. A public release keeps it.

**Changes, once accepted:** D115 (a merge's gates; GATESLIM1's second part), D180 (points 1, 2 and 4, and the budget note's
thirty minutes, now the background run's), CI1 (the watch as the background run), GATESLIM1 (`BLOCKING` and `PATH_CHECKS` as the
cheap tier, `--gated` as the scoped run) and PROCREACH1 (its census for every suite, its sweep moved to the background, its third
whole rule removed). Until then it changes nothing. On acceptance, D115 and D180 each get a dated note pointing here. **Held by:**
the rows of point 7.

**Note, 2026-10-24 (round 2, under D191: Codex's read and the Opus foundation read answered).** Codex read round 1 (17 findings,
14 blocking, *another round*) and an independent Opus reader read it as a foundation (21 findings, 8 blocking, *another round*);
both reads are `docs/2026-10-24-ci-scope-reads.md`, and the design's §11.1 tables each finding, taken or answered, and where.
Every finding held against the code on main at `b61325e6c`, CIFAST1 merged. The steward settled one direction for round 2:
development never waits on the full set, since a merge waits only on its scoped run; the owner's install is republished only on a
commit the background run has passed. Points 1 to 7 above read as this note says:

- **Point 1, reach.** The .NET reach is PROCREACH1's name census, one level deep, **not a closure** (D180's PROCREACH1 note; the
  FIX-LOG's 2026-10-21 entry for GENREGEN1, whose change broke two driver censuses that walk every source as text). The
  TypeScript reach is a closure over the repository: every relative and literal dynamic import, folder, basename and glob edges.
  Edges no string names are declared; an unresolved read reaches its whole suite. The census's checks test the inventory, bound to
  the tree that ran; recall is measured apart, by a replay of a month's recorded failures, the FIX-LOG's among them, through the
  census at each introducing commit, and by a running miss count in the background run (design §3.5).
- **Point 2, the scoped run.** The candidate is made in `local/scope-tree`, not by `commit-tree` beside the checkout. Merges that
  arrive while a scoped run is in flight join one candidate of up to eight, run on the union of their reach, and are bisected on
  red; at the measured rate (670 merges in ten days, a peak of 127 a day and 12 an hour) one run per merge would queue through every
  busy hour. The scoped set is every unit with no pass standing on the candidate's tree, which covers direct commits. **A reached
  .NET fast half runs whole**; the TypeScript suites run by file; the Process halves by class, keeping the sweep; the git half by
  reach whole when its predicted wall fits the budget, else by subject within it. Browser specs and rehearsals are deferred.
  Retries stay FLAKE1's. What the scoped run leaves to the background run is **deferred**; *owed* keeps CIFAST1's meaning. Expected
  walls are rebased on measured ones: 15 to 28 minutes for a driver merge, 2 to 8 for the rest (design §4).
- **Point 3, the background run.** A durable due record for the sweep, an unconditional nightly run with catch-up, a failed run
  satisfying nothing, overdue reported; no background Process group while a scoped Process tier runs. **Known red is keyed by test
  and failure fingerprint** and waived only when the test fails on the candidate's base too; it clears on a pass and stops being
  waived after 72 hours (design §5.1, §5.2).
- **Point 4 is replaced.** The install is republished only on a commit the background run has passed: every gate's pass standing on
  its tree, the sweep within its bound (`sweptOut` kept for the install), CIFAST1's rehearsals paid, and no known-red test that the
  change since the commit last staged reaches. It is never staged on scoped-green alone. `--from-scoped` and the hand list of
  update-path files are withdrawn. **The claim that the install is reversible is withdrawn**: once a staged build confirms,
  `InstallSwap.Finish` deletes `update/previous/`, and D139 excludes failures after confirmation (design §5.3). D180's rejection of
  letting an install out without a green run stands.
- **Point 5.** The rehearsals' ports are picked, not reserved, and MEMGATE1 reserves no memory: side by side waits for a
  machine-wide port claim and one memory ledger, and the serial chain stays the default until collision tests and five loaded runs
  hold. CISCOPE1f takes over REHPAIR1 (design §6.2).
- **Point 6.** The report nominates and a removal records the obligations kept; attempt-level history; coverage within its
  currency (Process by Process; a cross-language or program-starting unit never removed); one removal at a time; nothing pruned
  before the window matures. The git half's target is its whole reached set within the budget's predicted wall, about 28
  class-minutes (round 1's 40 did not fit eight minutes at four wide), set by CISCOPE1g's report (design §7).
- **Point 7, the rows**, each landable alone, no backstop removed before its replacement: CIFAST1 (landed); CISCOPE1b, the third
  whole rule narrowed to a pass gone stale by reach, the sweep kept; CISCOPE1c, the census and its recall proof; CISCOPE1d, the
  background schedule, known red and the stage's rule; CISCOPE1e, the scoped run and the merge queue; CISCOPE1f, the rehearsals
  side by side; CISCOPE1g, the value measures; then TESTVALUE1 (design §8).
- **Corrections to the text above.** `6ce6235`'s 74 minutes were not the rehearsals alone: they were 44.1 of them, the rest the
  light lane a rehearsal waits for and the tree's preparation. **Why**'s "coalescing made the CI slow" is half right: coalescing
  makes one run wide but lowers total work; per-merge runs buy attribution and a short wait, not less work, and the queue's
  batches recover some of it. **Rejected**'s "the git half exact per merge now" stands, and its "becomes exact once TESTVALUE1
  brings it under its target" is conditional on the target §7.3 sets; its "staging the install only on the full set" is
  withdrawn, the full set being what the install waits for. Added to **Rejected**: staging the install on scoped-green (no rollback
  after confirmation); known red keyed by class or file (it hides a second failure); one scoped run per merge (it queues at the
  measured rate); scoping a .NET fast half by class (the name census is not a closure, and the half costs under two minutes).

Round 2 rewrites the design's §4.1, §4.2, §5.3 and §8, so Codex reads it again and an independent Opus reader reads it again as a
foundation. **Status unchanged: proposed.**
