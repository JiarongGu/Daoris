## D207 — A modular CI: each merge waits on a scoped run of what it reaches, in minutes, on a candidate commit in a tree of its own; the full set runs in the background on its own schedule, never blocks a merge, and is what a republish of the install waits for; the rehearsals leave the per-merge path and run side by side; every test's value is measured and the git half cut to fit (2026-10-24)

**Decision (CISCOPE1, accepted 2026-10-24).** **Status: accepted** (the steward, under D191, after round 6; the acceptance note at
the end), round 6, the final round. Written by Claude Opus under D191; it changes a foundation (what a merge and a stage wait for,
which D115, D180, CI1, GATESLIM1 and PROCREACH1 rest on), so Codex reads it and an independent Opus reader reads it as a
foundation, and the steward accepts after both. Codex read rounds 1 to 4; its read of the final text is owed when its
workspace's credits return, and a blocking finding of it becomes an amendment to this decision. The contract is
`docs/2026-10-24-ci-scope-design.md`. Its §2 gives the measurements this rests on, §10 the questions Codex's owed read is asked,
and §11 every read's findings, answered.

The owner directed on 2026-10-24 that CI be scoped to what a change needs, module by module; that the full run go to the background
and never block development; and that the tests are too many and too verbose. Measured on this machine: a `--ci` run took 38 to 74
minutes. Its wall was the git half (24 to 44 minutes, whole whenever a merge reached `Trees`) and the family and deployment
rehearsals one after the other (44.1 of `6ce6235`'s 74.3 minutes, the rest the light lane a rehearsal waits for and the tree's
preparation; CIFAST1 has since taken the two off a plain run's critical path). One run (`f296996`) spent 31.5 minutes on a git half
whose every class already had a standing pass. Main took 670 merges in ten days, a peak of 127 a day and 12 an hour, and 10 to 94
direct commits a day. The steward's direction: development never waits on the full set, and the owner's install is republished
only on a commit the background run has passed.

1. **Modules and a census of every test unit.** A module is a source area (a project's first folder, a CLI module folder, a page
   folder, a tool file). Every test unit (a .NET class in either half, a `node --test` file, a vitest file, a spec, a rehearsal) has
   a **reach** and a **subject**. The .NET reach is PROCREACH1's name census at the area grain, one level deep and **not a
   closure**; the TypeScript reach is a closure over the repository (relative and literal dynamic imports, path, folder, basename
   and glob strings). Edges no string names are declared, and a read the census cannot place reaches its whole suite. The census's
   checks hold the inventory against the runners' discovery on the same tree, the hand rows of `REACH`, the whole-suite files, a
   fixture per edge kind, and a skip that names an open row (design §3.1 to §3.4).
2. **Recall, measured causally and conservatively.** Each failure is judged against the one commit that introduced it, the last
   transition into its signature on main's first-parent line, found by running the failing unit's class or file: first the commits
   before the first failure, one by one, until the test passes, within 48 runs, which finds the transition exactly (a commit the
   FIX-LOG names, whose two runs show the transition there, is taken as the first failure); only a failure past that cap is
   halved and probed until no stretch exceeds sixteen commits, and its verdict (*selected* when that commit's change reached the
   unit, else *missed*) is credited only when every commit that could still be the last transition gets it, else it is unsettled.
   Only a passing run bounds the search: a run where the test fails with another signature, or does not exist, moves nothing,
   and where the walk meets one the failure is unsettled, so a renamed test or a changed exception is never credited to the
   commit that changed it.
   Deliberate deferrals, the parent's direct commits (unscoped), execution failures and unsettled ranges are counted apart, an
   unsettled range as missed, so recall is a lower bound with no real miss in its numerator. A month's recorded failures (over
   2,153 first-parent commits, each source's observation lag stated) are replayed by the pinned selector on the historical trees,
   with a failure reader that keeps each test's case, exception type and location, built there, structurally, before the scoped run
   is relied on, each run a lowered guest behind MEMGATE1 until CISCOPE1e's admission exists, and a lower bound under 0.9 holds
   CISCOPE1e for the steward; afterwards a running count reads the scoped runs of the candidate that reached main (design §3.5).
3. **A scoped run per merge, through a queue.** The parent reads a branch's diff (`--preview`) and queues it with its message and a
   records commit on the branch; the branch's tip and the message's bytes are frozen at enqueue, and the tool commits nothing it
   was not handed, a tip that differs from the branch's last preview refused, so the records commit comes before the preview. A runner it starts detached, with a log and a startup acknowledgement, merges every queued branch, up to eight,
   as one candidate in `local/scope-tree`, one merge commit each, and runs on it every unit with no pass standing on its tree: the
   cheap tier always; a reached .NET fast half whole; the TypeScript suites by file (of the tools' own tests, the twelve verify
   runs); the Process halves by class, keeping the sweep; the git half whole when its predicted wall fits an eight-minute budget,
   else by subject within it, a known-red class taking the budget first; and a known-red unit among those in every candidate,
   whatever it reaches. Browser specs and rehearsals are **deferred** to the background run, known red or not. It is scheduled by
   memory, as a CI run is, its heavy light gates below normal while its Process tier runs, as the CI's are. On green, main fast-forwards to the candidate, only onto a clean main checkout, whose files it moves.
   On red, every failure is matched by its **signature**: a failing test by its full name with its case, its exception type and
   its assertion's location, by its method and the text of its source line, never its line number, and never its message line
   where a location can be read; a gate that names no test by its step and what the step names, a build by the set of its error
   codes with their files, GUIDs and hex runs normalised in any line it uses. A death of memory is the machine's: it is run again
   as MEMGATE1 runs it, never run on the base or over the prefixes, never stops the queue and never hands a member back, a second
   death holding the candidate until its memory is reserved; only on the run after that hold, and only where the gate's own job
   used more committed memory than it reserved, is a death of memory the gate's, judged as a failing gate that names no test,
   and one within its need holds the candidate again. A failing test the base shares is inherited and filed as known red;
   a failing gate that names no test (a check, a typecheck, a discovery or host failure) is run on the base first and stops the
   queue if it fails there, as a base that does not build does, until a direct commit or a recheck lifts it; otherwise the failing
   class, file or gate selection runs on every prefix, and the member at the last transition into the signature is handed back,
   alone or with those it needs, earlier transitions named as interacting; a changed signature on a failing base, a partial fix's
   included, is pinned the same way. A failure no prefix places, or which a prefix cannot run, is unresolved: a candidate of
   several runs its members one at a time, and a candidate of one is handed back as unresolved and the queue goes on, a passing
   re-run never making a candidate green; the members kept are judged again. A direct commit re-forms the candidate; one whose
   paths' own rules are the records lane, `docs/**` or `docs/index/**` runs the whole cheap tier and defers only `service`.
   Promotion is recognised by ancestry after a crash, and a candidate held by repeated direct commits is reported. A deferred git
   class is carried, by standing, into every later candidate until the background pays it. Expected walls, an estimate the proof
   replaces, before MEMGATE1's memory waits: 7 to 11 minutes for records, 9 to 16 for the page, CLI or tools (15 to 22 when the
   CLI reaches `driver-process`), 15 to 28 for the driver (design §4).
4. **The full set in the background.** `--ci --watch` in `local/gate-tree`: an ordinary run after each promotion (the family and
   deployment rehearsals owed, as CIFAST1 has them), each Process half's sweep from a durable due record, and an unconditional
   nightly run of every gate, rehearsals included, caught up after a missed night. A sweep or a night is satisfied by a run that
   finished, whatever its verdict; only a run ended before its classes ran leaves it due, and overdue is reported. One admission
   record serves both runners: while a scoped Process tier runs or waits the background starts no Process-lane gate; a scoped tier
   due while the background's set already runs (its git half with one rehearsal, two once they run side by side, or with up to
   three heavy light gates of its below-normal light lane) runs beside it at normal priority, never waiting for a slot, though a
   heavy gate may wait MEMGATE1's ten minutes for memory. Memory is reserved in physical memory and in commit; each admitted gate
   runs in a job object of its own that kills on close, held by its launcher, as HEAVYRUN1a's gates do, so its membership
   survives an intermediate process's death, and its reservation is released on a read that finds the job empty or on a name no
   job answers, which is an ended job, any other failure to read keeping the charge; the
   background leaves 26 GB of foreground headroom; a background gate kept waiting 60 minutes takes the slot between scoped tiers,
   and finishes when memory admits it. **Known red** is keyed by test and a fingerprint that keeps the theory case and the
   assertion's location, matched by signature, waives only in the queue, only when the same signature fails on the candidate's
   base, expires 72 hours from the test's first sighting, and is cleared only by a counted pass on a descendant of the commit it
   was last seen failing on, its first sighting kept (design §5.1, §5.2).
5. **What a republish stages.** Every stage entry point asks `--passed`, which needs a finished run's receipt on that commit's
   tree (an ordinary or nightly run, a plain `--ci`, a `--ci --stage`, or a `--full --beside`; not a sweep-only run), the build
   made from the gate tree at that commit under the tree's lock, never from the checkout (a plain `--stage` builds only under
   `_fixtures`, as GATE3 has it, or as the delegated `--from-gated` child inside the gate tree under its parent's held lock,
   and refuses elsewhere, the owner's `--force-ungated` apart), the commit's, the receipt's and the build source's trees one
   before the build and again in the child just before it stages, and
   every gate of the plan passing on its tree, with
   **no waiver**: a known-red test fails its gate. The sweep is within its bound (`sweptOut`, the due record, and an age on a whole
   Process pass counted by standing), CIFAST1's rehearsals are paid, and the census was read. Every gate verdict carries the kind
   of run that gave it, and the gate store keeps them per gate, so a scoped run never evicts a background one. Stages are recorded
   in a history of their own, apart from the gate tree's record. A public release keeps the release workflow's own jobs, which
   verify the input revision and a stamped worktree, not one exact commit (design §5.3).
6. **The rehearsals.** No scoped run runs one. Each runs in a worktree of its own, ports claimed machine-wide, and two at a time,
   the third waiting, only once collision tests and five loaded working-day runs hold; the serial chain stays the default until
   then (design §6).
7. **Each test's value** (TESTVALUE1 folded in). Measured per unit: runtime, attempt-level history, catches, and unique coverage
   within its currency. The report nominates and a person or a session decides, one removal at a time, each recording the
   obligations kept, nothing pruned before its window matures and no line or branch losing its last cover. The git half's target is
   its whole reached set within the budget's predicted wall, about 28 class-minutes, set from the report (design §7).
8. **Rows in build order** (design §8), each landable alone, no backstop removed before its replacement and no row loosening the
   stage: CIFAST1 (landed); CISCOPE1b, a half composed only from a pass gone stale by reach; CISCOPE1c, the census and its recall
   proof; CISCOPE1d, the background schedule, known red and the stage's evidence; CISCOPE1e, the scoped run, the queue and the
   admission between the runners; CISCOPE1f, the rehearsals side by side (REHPAIR1 taken over); CISCOPE1g, the value measures; then
   TESTVALUE1.

**Why.** A merge's real reach is minutes everywhere but the git half (design §2.2), and a merge that waits on its scoped run waits on
strictly more than today's, which waits on `BLOCKING` alone. The grain was not the cause of the CI's length: the module-closed and
area grains cost the same, and the file grain saves a third only by dropping a module's own calls (design §2.3). The name census
cannot be exact for the driver, so where it chooses, a backstop runs: a reached fast half whole, the sweep within a day, and the
background run, which alone the install waits for, since once a staged build confirms its predecessor is deleted and nothing rolls
it back. A miss therefore costs attribution, and recall is measured so that cost is known; the one exposure left at the install
is today's, a Process-half census miss whose class keeps an old pass within the sweep's bound of a day, which D180's PROCREACH1
note accepts and a whole Process half before every stage would close at 24 to 44 minutes a republish. Coalescing
makes one run wide but lowers total work; per-merge runs buy attribution and a short wait, and the queue's batches recover some of
the work.

**Rejected.**
- **A finer reach as the fix** (the file, or the type): measured to save a third while missing calls inside a module, which
  PROCREACH1 rejected for the same reason.
- **The git half exact per merge now**: a median of 12 and a p90 of 37 minutes a merge. It becomes exact if TESTVALUE1 brings it
  within the target the value report sets.
- **The scoped run in the main checkout**: D180's reason holds, since a merge there held every dispatch.
- **The scoped run in the gate tree**: it would wait on, or end, the background run.
- **One scoped run per merge**: it queues through every busy hour at the measured rate.
- **Scoping a .NET fast half by class**: the name census is not a closure, and the half costs under two minutes.
- **Staging the install on scoped-green**: no rollback survives a build's confirmation.
- **Waiving known red at the stage**, by the census or otherwise: it lets an install out without a green run (D180), and judges by
  the census whose misses the background run backstops.
- **Known red keyed by class or file**, or by a fingerprint without the case and the assertion's location: it hides a second
  failure.
- **Judging recall by selection anywhere in a range**: a unit selected before a regression proves nothing about it.
- **Blocking a merge on a known-red test it reaches**: one broken test on main would stop every merge near it, which is the blocking
  D180 removed. **Two deliberate exceptions**, each making every merge wait:
  - a test known red past 72 hours from its first sighting is no longer inherited, and since a known-red unit the scoped run may
    run runs in every candidate, **the queue stops**, not only for merges near the test, until a direct commit on main fixes it
    or skips it under its row; a waiver cannot outlive the fix-forward D180 expects within a working day, and the parent's watch
    warns twelve hours ahead. A known red in a browser spec or a rehearsal, which no candidate runs, never stops it; the stage
    refuses it;
  - **a gate that names no test failing on the base** (a check, a typecheck, a fast half's compilation, discovery or host failure)
    **stops the queue at once**, with no grace, since every candidate on that base fails the same way and none can be judged;
    it is lifted by a direct commit, by `--queue --recheck`, or by the runner's own recheck an hour on, so a transient host
    failure does not need a commit to clear.
- **Handing back the members that reach an expired known red's gate**, instead of stopping the queue: a unit the scoped run may run
  runs in every candidate whatever its members reach, so it would hand back members that did nothing, and one direct commit ends the stop.
- **Halving a red candidate to its first transition**: a member whose failure a later one repaired would be handed back, and the
  member that broke the candidate kept; every prefix runs, and the last transition is handed back.
- **Bisecting a check, a discovery or a host failure by building the prefixes**: a build that passes proves none of them; the
  failing gate's own selection runs, on the base first.
- **A scoped Process tier waiting on a background gate, or ending one**: the merge would wait on the full set, or the background
  run would never finish; it runs beside one already running instead.
- **Matching a failure by its message line**: a message can carry a token each run makes fresh, so a reproducible failure would
  never be pinned, inherited or found at its introduction. **Or by its line number**: every judgement compares different trees,
  so a line added above the assertion would read as another failure, pinning the member that added it and crediting it in recall.
- **Judging a death of memory on the base or over the prefixes**: under the same load the base dies the same death and stops the
  queue, and a prefix's death pins a member for the machine's load; **or as the gate's on any admitted run**, since admission
  reserves only the runners' gates while the workers and the install take the rest.
- **Re-forming an unresolved candidate of one until a run passes**: an unbounded retry of a fast failure, which D180 keeps out.
- **Crediting a recall verdict to a probed range**: a fix and a reintroduction between two probes put a real miss in the
  numerator.
- **Building a stage from the checkout, checked before and after**: a source changed and restored between the checks, or a
  promotion during the build, puts other content in the artifact.
- **Finding a reservation's processes by a search of the process table**: a grandchild of an ended shell, or a failed query, reads
  as empty while work survives.
