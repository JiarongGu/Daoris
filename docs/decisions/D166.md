## D166 — Daoris's code is cut into domain modules, each layered as an onion, held by a structure gate (2026-10-12)

**Decision (the owner's direction).** The owner, 2026-10-12: *"I also find daoris currently does not have a proper dev
folder structure, since this is growing we do need to properly separate into a good code design in modules (onion
structure + modularized domain)"*. The driver was 299 files of one namespace, about 260 in one folder, with no rule on
what may call what. The design, its facts and its rows are `docs/2026-10-12-code-structure-design.md`.

1. **Modules by domain.** The driver is cut into modules named by the glossary's domains (`Platform`, `Accounts`,
   `Agents`, `Conversations`, `Sessions`, `Trees`, `Quests`, `Review`, `Workflows`, `Plugins`, `Help`, `Service`,
   `Setup`, and `Loop`, the composition root), one folder each, its tests mirrored. The other projects follow (STRUCT5).
2. **Onion layers inside a module**: `Domain` (records and rules, pure: no files, processes, network, environment or
   clock), `Application` (use cases against ports), `Infrastructure` (the I/O behind the ports). Inner layers never name
   outer ones; a module reaches another only through its `Domain` and `Application`; nothing uses `Loop`; the hosts
   (`Driver.Host`, `Modules`, `App`, the service's hosts) are the outer ring.
3. **A structure gate holds it**: a fast test that places every file in a module (an allowlist that only shrinks), keeps
   `Domain` free of I/O by a token table, and refuses a reach into another module's `Infrastructure`.
4. **It moves in steps the gates prove**: path readers made name-based first; one module per branch, moved as it is, while
   no branch in flight touches it; then one module's layers per branch; namespaces per module last, resource names pinned.

**Rejected:** a big-bang move; an assembly per module or layer now (the parallel-development design §7's costs stand, and an
assembly would not make a layer pure); renaming namespaces as files move; leaving the shape to the README's prose.

**Amends:** the parallel-development design §4 (the MOD splits by feature now land in module folders) and §7 (one
assembly stays, with a named internal structure; assemblies measured again at STRUCT6).

**Note, 2026-10-14 (DEDUP6, decided: one path rule, three id rules).** A scout read every copy (the survey's §6 and more):
eleven path checks, three folder-id rules and the id patterns, with what each path is for and who supplies it. One
`SafeNames` in `Platform/` answers yes or no; each caller keeps its own refusal sentence, so no pinned sentence changes.
- **A repository path joined to the disk** (a tool's package, a plugin's icon, a review procedure, a served folder, a
  manifest's router, an opinion packet, a served page's file): not empty; no control character, NUL or DEL; no `\` and no
  `:`; not starting with `/`; every `/` segment not empty, not `.` or `..`, not ending in a space or a dot, and not a Windows
  device name (`CON`, `PRN`, `AUX`, `NUL`, `COM1` to `COM9`, `LPT1` to `LPT9`, with or without an extension). Why the last
  two: Windows strips a trailing dot or space, so `a.` opens `a`, and a device name opens the device, each past an "inside the
  folder" check; such a path cannot be checked out on Windows anyway. Callers that first turn `\` into `/` or strip a leading
  `./` (the router, the packet) do so, then ask the rule, and keep their own containment and existence checks. Stricter for
  every copy in some case; looser for none.
- **Not that rule:** a path handed to git only (`GitReads`, the evidence's `EvidencePaths`), where `a:b` is a legal tree
  entry, keeps its own rule, which must refuse a leading `-` and a `:` pathspec unless the call puts `--` first; the launcher's
  `StagedBuild.Inside` stays standalone; `ArePaths` is a glob, and `ReviewShowing.BaseOf` a URL path.
- **An id joined under the home as a file or folder name:** the shape its kind already has, ending `\z` (a `$` takes a
  trailing newline), with no `:` (on Windows `a:b` names a stream of `a`), no `..`, no trailing dot and no device name.
  `SessionEvents.IsId` keeps `:` for a remote's `machine:id` form, and every local `PathOf` asks the folder rule. Before a rule
  tightens an id kind, the build reads how that kind is minted, and an id this machine already holds stays valid.
- **The plain id** `^[A-Za-z0-9_-]{1,64}\z` (a quest handed, an opinion gate's chain, a workflow run, the Ask Daoris door's
  suffix), compiled once; the start request's id (no `_`) keeps its wire shape. **The kebab id**
  `^[a-z0-9]+(?:-[a-z0-9]+)*\z` with each caller's length cap; the TypeScript twins already end where `\z` does.
