## D251 — The tools' provider census runs the contracts' generator, and reads the table it writes (2026-11-07)

**Decision.** The tools' twin of the provider census (`provider-census.test.ts`) read `PROVIDER_VOCABULARY` from the page's generated,
untracked service types, so it passed only where an earlier step had written them. It now runs the contracts' generator first
(`writeContracts(root, '--if-stale')`, under the generator's run lock, into the generator's own build output) and reads what that
wrote: a fresh checkout and the test file run alone read the same table, from the one place the table is written. The merge tool sends a
provider's own sources and the registry's list and reader to `tool-tests`, since the generator reads them. D250's service twin moved
into the driver's tests because a .NET suite cannot run a Node generator; the tools' census is Node, where running it is a call.
*Rejected:* reading the providers' C# sources in the census, which is a second reader of what `ProviderVocabulary` and the generator
already read, kept in step by hand; a pre-script on the `tooltests` script, which a single file run (`node --test <file>`) skips.

**Proof:** `provider-census.test.ts` green from a checkout with no generated files, and the merge tool's reach table's rows for a provider's
sources.
