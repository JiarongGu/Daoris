## D352 — An unchecked done waits only where the configuration names who reads it, the `ask-reader` cast like any role, and never on the run's own worker; with none named it goes on (2026-11-20)

**Decision.** D255 holds a run's `quest.holds` where its ask's quest carries no requirement, and named the person as the one who passes
it, on the `acceptor`, a role no cast may give an agent; so an agent that filed the ask was refused as not its holder, and every such run
stood until the person typed a pass. The owner's rule for every gate: no configuration means no restriction; a gate stands only where there
is risk, one setting whichever actor or node (the unified setting is RISKGATE1's; this hold follows the rule now). The rule:

1. **No reader named, no hold.** Where the `quest.holds` step names no role and the place casts no `ask-reader` (and is not at high risk),
   the unchecked done goes on by itself: the step reaches, said once on it ("no one is set to read this done against its ask, so it goes
   on"), in both catalogues. The pass reads the cast as the home's files say it; where it cannot read it, the done waits.
2. **A named reader holds it.** A role the step names (the owner, a supervisor's role, a catalogue role), the place's cast of the
   `ask-reader` (any holder, the person included), or a high-risk place (the person) makes it wait on that role's holder: the attempt's
   tenure as the place casts it (D312), the line standing in where the person holds it. The holder passes it with words through the node
   door (`workflow skip`, the wait card and the *What needs you* row); the person's Accept naming the unchecked hand-back takes it from an
   agent holder in the same press, journaled `pressed accept`.
3. **Never the worker.** A pass from one of the run's working sessions (those serving its work quests or working its branch), or from a
   working session where those are not read yet, is refused `own-done`, whatever holder it speaks as. The role is never cast or handed to
   the bare `agent`, whose word any agent speaks; a place's cast and a step handed to an agent are the owner's presses (`PipeOwnerOnly`), so
   no session casts itself the role that reads its done.
4. **One word.** `ask-reader` (Ask reader, 需求核对人) reads a done against its ask; the *asker* (委托方) is the repository a quest comes
   from. The reason kept on the step names the role, never *you*.

*Rejected:* always waiting on the person by default (the first cut of this decision): it gates where nothing was configured and nothing is
at risk, which the owner's rule forbids. *Rejected:* comparing the done with the ask's own words through the requirement path: the ask quoted
as a requirement with a check nobody wrote is answered `met` by the agent that did the work. *Rejected:* handing the pass to the run's working
session as a task's Done is handed (`AgentSettles.Handed`, D318): the session that did the work would check its own done. *Not taken now:*
the unified risk setting (RISKGATE1), reading the reader from the ask record itself, and a supervisor kind of its own for holds.

**Held by:** HOLDSACTOR1.
