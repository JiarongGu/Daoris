## D298 — A session's tree is told its preparation and runs it itself; only a verification tree runs it before its work (2026-11-16)

**Decision (OPENSLOW1).** A driven session's tree no longer runs the repository's declared tree preparation (`regenerate`, the
quick base) before the agent's first turn: the session is told the commands (`TreePreparation.Told`) and runs those its work needs.
A verification tree still runs `regenerate` before its gates, which read the generated files. Every step of an opening is timed in
one `session.opening` line (area `driving.md`).

**Why.** Measured on the install, 2026-11-16: session c69733ec opened in 281 s, of which the preparation TREEPREP1 (ccdfd8fb52) ran
before the hand took about 232 s (a cold `contracts --if-stale` build about 101 s, `quick --record-base` about 131 s), one after the
other, while the session sat queued. The quick base only tells a builder whether a red is main's own; the merge's ratchets judge
against main at the merge base (MERGEPARITY1).

**Rejected:** a base kept per commit and reused (5 of 34 later opens would have hit it, and a burst of opens starts together); a
second, prepared twin tree per session (double the disk and checkout time); and running the preparation beside the agent's first
turn (its build clashes with the agent's own, and a base recorded while the agent edits is spoiled).
