## D322 — A home's history is disposable, and one command purges it and keeps the configuration (2026-11-19)

**Decision (CLEANSTART1).**

1. `daoris home purge --history [--plan|--yes]` moves a home's history out and keeps its configuration. History is what Daoris recorded
   of work done (sessions and their events, frames, logs and lineage; quests, asks, intake, handed, opinions, brainstorms, checks, helpers,
   proposals, notices, run, unit, tenure and agent-step records, lines moved, overlaps told, abandoned,
   salvage, keeping, reads, files found, pipe waiting and sent; the desktop store's session, word and run tables; the service
   store's quest and ask tables and its event log). Configuration is what the person set or signed in to (accounts, cooling, harnesses,
   agent offers, permissions, `driver.json`, the workflows' definitions and casts, roles, the registry, workspaces, git identities,
   plugins, their data and approvals, `home.json`, browser profiles and sign-ins, the knowledge and memory stores' kept facts). Where it
   was unclear it is kept, as are the place receipts, landings and session branches that a restart or the tidy settles by, and `docs/areas/install-home-update.md` (rules 52–54) says which.
2. The purge takes both stores' write locks, copies each whole (`VACUUM INTO`) and moves each history file into `purged/<UTC stamp>/` in the Daoris folder, then empties the history
   tables, and writes every purged quest id into `quest_forgotten`; it is refused while a desktop, a `daoris drive`, a service or a running session holds the home, and from a session's terminal it only lists.
3. No older build's reader, and no tool that carries a purged record forward, is kept for it: after a purge the home is as a new one
   that has been configured.

**Why.** The ask that reserved this decision (CLEANSTART1) gives the grounds: Daoris's history is disposable, every repository keeps its
own records, the foundation changed many times, and a clean start is wanted with no backward compatibility. A new foundation otherwise has to
carry every old shape of every record, which D323 already refuses to do for readers; a purge makes the clean start one command and one
backup folder rather than a hand deletion that risks the configuration the person set.

**Rejected:** deleting the history in place (a purge that cannot be undone, where a move into a dated folder costs a rename on the same
volume); a purge that also resets configuration (the accounts, sign-ins and roles are the person's setup, not history); emptying the
stores' tables by dropping their files (the stores' own bookkeeping, import marks and revision marks must stay so a revision never moves
back and a purged file is never imported again); a purge that runs beside a running Daoris (the loop holds the stores open and writes
as the purge reads); classifying by name pattern rather than by a list a census holds complete (a new file or table would be purged or
kept by accident).
