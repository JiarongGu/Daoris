## D239 — The Map is two levels in one place, read-only: each zoom says less about the same cards, one choice is read in one line and one detail, find reaches the level shown, and the list is one tree (2026-11-06)

**Decision (MAPUX1; proposed 2026-11-06).** The contract is `docs/2026-11-06-map-ux-design.md`. It settles the person's side of
the maps that CANVAS1 (D224) draws. It changes no data the Map reads and adds no act.

1. **What the Map is for.** It answers four questions: where work is moving and where the person is needed, what one repository is
   and what it touches, how a repository's code is put together, and where something is. Every act lives elsewhere, behind the
   detail's doors.
2. **Two levels, one place.** There is the workspace map and a repository's code map. The code map is drawn only on the Map; a
   repository's page has a door to it. *Back to the map* is the one way back, and returns with that repository chosen.
3. **Each zoom says less about the same cards.** The full tier has a card's words. The chip tier has its name, its count and its
   ring. The dot tier has its place. The chosen and the focused keep their name at every tier.
4. **One choice, read in one place.** A press chooses and a second press releases; a double press is one press. The choice stands
   forward on both levels. One line under the drawing names it and is the Map's one live region. The detail holds the facts and the
   doors, including the repository's page.
5. **Find reaches the level shown**, from 13 items. On the workspace map it matches names and what a repository says it owns and
   accepts; on the code map, module ids and folders. Enter while an input method composes steps nothing.
6. **The list is one tree on both levels.** Below 36rem it is the reading, with the detail opening in place under the chosen row.
7. ***Which quests* opens on the last 30 days** for a viewer who never chose. A kept choice stays.

**Why.** CANVAS1 decided how a graph is drawn, but not what a person reads at each scale, where they read a choice, how they move
between the two maps or what the list says. The four questions put the Map's first view on work moving now. A single place for a
choice's facts keeps the keyboard, touch and the reader on one path. Find on the level shown answers a name without reading every
repository's file.

**Rejected.**
- **A *Code* tab on the repository's page.** A second place drawing one map.
- **A separate overview mode, or the minimap as the overview.** The tiers are the overview.
- **Hover cards or popovers for a choice.** The keyboard and touch do not reach them, and they would be a second detail.
- **Choosing several.** Nothing on the Map acts on many.
- **Find across every code map from the workspace.** It reads every repository's file to answer one name.
- ***All* as the first *Which quests*.** It grows with every closed quest. *Open only* was rejected too: a quiet workspace would
  draw no connection at all.
- **A double press opening the code map.** It would be a second way in, and a level changed by accident.
- **Announcing what changes live.** A status repaint is never said (D224).

**Amends, once accepted:** D67 §3, through the map design's *What a person does with it* (`docs/2026-09-23-map-design.md` §1),
where a choice dimmed only the lines and the first *Which quests* was all of them; D224, whose find stands from 40 nodes, which the Map
sets at 13 on both levels. Each amended decision takes a dated note pointing here.
