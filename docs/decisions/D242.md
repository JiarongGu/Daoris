## D242 — A plugin that takes the host's token runs one process per place, never one shared by places; `gh` and `az` are no tool of the product (2026-11-06)

**Decision (GITDESIGN1, G9).** This completes D241 point 5, "handed the API token of the identity serving origin, for its one process".

1. **One process per place.** A plugin that declares a `pull-request` step is started for each repository and workspace that awaits
   it, when the loop holds the lease. Each process is handed, once and at its start, the token of the identity that serves that
   place's origin (`PluginHostToken`). A place whose hand is refused (no identity, read only, Write denied, no API token) has no
   process, and the plugin's other places are served. No process holds a token for a place it does not serve.
2. **The runtime sees one plugin.** The processes are kept by a key beneath the plugin's id, so each one's waits, unsound mark and
   idle stop are its place's own. An attempt goes to the place its unit was told for. Generations are unique across a plugin's places,
   and an attempt or an event is fenced against the process that took it.
3. **`gh` and `az` leave the tool list.** Nothing starts them: no tool list, resource list, page or check names either. A session's
   `gh` and `az` configuration folders stay empty (D241 point 7).

**Rejected.**
- **One shared process with the first place's token.** A second place with another identity would act with the first's token.
- **One shared process given every place's token to choose from.** The process, a plugin's code, would then hold tokens for places
  it is not asked about.
- **The token on each call** instead of at the start. The plugin's wire has no per-call secret, and D241 point 5 names the process.
- **One process per identity.** Two places of one identity would share a process safely, but the loop would have to know the
  identity before the place's checkout, and the identity can change between looks. The place is the stable key.
