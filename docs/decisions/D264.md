## D264 — A plugin's step runs in every kind of place, and a workflow chosen for a department is judged by its place's kind (2026-11-11)

**Decision.** PLACEWORK1b's design (§3.6) has each node kind declare the kinds of place it runs in and the bind refuse a workflow with a
step its department's place cannot run (`place-kind`). Two choices it left open are settled:

1. **A plugin's step runs anywhere.** No plugin's manifest says where its steps run, so a step `<plugin>/<step>` is accepted in a git
   repository, a folder and a system alike; only a half Daoris has of a step name narrows it, as `*/pull-request` runs in git alone,
   since it opens a pull request on the branch a `push` pushed.
2. **The choice is refused, not only the run held.** Choosing a workflow for a department (`daoris workflow use`, the window's
   `WORKFLOW_USE`) refuses it, nothing written, where the department it names, or one of the workspace's that the choice reaches, cannot
   run a step, each such department named with the step, its kind and where it runs; a workspace's choice is refused as a choice that
   cannot integrate for one of its repositories already is.

*Rejected:* a `places` field on a plugin's step declaration now, which would add a field to every node declaration and its digest for a
declaration no plugin makes; refusing a plugin's step outside git by default, which would refuse every step of a system's own adapter
and of any plugin made for documents; holding only the run at its bind, which would let a folder's choice be written and every quest
there sit afterwards, where the person chose it and could be told.

**Amends** the workflows area's rule 5 (choosing). **Held by:** PLACEWORK1e.

**Note, 2026-11-11 (PLACEWORK1e, *Work in place*).**

- **A graph that lands nothing ends at the person's review.** The shipped *Work in place* (`in-place`) holds no `land`, so every kind
  of department can follow it. A named version holds one `land` and ends after it, or holds none and ends at a `review`; a `review`
  ends no graph that lands, and a hold judges the work before that review as it would before a landing. A run bound to it is a process
  like any other, and a landing's press under it is refused, saying nothing lands it.
- *Rejected:* a land-less graph ending at any kind that may end (a `work.requests`, a plugin's step), which would end a department's
  work on its agent's done with nobody having read it, a git department's commits on its line included; and letting a `review` end a
  graph that lands, which would end its run before the landing it guards.
