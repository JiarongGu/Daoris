## D249 — One management holds every process Daoris starts: a job per purpose, joined as its start returns (2026-11-07)

**Decision (OPTIMIZE1b; proposed for the owner's acceptance).** Processes Daoris and its tests started outlived their owners more than
once: git children, testhosts' stand-ins, uncontained agent and plugin hosts. Each start site held its own: the agents' job through the
launcher, a session's own job, a kill on cancel in the git runners, nothing after a crash anywhere else.

1. **The start gate hands every start to one management, under a purpose.** `ProcessStarts.StartAsync` takes a `ProcessPurpose` as a
   required word, and as the start returns, inside its place, `OwnedProcesses` joins the process to that purpose's job: one kill-on-close
   job per purpose (`Agent`, `Plugin`, `Git`, `Read`, `Tool`), made at the purpose's first start and held for the process's life, so its
   handle closes with the process however it ends, and the job ends what it holds. *Rejected:* putting the whole Daoris process in one
   job, which has no race but holds the update's launcher, the recorded Edge and the file manager, which must outlive it, and needs a
   breakaway .NET cannot ask for; starting every process through the launcher, as agents are, which costs a launcher's start per git run
   (the terminal-trust design §3.4); and a kill per site, which is what leaked.
2. **The agents' job stays where it applies.** A start the launcher took is `Launched`: born in the agents' job, joined to nothing here,
   since a second join races the launcher's own. An agent or plugin start the launcher could not take (a test's home lays out none) is
   joined to its kind's job, so it ends with its owner too. A session's own job, the terminal's, a heavy run's and an act's named jobs are
   made by their owners and nest beneath.
3. **Two purposes are held by no job, named with why.** `EndsItself`: the HTTP host, which stops when its input ends with the window and
   which a job's kill would cut short. `Outlives`: the update's launcher and the Edge recorded for the next shell. The census
   (`ProcessStartsCensusTests`) holds each file's purpose and names these, the gate's two process-less starts (the file manager, the
   terminal's shell) and every direct start, with why.
4. **The kill on end and the census are the management's.** `OwnedProcesses.End` is the one tree kill (it replaces
   `ChildProcess.KillTree`), and `Census` reads each purpose's job by process id. It stops nothing Daoris did not start: a job holds only
   what joined it and what that started since, the census reads and never ends, and `End` is handed only a process its caller started.

**The race it accepts.** .NET starts no process suspended, so what a child starts in the instant between its start and its join is
outside the job. A start that cannot accept that starts suspended and joins its own job (a terminal's shell, a heavy run's gate, a git
act's step).

**Proof:** `OwnedProcessesProcessTests` kills a stand-in owner (`Daoris.Desktop.OwnerStandIn`, compiling the management by link) and
finds its node and the node's detached node gone; the control, an `Outlives` start, survives its owner.
