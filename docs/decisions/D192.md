**Why.** A sentence an agent can drop held this repository's sessions back, and three of them still ran a whole test project,
held their place in the cap to the timeout and committed nothing, while the full set beside was run by hand and superseded as main
moved. A route the graph holds, a refusal Daoris and the harness enforce, and a verification Daoris runs on landed work move each
of those out of anyone's memory and into the process. A route that only selects keeps each pipeline whole and versioned under
D190, and a run on the line is what lets verification batch and supersede, which a node of each development run could not.

**Rejected** (design §6): a route by a model's reading or a kind inferred from paths; the start node inside a version's graph, a
pipeline as a sub-graph or a path; landed work routed by its paths; a versioned route set; verification as nodes after every
`handed`; the instruction as a standing text; a heavy run guessed from command text; Daoris ending a session's call; a bound of a
session's own on its background work; Daoris's own CI engine with lanes; a landed edit of the declaration run unasked; superseding
with no bound; a fix ask published with no say-so of the person's by default; an automatic bisect, revert or rollback; a
verification run counted against the cap or run in the main checkout; this repository's suites marked heavy before its development
pipeline is light.
