## D138 — The right-click menu is the page's own: a surface's acts from the owner it has, selected text, a link and a code span, the engine's menu kept for fields and suppressed elsewhere (2026-10-03)

**Decision (CTX1).** The owner, 2026-10-03: *"we do need to utilize the right click menu of daoris desktop"*. Read from
the code at `19592227`: a right-click showed Chromium's own menu, in the operating system's language, almost everywhere;
only the side bar's and the panel's tabs answered it. Shenora 0.19 gives a page no native menu to fill, only the window's
system menu (`showSystemMenu`). The contract is `docs/2026-10-03-context-menu-design.md`.

1. **The page's own menu.** One `contextmenu` handler in `Daoris.Web`, mounted once per window, draws MENU1's menu at the
   pointer. No native hook is added: the shell is unchanged.
2. **A surface offers the acts it already has, from its one owner**: a session's row its ⋯'s acts and its page its
   header's (D126 §3.1, `sessionActs.ts`); a quest's and an ask's page their header's and body's acts (`workActs.ts`
   among them); a repository's, a plugin's and a document's page and row (design §4). **A row offers what it does; its
   page offers what is done to it**, and a session's row is D126's exception. A record's menu ends by copying its name.
3. **Selected text, a link and a code span or path** add their own group, most specific first: *Copy*, *Search Daoris
   for it*, *Ask Daoris about it*; *Open*, *Open in Daoris's browser*, *Copy link*; *Copy*.
4. **Where the menu is not the page's**: a text field keeps the engine's (cut, copy, paste); the strip's own space opens
   the window's system menu; Daoris's browser keeps the engine's, since it shows other sites' pages and no page of
   Daoris's runs there; and the page in a person's own browser keeps that browser's wherever no surface offers acts.
   **Everywhere else on the desktop with nothing to offer, the engine's menu is suppressed.**
5. **Keys and access**: the menu key and Shift+F10 open it for the focused element; it is a `menu` named by what it is
   for, the arrows move in it, Esc closes it, and the focus goes back where it was unless an act moved it.
6. **Both languages**: an area of its own (`contextMenu`), structural keys, and an act named on a button keeps its key.

**Why.** Every act already has its owner in the page and its name in the catalogue; a native menu would add a host module,
carry every press across the bridge to the same owner, and look like neither theme. The engine's menu offered a web page's
acts in a third language.

**Rejected.**
- **The shell's native menu**, for the reasons above.
- **A page's acts on its row** (*Take* from a quest's row): an act that asks under its header needs its page, and the lists
  say a row is for choosing. Reopened if the window shows it is wanted.
- **The engine's menu wherever nothing is offered**, and **our own cut, copy and paste in a field**, which would need a
  clipboard permission the engine's menu does not.

**This amends:** the platform language §4 (a right-click is a door to a surface's acts) and §6 (the menu's role, keys and
focus). D126 §3.1 stands: the menu reads its rule. D56's title bar gains the caption's system menu.

**What the checks do not cover.** jsdom has no engine, so whether CEF fires `contextmenu` on the menu key's key-up is not
seen; the handler stops the key on its down and its up, and an open menu ignores a second one. The menu's place, its look
in both themes and both languages, and the strip's system menu were not looked at on the window.

**CTX1, built 2026-10-03: the page's own menu on every surface** (design §6), held by `menus/press.test.ts`,
`menus/ContextMenu.test.tsx`, each surface's suite and `contextMenus.test.tsx` over the mocked shell. What building settled:
- **The keys take a right-click's path**: the handler dispatches a `contextmenu` at the focused element, so a surface
  offers once for both doors. A tab strip that answers its own right-click (DOCK1e) answers the keys too.
- **A bare `pre` is not a code span**: an entry read as it is written and a session's evidence would have copied a page.
- **A selection is asked of each range** (`intersectsNode`): jsdom answers `containsNode` wrongly for an element whose
  contents are selected.
- **Radix closes a menu on the window's `blur`**, so the handler adds none; and jsdom, once a focused element is removed,
  fires that `blur` at the next focus. The tests' right-click (`test/contextMenu.ts`) focuses what a real press would.
- **Quick Ask takes a draft** (`AskOpening.draft`): the quoted words wait in its box for the question, and nothing is sent.
- **The page in a person's own browser** keeps that browser's menu where no surface offers acts (point 4), decided while
  building: there the browser's own acts are the person's.
