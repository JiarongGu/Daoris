## D235 — Comments shrink where code is touched, under a gate, after the scope's one verification (2026-11-04)

**Decision.** CODESHAPE1 took the large files apart, and moved code had its comments cut to the why (D231 point 3). The rest of the
source is still a third comments: 43% of the driver's non-test source, 45% of the modules', 37% of the web's. Cutting all of it by
hand is about a hundred builder-hours. So:

1. SCOPEVERIFY1 runs first, on the code as CODESHAPE1 left it.
2. Then a gate (COMMENTGATE1): a changed file's share of comments may not rise. A comment names no row id, decision number or
   history ("since CHR8", "D99", "LOG2b"); the decision or the commit holds those. Comments then shrink wherever code is touched.
3. One targeted pass strips the row ids, decision numbers and history notes from the comments that exist.

**Rejected.**
- A full sweep before the verification. It costs about a hundred builder-hours and leaves the verification waiting behind it.
- The targeted pass alone. Nothing would stop the share rising again.
