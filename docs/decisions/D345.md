## D345 — Radix stays the window's one headless layer; the library owns the combobox, the tree and the list keys (2026-11-20)

**Decision (UIDS11, the window redesign `docs/2026-11-19-window-design.md` §8, amending D42's libraries).** Radix remains the one
headless layer under the design library and gains three packages: `@radix-ui/react-popover` (`Popover`),
`@radix-ui/react-hover-card` (`Peek`) and `@radix-ui/react-tabs` (`Tabs`). `primitives.test.ts` keeps every `@radix-ui/*` import
inside `design/primitives/**`. The library owns the three behaviours Radix lacks, each a small unit with its tests: the combobox
(today's `ChipCombobox`, generalised, keeping an input method's Enter and Escape), the tree (the WAI-ARIA pattern, replacing the
two hand-built ones) and the list's keys (roving focus, J/K, the queue that holds still under the pointer). Reordering a list is
up and down acts with Alt+↑/↓; no drag library is added. If Radix stops shipping fixes, Base UI is the named replacement: its
parts follow Radix's shapes, and the atoms boundary keeps the swap inside `design/primitives/`.

**Why.** The atoms already solve, with tests and fix-log entries, the behaviours a new layer would reopen: popovers held by the
frame's zoom, Escape kept while composing, toasts standing beside a sheet, focus returned with no trigger, non-modal menus,
tooltips that close on scroll, blur and key. The three components Radix lacks are a few hundred lines each.

**Rejected.**

- *React Aria Components*: the strongest accessibility and everything here, but its built-in localized strings (hidden dismiss
  buttons' names, controls' labels from its own tables) send words around the catalogues and the glossary, which every window
  word goes through; adopting it rewrites all thirteen atom files at once.
- *Base UI now*: younger, and it adds only a combobox over Radix.
- *cmdk for the palette*: a second list engine beside the combobox, two ways to do one job.
- *Ariakit*: only its combobox would be used.
