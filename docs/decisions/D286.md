## D286 — Ports and adapters: the application depends only on ports and is tested on fakes, each infrastructure adapter is a package of its own pinned by a fingerprint, and its dependency tests run only when that fingerprint moves (2026-11-13)

**Decision (LAYERS1, 2026-11-13).** The owner directed that the application be separated from its infrastructure, that each real
dependency be a package of its own, and that a dependency's tests not run at a merge that changed nothing below it. Measured on
2026-11-12: the .NET fast halves took 7 to 11 minutes, because tests that start processes, open real repositories or wait on clocks
sit among the unit tests; the driver's Process suite took 48 minutes; a merge's path-reached gate 10 to 21. The driver is one assembly
of about 2,980 files whose structure gate orders its subdomains but lets any of them perform any effect. Two independent proposals
answered one brief (Codex, on gpt-6.1-sol, and Fable 5.2), and the steward chose between them point by point. The contract is
`docs/2026-11-13-layers-design.md`, built in its §8 order.

1. **Ports and adapters, Codex's map.** `Daoris.Ports` holds the effect contracts and their value records and references the BCL
   alone. `Daoris.Application` holds the driver's domain and orchestration, `Daoris.Service.Application` Service.Core's policy, and
   `Daoris.Testing` the fakes and the shared contract cases. The modules and the composition roots stay inbound adapters and roots,
   the roots the only projects that reference an adapter. The infrastructure is `Daoris.Adapters.*` under `src/Daoris.Adapters/`:
   Network, Clock, Machine, DesktopStore.Sqlite, ServiceStore.Sqlite, Git, Browser.Chromium, Browser.Edge, Knowledge.Files,
   Memory.Lyntai, an `Agent.*` package per harness and `AgentRuntime.Lyntai`. The name says what each package is, an adapter for one
   port, and frees *driver*, which today names the application assembly that dissolves into `Daoris.Application`. `Daoris.Desktop.Driver`
   is never kept as a forwarding assembly. Git's policy (its access rules, push approvals, landing and recovery judgement) stays in the
   application; its execution is the adapter's.
2. **Ports cut at the funnels, Fable's.** About eight funnels carry every real effect (`GitLaunch`, `ProcessStarts`,
   `DriverHttp.Client(handler)`, `DesktopStore`, `TimeProvider`, `IInAppBrowser`, `AgentRun`/`HeldRun`, the instance pipe). The
   platform's seam is the port where one exists: `TimeProvider`, `HttpMessageHandler`, and `DbConnection` behind a unit-of-work gate. A
   new interface is written only for git, processes, the browser, the harness and the store's unit of work, in Codex's signatures'
   shape. The filesystem port waits: it is added only where the census shows that unit tests need it, never in the first wave.
3. **Versioned by fingerprint, Fable's.** An adapter's version is its folder's git tree hash with the pinned version of what it drives
   (git, CEF, an agent's binary) and the Ports folders it implements. The tracked `daoris.adapters.lock` holds one row per package, the
   fingerprint its dependency suite passed; a merge reads it in milliseconds and runs no dependency test below an unchanged package.
   Builds are cached once per fingerprint for every worktree. There is no NuGet feed for packages inside the repository, and
   `Daoris.Ports` becomes a NuGet package only when an outside consumer needs it. The row is a dependency gate's verdict under
   MERGEFLOW1's key with the fingerprint as its reaching inputs, kept in D285's one store and made tracked so it travels; only an exact
   match stands for it, and it never expires with time.
4. **Twin-proved fakes, Fable's.** Each adapter's fake ships in `Daoris.Testing`, and one contract suite runs on the fake and on the
   real adapter: merges run the fake side, and the real side runs when the package's fingerprint changes. Git moves in two rings: first
   `GitRuns` becomes `IGit` at the argument level with its ambient seams removed, then typed repository operations over an in-memory
   model, family by family.
5. **A census by construction, Fable's.** The application and the unit-test assemblies cannot reference `Daoris.Adapters.*`. The
   banned-API analyzer forbids process starts, sleeps, the real clock and sockets there at compile time. A unit test over one second
   fails, read from the gates' duration records. TESTTIME1's `Needs` traits are the bridge until each package is extracted, and then the
   tier is the assembly. An ambient locator of the ports for static funnels is allowed only as a ratcheted, shrinking bridge, never a
   new seam.
6. **The siblings.** Agent transports and their conformance corpora belong in Lyntai (AGENTLYNTAI1), so Daoris's `Agent.*` packages are
   thin registrations over Lyntai's runtime, and no transport AGENTLYNTAI1 is retiring is packaged. Process ownership and the browser
   engine's bring-up move to Shenora when Fable's graduation rule holds: a surface that names no Daoris noun, a second consumer or that
   sibling's owner asking for it, and a surface that has stood unchanged across two releases. Each move is a quest to that repository.
7. **Migration order, each row one builder's package, the build green after each:** a, the Ports and Testing skeletons and the census;
   b, DesktopStore.Sqlite, the cheapest proof of the fingerprint, the lock and the twin suite; c, Clock; d, Machine; e and f, Git's two
   rings, the second in the timing census's order; g, Network; h, ServiceStore.Sqlite and Service.Application; i, the browsers; j, the
   `Agent.*` registrations over AgentRuntime.Lyntai; k, Knowledge.Files and Memory.Lyntai; l, `Daoris.Application` takes the rest and
   `Daoris.Desktop.Driver` is deleted; z, measured. Rows b to k run as parallel builders once a has merged, at most three at a time.
8. **Measured:** the dependency-test minutes of a merge that changed no package, zero, read from the lock; the unit suite's wall time
   and the merge's time, before and after.

**Rejected.**
- *One big infrastructure assembly*: the layering and nothing else; any change below runs every dependency suite.
- *Interfaces everywhere*, an `IFileSystem` among them: thousands of seams whose fakes nobody proves.
- *A service split*: a process, a socket and a wait on every call, against the local-first constraint, for a boundary that is a build's
  and a test's, not a deployment's.
- *A NuGet feed for packages inside the repository* (Codex's proposal): a pack and a restore between an edit and its test, machine state
  in every worktree, and versions edited by hand.
- *Porting the filesystem now* (Codex's `Files`): about 517 files of seams before a test is shown to need one.
- *A hand-kept SemVer per package* (Fable's): the fingerprint is the version.
- *Verdicts that expire with time or move with the application's paths*: an unchanged package would run again for nothing.
- *Packaging a transport AGENTLYNTAI1 retires*, and *a package per plugin-declared agent*: the first is being deleted, the second ships
  from its plugin's repository.
- *Other names*, Codex's `Daoris.Drivers.*` and Fable's `Daoris.Infra.*`: *driver* already names the application.

**Supersedes in part**, noted in its file: D207 (point 1's reach choosing a dependency test at a merge: an adapter's dependency tests are
chosen by its fingerprint against the lock, and a merge that changed no package runs none).
**Held by:** LAYERS1a to LAYERS1z.
