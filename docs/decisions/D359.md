## D359 — `sync` writes no pointer to `AGENTS.md`: every agent in use reads it itself (2026-11-23)

**Decision (AGENTSMD1; the owner's direction of 2026-11-22; amending D117 points 2 and 3).**

1. **Why.** D117 had `CLAUDE.md` hold `@AGENTS.md`, at the root and in each room, because Claude Code read only that name.
   Claude Code 2.1.277 reads `AGENTS.md` where a project has no `CLAUDE.md`. Probed with only `AGENTS.md` present
   (`docs/2026-11-22-instruction-file-evidence.md`): Claude Code 2.1.329 native, and over the protocol door at CLI 2.1.322
   and 2.1.284; codex 0.167.2 and 0.160.0; dsh 0.2.1-rc.2. Each was handed the brief. codex reads no `CLAUDE.md`, and
   dsh read the pointer as the text `@AGENTS.md`, so the pointer served no agent measured.
2. **What goes.** `Harness.pointer`, the roots' and rooms' `CLAUDE.md` writes, and the lock's `rooms`. `sync` takes out the
   `daoris:import` region an earlier sync wrote, at the root and in each declared room, and the file when the region was all
   of it (`layout/pointers.ts`, also in a room an earlier lock recorded and the manifest no longer declares); `check` fails on such a file until a sync does. The reader of that old region ends when no
   repository this family keeps holds the marker.
3. **A `CLAUDE.md` with text of its own keeps its region.** Claude Code reads that file and then not `AGENTS.md` (probed:
   both files present, only `CLAUDE.md`'s token quoted), so taking the import out would leave the repository's Claude Code
   sessions with no brief. `sync` says it kept the file and why; `check` does not fail on it. A `CLAUDE.md` with text of its own and no import at all
   (the root, or a declared room) is named by `sync` and fails `check`, since it hides the brief the same way. A repository
   ends either by moving that text into `AGENTS.md` and deleting the file, or by importing `@AGENTS.md` by hand.
4. **A link there is refused as before**, now saying to take it out: a `CLAUDE.md` held as text hides `AGENTS.md` too.
5. **The condition the pointer would have named.** Claude Code before 2.1.277 reads no `AGENTS.md` (its changelog, not
   probed: no such build is here). A person on one gets no brief from a repository without a `CLAUDE.md`; updating the
   program ends it. A maker-side flag (`tengu_agents_md_mod`) can switch the read off for an account, and a probe shows it.

**Rejected.** Keeping the pointer as a manifest option for older builds: one way per job (doctrine rule 4), and the
builds that need it are a program update away. Removing the region from a file with text of its own: silent loss of the
brief (point 3).
