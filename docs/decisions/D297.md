## D297 — The person's doors that are a workflow's accept steps are a role's to answer at low and medium risk (2026-11-16)

**Decision (OWNERGATE1).** Three doors that were the person's by being classed so, never by a choice that weighed risk, take an
appointed role's answer (area `roles-and-supervision.md`, rules 7 and 49; area `knowledge-memory-records.md`, the memory desk):

1. **A session's staged memory kept or dropped (`memory.keep`), a memory end approved or declined (`memory.decide`) and a done's
   departure accepted (`departure.accept`) are supervisor acts of two kinds, `memory` and `departure`,** granted, held and released as
   `landing.accept` is (D296): an agent or terminal holding the role decides, the decision is held for the role's window with
   *Overrule*, its file names the role and the agent, and its release asks the admission again before it posts.
2. **The service's three doors stay the person's, each with a `role` form of the driver's class.** The release posts with the key and
   names the role, its agent and its decision; the memory row's approver and the desk's words say `role:<role> · <agent>`, and so does
   a departure's accepted move (`by`), which the owner's mark never reads as theirs. A keyless agent or terminal is refused either
   way, and every other write the door table does not class stays the person's.
3. **Risk is the place's appointment.** No per-place risk declaration exists in the code yet, so an act applies only where a role
   holding it is set for that scope; a place the owner marks high-risk holds none, and its steps wait for the person.

**Rejected:** classing the three doors `Agent`, which would let any keyless session keep its own memory or accept its own departure;
the driver posting the role's answer as the person's, which would record a role's decision as the owner's; a per-step party option,
which would let one graph's step outrank the place's risk (D296).

**Left:** an end the service's sweep wrote names no session and stays the person's.
