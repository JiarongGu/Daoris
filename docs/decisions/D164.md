## D164 — A session commits on its tree's branch as it goes; the person's Accept makes the pull request's branch (2026-10-12)

**Decision (the owner's direction).** The owner, 2026-10-12, after a report's conversation sat on its session branch with its
work uncommitted, the review saying there was nothing: *"so currently we should have logic to update rules in the repo and
because I think our setup is until it has a pr branch currently it stops at daoris branch"*. The repository's own rules
asked its agent to commit only on a yes and only on a branch of its own (`feature/<ticket>-…`), while Daoris gives each
session a tree on `daoris/s-<id>` and makes the pull request's branch at the person's Accept: the two met, and the work
stopped between them, uncommitted, on the session branch.

1. **In a Daoris session tree an agent commits as it goes, on the tree's branch.** It does not create, switch or push
   branches, and it asks no one before committing there: the tree's branch is the session's scratch, nothing outside it
   moves, and the person's **Accept** in Daoris is the yes that lands it. Outside a session tree, the repository's own rules
   stand.
2. **Daoris says so twice.** As doctrine, a canon rule synced into every adopted repository's instructions (the way Daoris
   updates a repository's rules); and to the agent itself, in its first instruction on both doors, as the browser's line is
   said (BRWHINT1), so it holds before a repository has synced.
3. **Accept makes the pull request's branch as the repository names its own:** by the repository's landing pattern, with a
   ticket key found in the title or the request (`feature/<KEY>-<words>`), never a web address's slug (LANDNAME2); squashed
   to one commit where the repository's landing rule asks for that.
4. **Daoris reads what the tree holds, committed or not** (REVIEWDIRTY1), **and follows a tree an agent moved anyway**
   (TREEFOLLOW1).

**Rejected:** Daoris committing a session's work on the person's behalf (the agent commits, by its repository's
conventions; Daoris lands); leaving each repository's "ask before committing" to stop every session; Daoris editing an
adopted repository's own text outside its doctrine region (a repository's own rule that contradicts point 1 is changed by
that repository, through a request: D32).

**Amends:** D51 (what a session tree's branch is for), D145 (Accept's branch name and squash).

**Note, 2026-10-12 (REVIEWDIRTY1-a, the read).** `SESSION_DIFF` gains `uncommitted`: null unless the source is the session's own tree
and something is uncommitted, else `{ files, truncated }` in the committed list's file shape (`WorkingTree.UncommittedDiffAsync`:
`git diff HEAD` through the same splitter and bound, and each untracked file as an addition, its status `added` as the committed
list says it, its patch from `git diff --no-index` where it is text and at most 200 KB). Where nothing is committed or readable but the
tree holds uncommitted work, that is the review rather than `SESSION_NO_BASE`. `LANDING` gains `uncommitted`, the count of the own
tree's uncommitted paths (0 where clean); Accept's refusal is unchanged. A conversation in the person's checkout stays committed-only (D49 §3).
