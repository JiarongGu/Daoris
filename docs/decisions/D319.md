## D319 — A landed run keeps what it reached when its session goes on; a commit after the landing is the chain's next quest's work (2026-11-18)

**Decision (RESUMERESET1).** Once a run's landing has reached, every step bound to the landed branch keeps the revision it was bound
at, whether another branch comes to stand as the run's or the landed branch itself moves where no landing took it
(`LandedBranchKept`); a tip a landing of its own stands at, an advance its record keeps, is still followed. The person's words to
the run's working session after the landing are that session's turn: what the turn commits, or its tree brought to the line the work
merged into, is new work, never the landed run's. That work goes on the one way that already takes a landed run back: the chain's next
quest in that repository, whose claim lapses `claimed` and walks the run from there (rule 36's one landing branch while its pull
request can take it); short of that it waits for the person. Before the landing nothing changes: the session's going on moves the
run's branch and the steps bound to it are judged again.

**Why.** A run on the release path had merged its pull request and released to production. Words said to its session for the
after-release config change resumed it in its tree, which stood at the line's merge commit; the branch's moved tip lapsed `content`
and, through its receipt, every step after it, so the run forgot an outside release and walked forward again, re-observing the release
steps (harmless only because its release action never creates). The session's docs record of the change then asked the Accept again,
which would have opened a second pull request and release. A landing's effects are outside the machine; a run that re-judges them on
its session's next turn repeats them.

**Rejected:** drawing the line where the line holds the work (the pull request merged) rather than at the landing, which keeps an open
pull request's automatic second Accept on its session's commit but leaves a pushed, released branch reopened by a turn until the forge
merges it, and makes the rule depend on each delivery's last step; keeping only the steps the release path names (an allowlist of kinds
to keep), which the next delivery kind would miss; and dropping the session's words after a landing, which are the person's to give and
the session's to act on.
