## D170 — Ask Daoris acts through doors the person applies, never a shell, and plugins may hand it servers and skills (2026-10-16)

**Decision (the owner's direction).** The owner, 2026-10-16: *"I found an issue with Ask Daoris: it cannot include a repo,
since it tells me there is no shell there, so we need to build some kind of MCP to support it (and we also should be able
to install new skills/MCP from a plugin to this too)"*. What happened, read off the install's record of that conversation:
asked to include a registered repository in Daoris, the helper read the checkout as D107 lets it (its files, `git status`),
found the repository registered but not adopted, and named `daoris-driver setup` as the next step. Asked to run it, it
said it has no shell and no door to propose it. Reading worked. What was missing was a door for the act.

1. **The MCP the owner asked for is Ask Daoris's proposal doors, and the gap is the doors it lacks.** Ask Daoris already
   reaches Daoris through MCP tools on its connector: each `*_propose` tool writes a proposal that the person applies
   with one press, which makes the same edit the screen or the terminal makes (D89, HELP1c). A shell is not given back:
   HELP4's refusal of one stands, because a helper that can run a command can run any `daoris-driver` verb, a change
   nobody confirmed (D89). So each act a person can start that Ask Daoris cannot propose is a door to build, and
   `HelpCoverageTests` already lists the ones owed. The first is the one the owner met: setting a repository up
   (LAYOUT8's `setup` kind, then WSSETUP7's `register` and workspace doors), together with the screen press it twins
   (D50).
2. **When a door is missing, the room says so and offers what exists.** The helper names the terminal command, as it
   did, and also says that this is a door Daoris still owes rather than a limit of its own, so the person is not told
   to work around a missing feature as if it were the design.
3. **Plugins may hand Ask Daoris MCP servers.** INT1's servers went to every session in a repository and never to Ask
   Daoris (`docs/2026-09-29-ask-daoris-design.md`, HELP1a: a browser brought up for a tool it may not use would be a
   window for nothing). That stays the default: a plugin's server reaches Ask Daoris only where its manifest declares it
   for Ask Daoris. Its tools are allowed in Ask Daoris's rules only as the plugin declares them, and the person sees on
   the plugin's page what it hands Ask Daoris. A tool that changes something outside Daoris is the plugin's own act
   under the person's install; nothing a plugin hands may change Daoris's own state except through the proposal doors.
4. **Plugins may hand skills, to Ask Daoris and to sessions.** A plugin may carry skills (a folder of `SKILL.md`
   documents) declared for Ask Daoris, for sessions, or both. Daoris hands them through the harness's own door for a
   spawn, never by writing into a repository's checkout (`repository-owns-its-work`): the room is Daoris's own folder,
   and a repository's session takes them from the spawn tier the way it takes its servers. Which tier a harness reads
   skills from untrusted is measured before it is built, as D107 measured its rules.
5. **Installing them is installing a plugin.** A plugin that carries servers or skills comes the way every plugin comes
   (D120's workshop and packages, the Plugins screen); there is no second catalogue for skills or servers.

### What this does not decide

The manifest's fields for a server's or a skill's destination, the allow shape for a plugin's tools in Ask Daoris, and
the harness's tier for skills are the build's (HELPPLUG1a, HELPPLUG1b), each recorded as a dated note here.

### Rejected

- **A shell for Ask Daoris, or a "run any driver verb" tool.** Either makes every change the helper's, with nobody's
  press (D89, HELP4).
- **Writing a plugin's skills into a repository's `.claude/`.** That writes into a repository Daoris does not own.

### Amends

- **D89 and the Ask Daoris design's HELP1a**: no plugin's server reached Ask Daoris; now one that declares itself for it
  does (point 3).
- **INT1 (D65)**: a plugin's server goes to sessions by default, and to Ask Daoris only where declared.
