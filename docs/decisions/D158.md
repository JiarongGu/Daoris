## D158 — Ask Daoris's conversations are the person's, kept on this machine: listed, named, pinned, searched and deleted there, resumed by the id they kept, and a new one started from an earlier one is handed its transcript (2026-10-09)

**Decision (ASKHIST1).** The owner, 2026-10-09: *"we are also missing a chat history resume and management with Ask
Daoris, so that we can reuse a session or continue with more knowledge"*, and then *"this is local knowledge, more bound
to the user, for Ask Daoris"*. Until now each press opened a new conversation, and an ended one could be read but not gone
back to (D137's MSG1c: Ask Daoris's conversation kept no id, since it never went on). The contract is
`docs/2026-09-29-ask-daoris-design.md` §9.11.

1. **Kept on this machine, and nowhere else.** A conversation is the help record the host already keeps, and its words
   are this machine's events file (D76). A help record has no workspace, so the session sync, which pushes by workspace,
   never sends it to a remote. What the person adds (a name, a pin, which earlier conversation it started from) is a file
   beside the conversation's own under the home (D63), in the inventory a delete and a history clear remove.
2. **Listed by what the person did in it.** Only conversations the person spoke in or named are listed, so one opened
   ahead (HELP5) and never used is not. Pinned first, then newest by last word. Each row has its title (the person's
   name, else their first question), when it was last spoken in, and the first line of the last answer. Search matches
   the name and both sides' words, bounded, and says when it left older ones out.
3. **Resumed in its own conversation, by the id it kept** (D137 point 8). The help place now keeps its harness
   conversation id. Words to an ended one are kept on its record through the say door and taken up with the same
   judgement and account resume as a chat. The room holds one conversation at a time, so the running one is set aside
   first; it keeps its own id. One mid-turn is never stopped, and the words wait with the reason said. A conversation
   with no kept id offers a new conversation from it instead.
4. **A new conversation from an earlier one is handed its transcript**: both sides' words, the newest 48,000 characters,
   saying when the start was cut. It is a file in the new conversation's own folder, attached to the first message with
   a preface naming it.
5. **Two doors** (D50): the panel's history, and `daoris-driver help list|resume|rename|pin|unpin|delete`. The
   terminal's `--json` row is the panel's row field for field. A new conversation from an earlier one is the panel's
   alone, since no terminal door opens an Ask Daoris conversation at all.

**Why.** The owner's two sentences together. The conversation is what Ask Daoris has learned with the person, so losing
it each time loses that. It is also about the person, not the work, so it stays where the person is (D63), not where a
workspace syncs to.

**Rejected.**
- **A summary, rather than the transcript.** Daoris calls no model (D24), so it has no summary of its own. Asking the
  earlier conversation's agent for one would spend a turn and reopen the conversation being left.
- **A history store of its own.** The help record and its events file already hold every word. A second copy would be a
  second place to delete from.
- **A name on the session record.** That record travels (D47 §4), and D76's RAIL1 rejected it for that reason. The name
  is on a machine-local file beside the conversation.
- **Resuming by default.** The newest ended conversation still opens a new one when the panel is pressed (HELP1a), as
  before. Going on is a press (*Go on in it*) or a row chosen from the history, so an old conversation is never revived
  by accident.

**What it amends.** D137 MSG1c's "Ask Daoris's keeps none, since it never goes on", and `help` as a door that takes no
words once ended. D89's HELP1a: a message after a restart still opens the next conversation, and now the person may
resume instead. D76's RAIL1 rejection of hand-naming, for Ask Daoris's conversations only: a chat's name is still derived.

**ASKHIST1, built 2026-10-09**, held by `HelpConversationsTests`, `HelpGoOnTests`, `HelpCommandTests`,
`DriverModuleHelpHistoryTests`, `AskHistory.test.tsx` and `AskPanel.test.tsx`; `HelpChatTests` (Process) runs through
