## D282 — A done whose own record says work is left is unfinished, derived and never stored: it stays where open work is listed until it is finished or the person sets it aside (2026-11-12)

**Decision (LEFT1, the owner's, of an ask: *"an unfinished work now its all called done which is kind wrong too"*).** A quest closed
done while its own record said part of the work was undone read as finished work everywhere: its session's line said *the quest
reached done*, its ask read done once the person accepted the departure, and nothing asked for the part that was left.

1. **Three kinds are left.** A done that departed from a requirement, accepted or not (the person's yes lets what follows go on and
   finishes none of what was left); a run whose step failed after its quest's done and is kept for the person, or whose end is failed at it, so what follows it never ran; and a
   held part, which the run's held attempt and a departure already say. Each is read from records that already hold it
   (`Quest.Left`, `PersonWaitReader`), never stored, so no replicated record changes and no older build disagrees.
2. **It is never the word done.** The service lists it with the outstanding quests and an ask holding one is not done (the channel's
   line for it says *awaiting*); the driver reads the session that finished it as *needs you*, reason `left`; its end's note says part
   is left (`ended.done-left`); the web draws it as *done, part left* in a group of its own, and *What needs you* has a `left` row for it.
3. **It asks for a next step and ends by the person's act.** The run view where the failed step is acted on, the quest's page where the
   departure is read, and the person's archive of the session, which sets it aside (a step that waits for the person's word is never
   hidden by the mark, a left one is the person's to set aside). Closing its ask is the person's other end.

**Rejected.** A stored *partial* status on the quest: a new status and an operation for the person's close travel through the quest
log, the wire, the cache and every older build, for a fact the answers and the run's end already say. A new quest operation for the
person's close of what is left: the same cost and a second way to the end an archived session and a closed ask already give; it is
the one thing still owed when a person needs the close to follow the quest to another machine. Reading *held* in the handback's
words: a free sentence is no record to derive a state from; a part held is a departure or a held attempt, as it is already recorded.
Showing the run's state beside a plain done: the quest would still read finished in the places that read the quest alone.

**What the checks do not cover.** The installed driver was not run on the work workspace's records. Quest `#18cf517f5c58`'s handback (requirement 8
departed) and run `#ae13d72400ed`'s node record (its pull-request step failed `no-token`, settled with no word on it, the run not
ended) were read; each case is shown by a test built on that shape.
