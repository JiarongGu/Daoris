## D142 — Daoris's lines in a session's note are worded by code in the reader's language and someone's words are shown as written; a session writes to people in its work's language, set apart from the window's (2026-10-03)

**Decision (LANG1).** The owner, 2026-10-03, seeing a page-built preface in English: *"we should be building a multi
language support"*. On where a session's language is set: *"so the UI language and session language should be able to
set differently this is more like system level or usage level"*, then, correcting the first reading: *"because session
itself is bind to the work and the ui is bind to the user I think you got this in reverse?"*. Read from the owner's
install and the code at `122db847`: all 70 session records carry a note that opens with a line the driver wrote in
English, the 中文 window shows them as written, and only D126's verdicts, MSG1f's reasons, the modules' refusals and a
cool-off's reason are worded by code. Nothing tells a session which language to write in. The contract is
`docs/2026-10-03-language-design.md`.

1. **Whose words a text is.** A line Daoris writes about a session is chrome: the page words it from a code and its
   values, in the reader's language, from both catalogues. An agent's question, last words or closing note, the person's
   words, and a quest's or an ask's title and body are content, shown as written. A program's words (an exception's
   message, git's) pass through as written, as `DRIVER_REFUSED` passes the driver's sentence. **A note that is both is
   split**: Daoris's lead-in is a code, the words beneath it a part of their own (design §2).
2. **The record keeps both.** `noteParts`, an ordered list beside `note`: a coded part carries its code, its values and
   its own English; a words part carries the words and whose they are (`agent`, `person`, `program`, or `before` for an
   English note from before). Values are facts, never a path and never an account's name. **`note` stays byte for byte**:
   it is the terminal's, the driver loop's lines', the next session's prompt's, an older page's and host's, and the
   rehearsals'. A move that writes a note without parts clears the parts. The store, both session routes, the remote
   feed (through `SessionNote.ForAnotherMachine`), the modules and the stop request carry them (design §3).
3. **Every line has a code.** 72 English lines at about 60 sites in 15 files become 66 codes, two writers' (the driver's
   and the service ledger's), with each code's values and its English and 中文 in design §4. An exception's message and
   the person's words on a finish or a decline stay words with no code.
4. **One list, held both ways.** Each writer declares its codes once; its test reads both catalogues and fails a code
   either language does not word, or whose entry drops a value. The page's test parses both declarations and holds its
   map and every `note.*` key to them. **A part the page cannot word** (an unknown code, a newer driver than the page, a
   missing value) shows its own English, marked *shown as recorded*. A words part is never marked (design §5).
5. **Records from before** show their note as kept, marked *shown as recorded* / 按原文显示. No pattern table re-reads
   the English and no migration rewrites the store (design §6).
6. **What Daoris writes to an agent stays one copy, in English**, plus one line naming the session language where one is
   set: the claiming, resuming, carrying-on and intake instructions and a resumed conversation's opening. Not a chat and
   not Ask Daoris, where the person writes to the agent directly. The driver's checks read the exit code, the quest and
   the harness's own output, never the agent's prose, so the line changes none (design §7). **Settled by the owner**
   (2026-10-03): *"since Ask Daoris is more like a chat so the UI will follow the UI as system but the chat itself usually
   just behaves like a regular LLM (multi language support)"*. Ask Daoris's chrome is the window's language; its
   conversation, like a repository's chat, answers in whatever language the person writes, and is handed no language
   line.
7. **The session language is the work's.** Set for a repository or a workspace, the repository's winning; neither is
   none. Kept in `driver.json` as `languages` and `workspaceLanguages`, resolved as `lines` and `landings` are, from a
   closed table (`en`, `zh`) on each side of the twin. **Both doors**: `daoris driver language <repo> en|zh|--clear`
   (`--workspace <name>` too) and `daoris driver list`; a repository's page in Repositories and Settings → Workspace; and
   Ask Daoris's `setting` kind (D110). **Unset, every instruction is byte for byte today's.**
8. **The window's language stays its viewer's** (D66, D110 §4), the user's, in Settings → Appearance. It never sets the
   session language and is never set by it. There is no machine-wide session language.
9. **The terminal stays English.** `daoris` carries no catalogue by construction; a terminal in 中文 would read these
   codes, and is a later question.

**Why.** A sentence the driver writes is chrome (the platform language §4), and the page already words one by its typed
half where it has one; the note had none, so the whole record read as English in a 中文 window, and the only way to word
it was to match the English, which the platform language forbids. Keeping the English beside the parts changes nothing
for any reader that reads it today, and a split note keeps the agent's words out of every catalogue. The instructions are
a contract, and a second copy in another language drifts where its maintainer does not read; one line naming a language
asks for the reader's language without a second contract. And the owner's split is the right one: who reads a window and
what a session works on are two things, so the window's language is the viewer's, and the session's is set where the
work's other choices are set.

**Rejected.**
- **Translated instruction templates**, and **a structured note in place of the English**.
- **A pattern table over the English**, and **rewriting old notes**.
- **One part holding the lead-in and the agent's words as a value**: the words would ride through a catalogue entry.
- **A machine-wide session language**, and **the window's language as the session's** (the owner's correction).
- **The repository's manifest as the session language's home**: it travels, but it has no door but hand-editing, a
  screen's press would write a tracked file in a checkout Daoris drives, and tracked wiring was refused for the fork and
  mirror case (the workspace design §2). **A workspace record in the registry**: a table, routes, a feed and a conflict
  rule for one field. A repository wanting every agent and clone to write in one language says so in its own instruction
  file.
- **An ask's or a quest's own language**: a field across the ask's and the quest's wire, store, feed and composers for a
  case not yet seen. Reopened when one is wanted.

**This amends:** the platform language §4 (*Language*: the driver's words stand only where the page cannot word a part,
and a record from before), the frontend architecture §3 and D42's boundary (a session note's Daoris lines move from data
to chrome; the service's refusals stay verbatim), D116's word that the check cannot see a sentence the driver writes
(a note's lines are catalogue entries now), and Settings → Appearance's hint, which LANG1b re-reads. D46 §4, D51 rule 4,
D66, D110 §4 and D137's preface stand. The rows are design §9: LANG1a, LANG1b and LANG1c.

**What the checks do not cover.** Documents only; nothing is built. The sites were read at `122db847`, the integration
branch carrying MSG1b–MSG1f, which main does not yet carry. The 中文 wording is a proposal, not yet held by
`names:check`. Whether an agent writes in the language its line names was not measured: no turn was run. `verify` checks
this entry's place and the design's links, and none of their words.

**LANG1a, built 2026-10-03: the driver and the ledger write each line as a code** (points 2–4; design §3–§5), held by
`NoteCodesTests`, `NoteSitesTests` and `ContinuationTests` (driver), `NotePartsTests`, `SessionSyncTests` and
`LocalHostTests` (service), `DriverModuleSessionsTests` (modules) and the web's `locales/note.test.ts`. What building it settled:
- **One composer, `Noted`**: each site composes its English exactly as before, joined with its glue, and its parts beside it,
  so a coded part's text is inside the note by construction and every site's test holds the English byte for byte. Where the
  English interleaves two lines (a declined sentence holding its exit, an unrecorded tree holding git's words), the second
  rides beside the first: the first's text is its whole sentence, the second's the words inside it. `ended.exit` rides so
  on rows 1, 10, 11, 42 and 43, its text `exit N`.
- **Values.** `started.tree`'s `basedOn` is the branch the tree started at (the line's, a chain step's, or `HEAD`), never the
  phrase that spells it for a person. `quests` is a list, `exit` and `minutes` numbers, `until` and `at` ISO 8601 in UTC to
  the second. A `why` is a reason's code with that reason's own values flat beside it (`from`, `to`, `adapter`, `agent`), as
  the page's `reasonOf` already takes them; `elsewhere`'s `agent` is the adapter the record ran on. `account.cooling`'s `why`
  is one of `harness.cooling.why.*`'s four (`CoolingWhy`). `account.refused` carries only the owner; the account's name
  stays in the English, which the cleaner cuts.
- **Words with no code**: an exception's message (`program`); an answer, a finish's note, a decline's reason and an ask's
  closing note (`person`); the agent's question, last words and a turn's failure (`agent`).
- **A note from before parts is carried whole as one `before` part** wherever a line is added to it: the driver's went,
  cannot and carried-on lines, the ledger's answer and going on, and a note a move passes without parts as it goes on.
- **The store and the doors.** `note_parts` is written with the note, cleared by a note without parts, kept by a move without
  one. The state door keeps only what a part is. The feed carries them both ways, cleaned at the push, and every session
  answer carries `noteParts`, cleaned as the note is for a caller off the machine. The create door takes no note, so no
  parts. A stop's reason and note in the registry, and a stop's request file (`noteParts`), carry them, so a pause's and an
  abandon's line keeps its code through another loop. The modules compose nothing: `RESOLVE_SESSION` goes through
  `SessionMoves`, and a part serializes in the record's shape wherever a route hands it on.
- **Added since the design read the code** (MSG1c), to §4's stop table: `chat.not-kept` | — | *Daoris kept no id for its
  conversation, so words written to it cannot go on in it.* | *Daoris 没有为它的对话保存 ID，所以写给它的话无法在其中继续。*
  The other sites MSG1c and MSG1e added write rows 38 and 39; `SessionSay.cs` writes no record note. 67 codes: 64 the
  driver's, 3 the ledger's. `account.refused-own` is worded as a sentence of its own, the design's cell having described it.

Proof: both writers' catalogue tests and the page's twin test were seen failing on a `zh` entry that dropped `{{minutes}}`
and a `note.*` key no writer declares. `names:check --strict` and `--all` find nothing in `note.json`.

record's note. Nothing is on the window.

**LANG1c, built 2026-10-03: a session writes to the person in its work's language** (points 6–8; design §7), held by
`SessionLanguageTests`, `SessionLanguageHandedTests`, `HelpSettingProposalsTests` and `HelpCoverageTests` (driver),
`DriverModuleLanguageTests` (modules), `driverconfig.test.ts` (CLI), and the web's `settings/Languages.test.tsx`,
`projects/SessionLanguage.test.tsx`, `WorkspaceDomain.test.tsx` and `ProjectsView.test.tsx`. What building it settled:
- **The table and the twin.** `en` is *English*, `zh` *Simplified Chinese (简体中文)*, the name the line gives the agent, held
  row for row on both sides. A code is read in any case without the spaces around it, and only where the table holds it; a
  name written twice in any case is read where first written. The repository's wins, then its workspace's (one in no
  workspace is in `default`, as its line is), else none. `.claude/knowledge/twins.md` has the row.
- **The line** is the design's, a paragraph of its own after the close in the claiming, resuming and carrying-on
  instructions, and in the intake's after its close (what it says when the declarations do not settle the ask), before its
  boundary. **A resumed conversation is told in its prompt's appendix**, after the person's words and the go-aheads' answers:
  `Continuations.Opening`, which the design named, is the record's first line, and no agent is handed it. A native run's
  go-on with words said while it worked (MSG1b) is not told again: its conversation was handed the line at its start. Unset,
  the target and intake goldens stand byte for byte, and set adds exactly the line.
- **The screens name each language by the driver's table**, which `STATE` answers as `languageTable`, so a new language needs
  no window catalogue (§7). The repository's page shows its resolution and its own field beside its standing answer;
  Settings → Workspace's *Session language* card, after the lines, sets each workspace's and each repository's, as Lines and
  Across do. `LINES` answers each repository's resolution and where it was set. A shell older than this answers no table,
  and neither screen offers the field.
- **The terminal reads no registry** (D50), so `daoris driver list` says each repository's own and each workspace's *for each
  repository there that sets none*, and *none set* when nothing is; the screens say what each repository resolves to.
- **Ask Daoris's door is judged and owed.** `HelpSettingProposals` judges `language` by the table and the registry, as
  `SET_LANGUAGE` and the terminal do, but it is not among the kind's `Doors`: the service's setting writer
  (`HelpProposalBox.Setting.cs`, `KnowledgeTools.Help.Setting.cs`) is another lane's, so `HelpCoverageTests` holds the verb
  and Settings → Workspace's control owed, as `cooloff` is, and the room's doors name both screens and the command.

**What the gates do not cover.** The `Process` half and the rehearsals were not run; no instruction changed where nothing is
