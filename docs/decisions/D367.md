## D367 — A need is learned per repository, kind and one gate; a run of gates asks the largest of its gates; a wait says learned or declared (2026-11-27)

**Decision (LEARNEDKEY1, under D349 and D362; the owner's ask of 2026-11-27: the learned file held one key, `<repository>|test|reached`,
while a session's check waited for "31.3 GB" of memory, and every gate that was not that one fell back to the declared 8 GB).**

1. **One gate, one key.** A need is kept under the repository's key (`HeavySlot.KeyOf`, its common git folder: every tree of a repository
   and its landing line read one history, never a tree's or a folder's), the kind and **one gate's name**. A run of several gates used
   to be kept and read under the names joined (`lint+test`), so every new combination had no history and asked the declared cost.
   The old joined keys are not read and not moved (D323: they are dropped; the file keeps its last eight runs of a key, so they age out).
2. **A gate is kept as it ends.** Each gate's end reads the run's job: its peak memory so far, and the cores it kept busy (the job's CPU
   time since the gate before over its own wall time). The peak is what the run had held through the gate: exact for a gate that raised it
   (a gate run alone, or a gate heavier than those before it), the run's peak for one that ran after a heavier. It is never less than
   the gate took, and the largest of a run's gates is the run's peak.
3. **A run of gates asks the largest of its gates, never their sum.** Its gates run one after another in one job, so the memory one
   needs the next does not (`LearnedNeeds.OfGates`). A gate with fewer than two runs counts at the kind's declared cost, and the run's need
   is `learned` only where every gate's is; one declared gate in it makes it `declared`. A check's unit stays its one `reached` gate (the
   whole run, kept by the executor), as it was.
4. **A wait says what its number rests on.** `CheckWait` carries `source` (`learned` or `declared`) beside the memory it names; a check's
   step says it in the reader's language (`workflow.wait.basis.*`), and the terminal's words and the driver's log say it in brackets.

**Rejected.** The median of the recent peaks as a run's need, to admit more at once: it reverses D362 point 2 (a run's peak is a floor of
what the next may reach), and the owner's case did not need it, since the 31.3 GB was three checks at the learned 10.4 GB each (the asking
check and two still starting), not a declared default. A job per gate to measure each gate alone: a nested job per step and a gap
between jobs in which a crashed run leaves nothing to end; the running peak is exact where it matters (the heaviest gate) and never low.
Keeping the joined key beside the per-gate ones: two truths for one number (rule 4).
