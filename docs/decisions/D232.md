## D232 — No compatibility: Daoris keeps no reader of older records, builds or configuration; a release converts the home once and deletes the old logic (2026-11-04)

**Decision (NOCOMPAT1, the owner's direction of 2026-11-04).** Daoris runs on one install the owner controls, and its data can be
updated directly, so nothing needs to stay compatible.

1. **No older reader.** No code reads a record, key, file or layout in a shape an older build wrote. No door is kept only to refuse
   an old form. No word, verb or launcher is kept for an older name.
2. **One migration per release.** A release that changes a stored shape carries one migration. It runs once at the release's first
   start, takes a backup of what it changes into the home's salvage, converts the home's data to the current shape, records that it
   ran, and is deleted in the next release that changes a shape.
3. **Deleted with it:**
   - the transitional register and its marker gate (`Driver/Transitional/`, `tools/transitional-markers.mjs`);
   - the floor of older builds (`HomeFloor`, `OlderBuild`);
   - the conversion door's receipts, review and undo, and its older-shape readers;
   - the old workflow engine and the doors it kept (WORKFLOWCLEAN1z);
   - the old command names and the `daoris-driver` launcher;
   - every key and file the current code no longer writes.
4. **D228 stands,** without its clause on kept older readings: a change that supersedes a way removes the old way in the same chunk,
   with no condition to wait out.

**Rejected:** keeping any reader "until the census ends" (one install, converted once, has no census to wait for); a conversion the
person reviews and undoes (the backup is the undo).
