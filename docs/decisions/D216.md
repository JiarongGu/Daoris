## D216 — A session's tree carries the machine-local files its repository's gates read, copied from the checkout read-only, as the checkout's gates file declares them (2026-10-29)

**Decision (TREELOCAL1, 2026-10-29).** A tree git checks out holds what git tracks, so a gate that reads an ignored file only the
owner's checkout holds runs weaker in every session's tree: Lyntai's leak check reads `local/sensitive-patterns.txt`, found none in a
fresh tree, fell back to its built-in patterns, said so in a line nobody read and passed, so each driven session's verify ran a weaker
leak check than the checkout's. The devkit's own scan refuses to run without the list instead, which fails a session's gate for want
of a file it could not have. **A session's tree now opens with the files its repository's gates read under `local/`, each copied from
the checkout read-only**, beside TREEDEPS1's dependencies (D51's note) and under the same rules of a copy, and the opening says what was
copied and why a declared one was not. The gate tree of the merge tool already took the pattern list the same way (D115's GATEWT1b
note); this is that rule for every session's tree.

1. **Where it is declared: the gates file.** `daoris.gates.json` already names the pattern list (`sensitive.patternsFile`), and it is
   the file of what the gates do (D26), so a repository names the rest there: **`localInputs`**, a list of repository-relative paths
   under `local/`. The pattern list is one whether `localInputs` names it or not: as declared, or the devkit's default
   (`local/sensitive-patterns.txt`) where `sensitive` names none, so a repository that only declares its list, as this one does, needs
   no edit. No gates file, or one that does not read as an object, declares nothing; the repository's own gates refuse an unreadable
   one in their own words. The devkit's record reads the key (`GateDeclaration.LocalInputs`) and no devkit gate uses it.
2. **The checkout's declaration, never the tree's.** The copy reads the checkout's gates file as it stands. What leaves the owner's
   private files is the checkout's say, never a branch's: a chain's step grows from a branch a session wrote, and a declaration there
   could name any other file under `local/`.
3. **The gate, per file.** A path under `local/` in git's spelling, none of its parts empty, `.`, `..` or holding a colon; the checkout
   holds it as a file; git ignores it in the tree, so the copy never reads as the tree's work and `git status` never shows it; and no
   link stands between the tree and where it goes, nor anything already there. A miss copies nothing of it and is one coded line of the
   opening: `started.local-missing` where the checkout lacks it, `started.local-refused` for any other miss, `started.local-failed`
   with the program's words where the copy failed or git could not say what it ignores. The one exception is the implied default the
   checkout lacks, which says nothing: a repository that never wrote a list may scan with built-in patterns on purpose, and a line on
   every opening would be the line nobody reads. A file copied is `started.local-copied`, the files as a list; `started.tree` and
   `started.tree-copied` keep their words, as every opening recorded before says them.
4. **A copy, read-only, never a link.** Copied under a name of its own beside where it goes (TREEDEPS1's prefix), marked read-only and
   renamed into place, while the tree is still locked as opening; a cancel takes back every file this open copied, and OPENCUT1's undo
   takes the tree. Read-only so a session's write to its gate's input is refused rather than quietly weakening the gate; a session that
   means to change the list changes the checkout's, which is the owner's. It is not refreshed while the tree lives: the next tree
   copies the list as it then stands.
5. **The agent is told** in the told-once field the dependencies already use (`TreeOpened.Dependencies`, read by the session's handed
   close and the conversation's first words): what was copied, that it is the checkout's, and that a gate's finding is fixed in the work.
6. **It goes with the tree.** Removal, a landing's tidy and an undone opening take the copy with the tree: TREEKEEP1's judgement keeps a
   shared ignored file only where the checkout does not hold it as written, and the copy holds the checkout's bytes. Proved on
   Windows: git's removal of a tree holding the read-only copy succeeds, and the checkout's file stays.

**Rejected:** `daoris.json`, the CLI's inert manifest, which names no gate and no file a gate reads (D26); a link to the checkout's
file, through which a tree's write would land in the checkout, and which on Windows needs a privilege; a hard link, which shares the
read-only mark with the checkout's file and every write with it; the tree's own declaration (point 2); copying any ignored path a
declaration names, which would carry a `.env` or a credential into every tree, where `local/` is the family's place for machine-local
files and the merge tool's gate tree takes only it; refreshing the copy while the tree lives, which no gate needs within one session;
and saying the absent default on every opening (point 3).

**Proof:** `TreeLocalInputsTests` (the declaration, the implied default, a missing, refused and failed file, a link on the way, a
cancel); four `SessionTreesTests` rows on real git (a tree holding the read-only copy with the checkout's bytes, `git status` clean,
the devkit's own `scan --tree` in the tree finding a token only the copied list names; a declared file the checkout lacks said on the
opening; an open cut off while it copies leaving nothing; the removal); `NoteSitesTests` for the opening's lines;
`noteLines.test.ts` for both languages; `GateDeclarationTests` for the key. Code: `Workplace/TreeLocalInputs.cs`,
`SessionTrees.OpenAsync` and `OpeningOf`.

**Not in it:** a tree made again on its branch after it was gone (TREEGONE1, `TreeReturns`) copies neither its dependencies nor these;
a pooled tree (D214) would need the same at its hand-out; and TIDYOUTPUT1's judgement of disposable output must keep reading a copy
as the checkout's, never as authored `local/` work.

**Note, 2026-10-29 (TREELOCAL2): a tree made again takes the same copies.** Rules 1–6 bind a remake as they bind an opening. `TreeReturns`
makes the tree again with `worktree add --lock` under the opening's lock reason (`TreeOpenings.LockReason`), copies the dependencies
and then the declared `local/` inputs into it, and lets go of the lock; a remake cut off while it copies takes back what it copied and the
folder it made through `TreeOpenings.UndoAsync`, which now keeps the branch when told to, since the branch holds the session's commits.
The record says what was copied and what was not by the opening's own lines (`started.local-copied`, the declined lines of both), after
`tree.remade`, whose words no longer claim the dependencies are installed again: they say the tree holds what git tracks and the copies
Daoris makes from the checkout, and that the lines after say which. The agent is told the same sentences an opening tells
(`TreeStanding.Told`, handed to the target's `Dependencies` where the session goes on in a remade tree). TIDYOUTPUT1 needed no change: it
judges a copy by its bytes against the checkout's, however the tree was made. A pooled tree (D214) takes the same copies at its hand-out
when that pool is built; none exists yet, so none is built here.
