## D220 — What is written is kept current by replacement: only what the code cannot say, one home per present fact, history apart, and tests that pin rules (2026-10-30)

**Decision (the owner's direction, 2026-10-30; the canon's `current-knowledge`, and one line in `persist-working-state`).** Daoris's
managed development, here and in every repository the canon reaches, writes only what the code cannot say (why, what was rejected,
the contract between parts, what the checks miss). Each present fact has one home that is rewritten when the fact changes, and the
entry it replaces is retired in the same step, in an agent's memory as in files. History stays append-only and read by lookup, apart
from the present. Tests pin behaviour and rules, never counts, file lengths or line numbers.

**Why.** On 2026-10-30 this repository's batch added about two characters of hand-written prose for every three of production code
and twice as much test code as production code. Each part appended a long dated note listing its tests and times, and a sentence to one
README row (eight thousand characters, in conflict at most merges). Censuses pinned call-site counts and file lengths. Every code change
paid to keep that in step, and the work slowed. An entry added beside the one it contradicts leaves a reader to believe whichever it
reads first.

**Rejected.** A ceiling on note length alone: the notes would shrink and still restate the code. Ending the decisions record's
append-only notes: history is what stops a rejected choice being rebuilt; what changes is that it no longer serves as the description.

**Not covered.** No tool yet finds two entries that disagree, or an entry of an agent's memory or the knowledge store that a newer one
replaced; KNOWFRESH1 is the row. The existing censuses that pin counts are not yet rewritten.

CENSUSRULES1 (2026-10-30): a census pins its rule, not a count. Each file allowed to make the call stays listed with its reason; the census fails on a file not listed (the new reader it exists to catch) and on a listed file that no longer makes the call, never on how many calls a listed file makes. A count stays only where the count is the purpose (a bound, a budget), with one line saying why. Each census proves it twice: a stand-in with a new file making the call fails; one with one more call in a listed file passes.

KNOWFRESH1a-ii (2026-10-31): the uncommitted reading is no longer taken as the index is. It runs behind the answer, one repository at a time, and a hit waits for its own repository three seconds at most, then says `+ uncommitted not yet read`, never clean.
