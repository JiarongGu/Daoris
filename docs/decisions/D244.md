## D244 — Events an outside session hears are read from records, a live wake is built only where the first build's use asks for one, and an outside agent speaks on a channel as a member of its own (2026-11-06)

**Decision (EVENTHOOK1d, EVENTHOOK1e, CHANNELJOIN1), proposed 2026-11-06 for the owner's yes.** The design is
`docs/2026-11-06-event-channel-design.md`, written by Claude Opus 5.5 from the code on main at `df7f178bf`. It holds only the choices
that rejected an alternative; the rest is the design's.

1. **The quest kinds come from the replay's moves.** The `quests` cache, written whole by the replay in the operation's transaction,
   journals its inserts and its status moves by trigger, as `sessions` does. `quest.published` is a row inserted, `quest.closed` a move
   into `done` or `declined`, and `quest.close-lost` a move out of a close, which only a rebase makes.
   *Rejected:* the quest log's `quest-op` rows, since an operation kept need not move the quest and a rebase that loses this machine's
   close rewrites the log in place and journals nothing; the look's snapshot (C5.4); and a read of the quest at each row, which tells a
   later state than the move.
2. **One teller in the lease's process reads them, with no cursor kept**, and tells `events.missed` when it takes its place and at each
   batch whose history is incomplete. *Rejected:* a kept cursor, which would replay across a restart; an event is a wake.
3. **`person.answered` is told from the pipe's confirmation after its record says the ending, only where no terminal waits on its
   line, carrying the confirmation's own id.** *Rejected:* the terminal's request id, which is the asker's own string and reads the
   answer with its key; telling every ending, two wakes for one answer.
4. **`work.ended` is link 1's.** The end keeping answers the entries it wrote, link 1 emits the chain's `work.ended` where an entry's
   verdict is ended, and the lease's hook set tells the unit. *Rejected:* the bound run's end, which is its workflow's and not the line
   holding the work.
5. **A relay that lives for the session is built only where the first build's use shows a batch read late because its session was in a
   turn, and then one adapter, the inbox first.** *Rejected:* building both, two ways to wake; building either before the first build's
   figures.
6. **The inbox's token is taken into memory at the entry, read by `events relay --inbox` alone, never written, and sent only to a pipe
   whose server is the session's own process. A refused batch is folded into one gap line in the next post and never sent again; three
   refusals end the relay with its batch on stdout.** *Rejected:* retrying the batch, which the inbox drops as a repeat; dropping it,
   round 2's silent loss.
7. **A channel, if built, is the relay's own channel form behind a front its `--where` writes.** *Rejected:* the knowledge server's
   channel, which needs the grammar, the lease and the pipe rule as twins, serves a workspace's home in this repository, and whose
   launcher drops what a server it left writes.
8. **The measurements run in a session the probe starts in a pseudo-console**, on the machine's account, never in the owner's or the
   steward's. *Rejected:* measuring in the owner's session, which spends its context and mixes its work with the probe's.
9. **An outside agent on a channel is a member, kept in the asks store, never synced, whose messages carry its own id as their
   poster.** *Rejected:* a ledger session, which every reader of observed processes would read as a lost run; a message with no
   session, which this build, an older one and a teammate read as the person's; a key, which guards nothing a process of the same user
   cannot read and is a second way to name a speaker.
10. **A member is admitted by its own press under the person's Confirm**, refused before any card where the asker is in an agents' job.
    *Rejected:* a role, which acts on the owner's behalf where a member only talks; a standing grant, before the Confirms are counted;
    the person admitting first, which carries the id to the agent by hand.
11. **A member's doors are the terminal's channel verb and agent-class doors of the service; the connector refuses a member's id.**
    *Rejected:* the connector as a second door now.

in the journal); D225 rules 9 and 10 (a channel's outside member).
