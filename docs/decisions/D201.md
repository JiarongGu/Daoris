## D201 — A terminal's standing confirmation: the person grants it once in the window, and while it is on a terminal outside every agent Daoris runs may stop or finish a session and hold or resume a repository without the card, each use logged and said on what it acted on, revocable at once, on this machine alone (2026-10-23)

**Decision (TERMTRUST1, proposed).** **Status: proposed**, round 3, written by Claude Opus at `f506863e7` and revised after Codex's read
(D191) and Fable's foundation read (D191's amendment, since it changes D156 point 4 and the containment every agent start rests on); the
notes below. The steward accepts after reading this round. The contract is `docs/2026-10-23-terminal-trust-design.md`.

The owner set the direction on 2026-10-23: the steward, an agent the owner runs by hand, drives the owner's local install for
development and testing, and stopping or finishing sessions from a terminal should not need the owner to press Confirm in the window
each time. Read at `f506863e7`, every terminal press the pipe's census makes the person's waits for the window's card
(`InstancePipe.Accept`, RPC1c; D156 point 4), so each routine stop costs the owner a press. The steward set the shape: no agent
bypasses the card; the person grants a standing yes once, in the window; it names management presses only; it never covers words, go-
aheads, sign-ins, widenings, a landing's push or a widening setting; each use is logged and said; revocable at once; this machine
alone, never synced.

1. **The standing confirmation** (长期确认; the glossary's *trust* is a folder's, design §0.1). The person turns it on, with their own
   press, on Settings → This Daoris → *A terminal*. While it is on and Daoris runs, a terminal's press it names, in exactly its verb's
   form and conditions, from a process in no job any Daoris on this Windows session made for an agent, runs without a card. Everything
   else asks as today.
2. **The presses it names** (design §2.1), each a route and a form whose every field the verb sends and nothing more: `stop`
   (`STOP_SESSION { id, said: true }`); `finish` (`RESOLVE_SESSION { id, state: "completed", said: true }`, no words of the person's,
   only for a session with no process on this machine, never through the request folder, which stops before the ledger moves: the verb
   answers `running-here` where it finds one; moved by the ledger only from `awaiting-person` through an expected state the store compares
   in its transaction); `hold` (`SET_HOLD { repository, held: true }`); and `resume` (`SET_HOLD { repository, held: false }`,
   only a hold a covered `hold` made during this run and nothing has touched since). TERMTRUST1b adds `done`: `quest done` moved onto the
   pipe as `QUEST_DONE`, covered with no words for a quest no session here still serves, bound to no graph version and no closure graph,
   neither held nor withdrawn by a source's reopen, whose last session here, named by the relay, was finished (read by its note code,
   `stopped.checkpoint-finished`, never its words), each condition judged in the service's own transaction. A grant names its presses; a later build's press covers nothing until the person grants it.
3. **What it never names** (design §2.2): words as the person, the keeping stop, `decline`, any answer or yes, *Try again* and every
   release of the person's own stop or hold, landings, hand-offs, discards, deletes and clears, every other standing choice
   (`SET_DRIVABLE` among them), sign-ins and account acts, and itself.
4. **Who it covers** (design §3.3). Each Daoris process that runs agents holds one named job, `Local\daoris-agents-<process id>`.
   Every agent it starts, a plugin's process and a partner's piece are **contained from their first instruction** through the partner's
   launcher, generalized: `daoris-piece-start` joins the agents' job and then any job of its own, which nests beneath, and only then starts
   the harness on the stdio it was handed, the driver rewriting each start in place as it does for a piece. A start it cannot contain (no
   launcher laid out, as in a workspace build; a job refused) is still made, logged `agent.contained: false`, and while it lives its
   process holds `Local\daoris-agents-<process id>-open`. The pipe keeps a handle to its client's process from the connection's taking. A
   press is covered only where that process is in none of the jobs of the prefix found in this Windows session's namespace, every one of
   them read, no `-open` object and no instance pipe served by a Daoris without such a job is there, and every agent of this process is
   contained; anything else asks, and says why. Being in none never makes a caller the person (D156 §2.4): the
   person's grant covers the press, and the jobs only take the cover from an agent. An agent the person runs by hand outside Daoris rides
   it, and the grant's ask says so.
5. **Made and revoked only in the window.** `SET_STANDING_CONFIRMATION { presses }` is `Window` in the census and refuses the terminal's
   door in its handler; no verb, Ask Daoris door or `settings_*` grant reaches it; no card offers it. Turning it on asks once, inline, each
   press ticked; turning it off asks nothing, clears the instance's memory before the write, and takes effect at the next judgement. A press
   is admitted once, under the judge's lock; a revoke after it does not recall it. A grant confirms no press already waiting.
6. **Where it lives** (design §4.2): `data/standing-confirmation.json` (`presses`, `since`, a hash of this machine and account), a home
   entry of its own in the three twins, written only by that route, read at the instance's start and kept in memory, off where absent,
   unreadable, newer or another machine's. What `resume` reads is the instance's memory of the holds it made this run, never the file. No
   sync reads it. A process of the account can still write it while Daoris is down (D156 point 7); PERSONDOOR2 moves that reach.
7. **Each use said** (design §5-§7): `person.confirmation` `state: standing` as it is admitted, and `person.standing` for a grant, a revoke
   and what a start found, codes only; the terminal told `STANDING` and a line on its error stream; the session's record gains the coded
   part `standing.terminal` after its move's own note; a hold made under it is shown as a terminal's; *Notifications* heads its presses'
   group with a line naming the granted presses, its count since the start and **Turn off**. A press the grant names that asks anyway says
   why, to the terminal and in the `asked` line.

**Why.** A card is worth a press only where the person decides something. A stop, a finish of a session already waiting on them with
nothing of it running, and a hold decide nothing the person did not decide when they asked the steward to work: each only ends or holds
work, nothing is lost, and each is undone by the person's next press but the finish, whose quest then sits for them. Pressing Confirm on
each teaches the person to press it unread, which is the failure D37 and D196 name. The person's one grant keeps the act theirs (D156
point 5 counts a confirmed grant), containment keeps it from every agent any Daoris runs that stays in Daoris's hold, and saying each use
keeps it visible. An agent's ordinary reach can still leave its job by one command (`explorer.exe <program>`, `wsl.exe`), and its reach
already does each of these acts without a grant (the request folder, the home's files, the ungated service doors), so the standing
confirmation adds no act to it; every press only narrows.

**Rejected** (design §10): a verb, an Ask Daoris door or a card that grants it; *don't ask again* on a press's card; covering every
person's press or a class of them by a word; covering a caller by who it is; "in no job at all" as the caller's test (measured: explorer,
Windows Terminal and the steward's own process are in jobs); the home's own jobs only; a join after the start; a contained start built on
`CreateProcessW` (every adapter, stand-in and test would move to a new process type); a start refused where it cannot be contained (an install
with no grant would pay for it); the home id in the job's name; a process id for the caller;
persisted provenance for `resume`; a finish judged by the verb's read alone; a grant held in memory only (every update's restart would
bring the cards back); a key in `driver.json`, beside writers a terminal reaches; a sealed record; watching the record for an outside write;
an expiry; a notice per use; `decline`, the keeping stop, a work's pause and resume, *Try again* and `SET_DRIVABLE`; closing a quest as done
by confirming the service's own confirmation, which names no process; stopping the automatic landing after a covered stop.
