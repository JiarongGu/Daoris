## D214 — A repository keeps a number of session trees and hands a free one from one line of work to the next: the tree is moved to the path of the line that takes it and brought to the line there by a non-forcing switch, so a path and a branch still name one line, every record keeps its meaning and an agent's conversation is found where it was; a tree is taken only when nothing in it is work no ref holds, until the owner agrees to work kept aside; the count is the trees kept, a start past it opening a tree as today; reached in rows after FOUNDATION1's Workplace move (2026-10-26)

**Decision (TREEPOOL1, proposed 2026-10-26, round 1 under D191).** **Status: proposed; both makers' reads of round 1 are owed before any of it
is accepted.** The owner directed on 2026-10-25 that each repository keep a pool of session trees: a session takes a free tree and holds it,
locked, while it works; the tree is first brought to the line, its untracked work cleared and its ignored dependency and build folders kept;
the session works on a branch of its own; at its end the tree goes back to the pool with the work on that branch, or with no branch where it
was done with no output; the pool is a managed number of slots, at most one per session the repository may run at once, each made lazily; and
trees are removed only when that number is lowered or the repository leaves, never by age. Today a tree is opened once for one line of work
and never reused (D51 rule 2), its folder's name is its branch's, its path is the line's identity to some forty readers, and its end is a move
aside that KEEPSIZE1b deletes an hour after its record, or fourteen days later otherwise; the price is the setup a fresh tree pays (`npm ci`
170 to 221 s, .NET's `bin/` and `obj/` built again) and the bytes moved-aside trees hold (about 205 MB each). The survey
(`docs/2026-10-26-tree-pool-survey.md`, read at `6b999d6b1`) and the brief (`docs/2026-10-26-tree-pool-brief.md`) set nineteen questions;
two sealed proposals answered them, Codex's and the independent Opus reader's; round 1 of the design,
`docs/2026-10-26-tree-pool-design.md`, is their synthesis by Claude Opus 5.5 from main at `f8fbb1bb7`, answering each question (its §1),
choosing each difference with its reason and the case the other gets wrong (§1.1), and correcting the survey and the proposals against the
code (§0.2). **Its central choice is neither proposal's**: both keep a slot at a stable path of its own and move a line into it, and the code
shows such a path either reaches a shipped build as the line's own tree while it holds another line's work, or needs a second session family
in the service to hide it; so the slot moves to the line's path instead. It changes decided rules other designs rest on and it switches and
removes trees, so by D191's note of 2026-10-24 no part of it is accepted on one maker's read, and its ⚖ rows are built only after both makers'
reads find nothing blocking in them. Nothing is built, and nothing is built before FOUNDATION1's row mod-x (D212 §14.6), which has not landed.

1. **A slot is a kept tree whose folder follows its line** (design §2.1, §2.2). A repository keeps a number of linked worktrees of its
   checkout, each known by `(workspace, repository, number)` and by git's registration name, which a move keeps. A slot's folder sits at the
   path of the line that holds it or last held it, `<home>/work/trees/<workspace>/<repository>/s-<8 hex>`, today's layout; it is moved to the
   path of the next line that takes it, and a free slot is moved back to a line's own path when that line returns and its slot was taken. A
   slot's first making is today's open, said in today's words.
2. **A path and a branch name one line, always** (§3.1, §3.2, §3.3). No line's path ever holds another line's work, so `BranchOfTree`, the
   ledger's lock key, the auto-lander's and the entry landing's grouping, the trace's *same tree*, the work record's sessions by path and the
   page's folder-named branch all keep their meaning. Only the sites that meet a gone tree are re-keyed, so that a free slot is brought back
   where today they refuse or remake a bare tree: TREEGONE1, words going on, a conversation's go-on and moves, a landing, the review of an
   unlanded line, the tidy's set-aside, the press, the session lock, the opened moment and the Disk space card. Nothing is cut. A census holds
   the list.
3. **The claim is a desktop-store row, Workplace's, by FOUNDATION1 §13's rules** (§2.3, §2.4). `kept_trees`, `tree_claims` and `line_ends`,
   every column required; one claim in flight per slot, taken in one `BEGIN IMMEDIATE` transaction by the start, the end or the look, passed on
   only from a dead process run by `HomeLease`'s test, its phases marks in §13.4's sense; whether a slot is held is read live from the ledger,
   the in-use set and the claims, never stored. git's lock is TREELOCK1's session lock while a session holds the slot, `daoris kept tree` while
   it is free, which `SessionLocks.HoldAsync` learns to take over, and OPENCUT1's opening lock during a take, so a take killed halfway reads to
   every build as a cut-off open. A conversation's slot is locked too.
4. **A line's agent finds its conversation where it was** (§4). Claude Code files a conversation and keeps its trust by the working directory's
   path; a line coming back runs at its own path whichever slot is brought there, so D189 point 2's *same agent, account and tree* holds and its
   resume-first rule stands.
5. **Brought to the line, and only when safe** (§5). A start takes, in order, the returning line's own free slot, a free slot whose line is
   finished, a free slot whose line may return and that is judged clean, a new slot below the count, or else a tree as today. A slot is taken
   for another line only where nothing holds it, git lists it, the look's last guards pass, no git operation is half done, nothing is uncommitted
   or untracked and every ignored path lies under the one list (a finished line's other scratch carried, never cleared), and its HEAD is where its
   line let it go and a ref holds it; judged again inside the claim right before the move. It is then moved by `git worktree move`, its links
   into the old path made again by TREEDEPS1's rule, and switched by a non-forcing `git switch --no-overwrite-ignore` to its new branch or its
   returning line's. The first build resets and cleans nothing.
6. **Two ends a person sees** (§6). *Done with output*: commits on the branch, ready to land, the slot free but for its holders. *Done without
   output*: no commit and nothing uncommitted, the slot free, the empty branch the tidy's, grown again under its own name only if its record goes
   on. *Done, with work it did not commit*: the slot stays the line's until the work is committed, discarded or kept aside. Daoris commits nothing
   on a branch.
7. **What holds a slot** (§7): a claim, a running or parked record, words waiting for a look, a helper wait, a served review, a standing move, a
   due auto-landing, a terminal, and work no ref holds; a D79 wait, an ended conversation, a clean kept lost take and a done of either kind hold
   none. When every kept slot is held, a start opens a tree of its own as today: nothing waits.
8. **The count** (§8) is `driver.json`'s `keptTrees`, per repository, 1 to 16, beside `trees`; absent, cap + 1 read live, `max(cap, laneCap) + 1`
   once DEV6 builds lanes; set by a verb, the Projects row and `SET_TREES`. The cap, set-ups' `atOnce` and CAPCOUNT1 are unchanged; a conversation
   takes a slot and counts under no cap. What the count means is the owner's question (point 17).
9. **Lazy creation, lowering, leaving** (§9). A slot is made the first time a start finds none free below the count. A lowered count retires the
   slots above it, highest first: a free one is moved aside whole by the set-aside's move and waits D195's days as `unmarked`, a held one goes at
   its let-go, one holding work no ref holds stays; a repository leaving retires every slot; the person's press retires one; never by age.
10. **The finished record at the end in place** (§10). The look's tidy takes a pooled line's branch where it takes today's, and runs KEEPSIZE1b's
    steps with *detach in place* for *move aside*: judge, hold the tip, detach the slot, delete the branch at the commit judged, post the record
    on today's route with the line's path, so its sessions are exactly the line's. A no-output line posts none. D195's kinds gain `kept-trees`,
    rule `count`; retired slots are `set-aside`; KEEPSIZE1c to 1f stand.
11. **Dependencies kept** (§11). One list of build and dependency folders, TreeScratch's thirteen and `wwwroot`, the slim's and TREEDEPS1's its
    named subsets. Per npm project, fresh by npm's own staleness rule (the agent told to skip `npm ci`), stale and matching the checkout
    (replaced by TREEDEPS1's copy), or stale (the agent told to run `npm ci`); build outputs kept and said to be no proof of a build. TREEGONE1's
    remake, where no slot is free, copies TREEDEPS1's.
12. **Git and Windows** (§12): a branch checked out only at its line's path; the four lock reasons and the fifth; `daoris/` on every branch;
    `TreeLock` unchanged; a refused rename `busy` and a refused switch `stuck`, each measured; long paths as today; junctions moved as entries and
    made again, never followed.
13. **Records and older builds** (§14). No record changes shape or meaning; a build that does not know the pool reads every path as today,
    refuses a free slot's lock in its tidy, let-go and press, goes on in a line's slot only where it is that line's, and remakes a taken line's
    tree by TREEGONE1 on its branch; the store's new tables and `keptTrees` are invisible to it. What is left is said: a build without the pool
    beside a pool-aware one can race a return, which git refuses once.
14. **The words** (§15), en and zh, new codes with no path or account, the old ones unchanged: `started.tree-kept` and its clauses,
    `started.tree-back`, `tree.returned`, `started.tree-past-kept`, `ended.output` (已完成，有产出), `ended.no-output` (已完成，无产出),
    `ended.uncommitted`, `tree.kept-held`, `tree.kept-stuck`; the glossary's *kept tree* (保留的工作树).
15. **The install's trees** (§16) are not adopted, converted or removed by this work; they drain by today's rules, and a legacy line whose tree
    is gone may have a slot brought to its path.
16. **Reached in rows** (§17), TREEPOOL1a to 1j, each its own branch after mod-x: the slots and the census (a), the take, return and end in place
    over git, unwired (b), the sites that meet a gone tree (c), the pool on per repository, off by default (d), lines coming back (e), lowering
    and leaving (f), the install's repository on and measured (g), the default flipped (h), work kept aside (i) and finished scratch cleared (j).
    Rows b to j are ⚖ and built only after both makers' reads find nothing blocking in them.
17. **The owner's** (§18, D191 point 3): what the count means; the pool on for the install's repository; Daoris keeping a let-go line's
    uncommitted work aside off its branch and clearing it from the tree; a finished line's ignored scratch cleared when its tree is taken; and
    one bounded real resume on the owner's account. Each is asked saying what it is, what a yes does and where to look.

**Why.** The disk and the setup are spent on making and discarding whole working copies, so a working copy is kept and handed on. What must
not be handed on is identity: twenty-odd readers take a folder for its branch and a path for a line, a shipped build goes on in a record's path
by whatever folder stands there, and Claude Code finds a conversation by its directory. Keeping the slot at the line's path keeps every one of
those facts true with no reader rewritten, no service family added and no resume traded for a brief, at the cost of a rename per take and the
caches that hold absolute paths, which a row measures before anything is switched on. A slot is taken only when nothing in it is outside a ref,
so the first build resets nothing and loses nothing; keeping uncommitted work aside, which Daoris committing off-branch would be, is the
owner's to allow. KEEPSIZE1b's protocol, the set-aside's move, TREEGONE1's remake and TREEDEPS1's gate are reused where they already prove
what the pool needs, so the pool is a layer over today's trees rather than a second lifecycle.

**Rejected** (design §1.1, §19): a slot at a stable path of its own, and with it a second session family in the service for pooled lines; a
durable lease per occupation; git's lock alone, a lease file or a lease in the service; a permanent pool lock reason; `reset --hard` and
`clean -fd` before the owner's yes, `clean -fdx`, a forced switch, `worktree add --force`; loose files moved to a kept area; Daoris committing
leftovers on the line's branch; the count in `daoris.json`, the registry or a store table of its own; the cap at opt-in as a stored default; a
start waiting for a tree (put to the owner); new tables, refs or a route for a finished line's record; removal by age; `git worktree remove` of a
retiring slot; a branch named for a slot; a junction per line; copying an agent's conversation between folders; a new part handed the brief
whenever a line's slot was taken; copying dependencies at every take; a stale `node_modules` kept untouched; adopting the install's idle trees;
a no-output branch gone for good.
