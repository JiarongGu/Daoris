## D214 — A repository keeps a number of session trees and hands a free one from one line of work to the next: between lines a tree waits at a parking name no reader keys, where it is switched to the next line's branch and checked, and only then is it renamed into that line's path, so a path and a branch still name one line, every record keeps its meaning and an agent's conversation is found where it was; a tree is handed on holding nothing but what a ref holds and its npm dependencies, a finished line's other folders going aside with its record by today's rule and a live line's staying its own until the owner agrees otherwise; the count is the trees kept, a start past it opening a tree as today; reached in rows after FOUNDATION1's Workplace move and its keyed open (2026-10-26)

**Decision (TREEPOOL1, proposed 2026-10-26, round 1 under D191; rounds 2 and 3 the same day).** **Status: proposed; round 3 answers both
makers' reads of round 2, and both makers' reads of round 3 are owed before any of it is accepted.** The owner directed on 2026-10-25 that each
repository keep a pool of session trees: a session takes a free tree and holds it, locked, while it works; the tree is first brought to the
line, its untracked work cleared and its ignored dependency and build folders kept; the session works on a branch of its own; at its end the
tree goes back to the pool with the work on that branch, or with no branch where it was done with no output; the pool is a managed number of
slots, at most one per session the repository may run at once, each made lazily; and trees are removed only when that number is lowered or the
repository leaves, never by age. Today a tree is opened once for one line of work and never reused (D51 rule 2), its folder's name is its
branch's, its path is the line's identity to some forty readers, and its end is a move aside that KEEPSIZE1b deletes an hour after its record,
or fourteen days later otherwise; the price is the setup a fresh tree pays (`npm ci` 170 to 221 s, .NET's `bin/` and `obj/` built again) and the
bytes moved-aside trees hold (about 205 MB each). The survey (`docs/2026-10-26-tree-pool-survey.md`, read at `6b999d6b1`) and the brief
(`docs/2026-10-26-tree-pool-brief.md`) set nineteen questions; two sealed proposals answered them, Codex's and the independent Opus reader's;
round 1 of the design, `docs/2026-10-26-tree-pool-design.md`, was their synthesis by Claude Opus 5.5 from main at `f8fbb1bb7`; round 2, from
main at `f92e95415`, answers both makers' reads of round 1 (the design's §22); and round 3, from main at `3dd134cf3`, answers both makers' reads
of round 2 (§23). **Its central choice is neither proposal's**: both kept a slot at a stable path of its own and moved a line into it, and the
code shows such a path either reaches a shipped build as the line's own tree while it holds another line's work, or needs a second session
family in the service to hide it; so the slot moves to the line's path instead, and both makers' reads of rounds 1 and 2 keep that choice,
Codex's of round 2 on the condition that row b's numbers bear it out, which row d waits on. It changes decided rules other designs rest on and it
switches and removes trees, so by D191's note of 2026-10-24 no part of it is accepted on one maker's read, and its ⚖ rows are built only after
both makers' reads find nothing blocking in them. Nothing is built, and nothing is built before FOUNDATION1's row mod-x (D212 §14.6), which has
not landed, nor rows d and later before its row 1d-i, the keyed open, which is designed and not built.

**Why.** The disk and the setup are spent on making and discarding whole working copies, so a working copy is kept and handed on. What must
not be handed on is identity: twenty-odd readers take a folder for its branch and a path for a line, a shipped build goes on in a record's path
by whatever folder stands there, TREEFOLLOW1 learns whatever branch a line's folder shows, and Claude Code finds a conversation by its
directory. Keeping the slot at the line's path, parking it between lines and placing it only once it is switched, relinked and checked, keeps
every one of those facts true with no reader rewritten, no service family added and no resume traded for a brief, at the cost of two renames per
take under the repository's exclusive hold and of every build folder but npm's, which a slot never carries to another line: a carried output
can stand in for a line's sources and a path-bound one reads another tree, so a finished line's go aside with its record as they go today, and a
live line's keep its slot until the owner agrees otherwise; row b measures what is left of the saving before anything is switched on. A slot
is taken only when nothing in it is outside a ref and nothing of its line's but npm's dependencies is in it, and opens a record only when it
reads clean where it will run, so the first build resets nothing and removes nothing a decision does not already remove; keeping uncommitted
work aside, which Daoris committing off-branch would be, and setting a live line's build folders aside, which D195 does not allow unasked, are
the owner's to allow. KEEPSIZE1b's protocol and manifest, the set-aside's move, the slim's manifest, TREEGONE1's remake, TREEDEPS1's gate and
link maker and FOUNDATION1's keyed open are reused where they already prove what the pool needs, so the pool is a layer over today's trees
rather than a second lifecycle.
