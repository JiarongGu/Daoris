## D248 — The driver takes Lyntai's agent layer from Lyntai's local build, and main without that build is today's driver (2026-11-06)

**Decision (AGENTLYNTAI1a, on the owner's answer to the backlog plan's Q2, `docs/2026-11-06-backlog-plan-2.md` §3; accepted by the
owner, 2026-11-06, with the requests' publication).** The owner answered that the driver may use Lyntai's locally built library for now: Lyntai's own release process
makes its published versions work, and this repository does not develop through publishing (D240 point 8). Lyntai's released 3.5.3
carries no agent layer (its `Lyntai.Core` holds no `IAgentProvider`, `AgentProviderRegistry`, `AgentFailure` or `IAgentUsageSource`);
the layer is on Lyntai's main line, under *Unreleased*.

1. **One released-or-local mechanism for both trees.** The desktop's package props import the ignored `local/lyntai-local.props` the
   service's import, which `tools/lyntai-local.mjs` writes and the merge tool copies into its gate trees: it sets `DaorisLyntaiVersion`
   and adds the local feed, and without it each tree's released pin stands. Each tree keeps its own released pin, since no desktop
   process loads the service's graph (the agent-lyntai design §7.1). *Rejected:* the design's §7.3 build property naming a pack, read
   only when a build is invoked with it and refused by the gates: a second switch for one job (D228), where the owner's answer makes
   the local build this machine's ordinary build, gates included, as D22's LYNTAILOCAL1 note already has it for the service.
2. **The driver references the layer only where the local build is in use.** `DaorisLyntaiLayer` is true when the version in use is
   not the released pin, and the driver's references to `Lyntai.Core` and `Lyntai.Providers.Basic` hold under it alone. From 1b-i,
   `Agents/Layer/` and its tests compile under the same condition, and nothing outside them names the layer (`LayerCensusTests`). So a
   build without the props (the CI, a clean clone) is today's driver: no Lyntai assembly, the same package graph, every door
   Daoris-run. *Rejected:* referencing released 3.5.3 unconditionally, which ships a library the driver cannot use and measures a
   closure that is not the layer's; keeping the rows on one long branch until a release (Q2's other option), since the owner lands and
   accepts each move; a pack committed here or made by the CI from a named Lyntai commit, since nothing of Lyntai is kept in this
   repository (§7.4) and every machine would have to pack it; and a shared prerelease feed, which Lyntai publishes none of (its D235).
3. **No release is asked of Lyntai.** The design's LQ1 is withdrawn; the requests that remain travel as one quest
   (`docs/2026-11-06-lyntai-requests.md`). *Rejected:* waiting on a release for rows 1a, 1b-i and 1b-ii (R-a), which the owner's
   answer replaces.
4. **The census is a class of its own, by place.** `LayerCensusTests` reads the three shipped projects by name, as the provider census
   does: `Lyntai` in code only under `Agents/Layer/` and the providers' folders, a vendor's registration and options only in its folder,
   the generic protocol registration only in those places, no layer-own id, and no `global using` of Lyntai anywhere. A file cannot
   name a layer type without spelling `Lyntai` once global usings are refused, so the token holds every name. *Rejected:* a token in
   `provider-census.json` (the design's §6.1), whose exceptions are per file and would need a row for every file of the layer's folder.

**Ends** when a Lyntai release carries the layer: the desktop's pin moves to it, `DaorisLyntaiLayer` and its conditions are deleted in
that change, and the local build is optional again. **Re-opens** at the first move that deletes a Daoris-run path (1d, the design's
§2.3 rule 4) while no release carries the layer, since a build without the props would then lack that door.

**Amends** D22 (its released-only consequence, for the driver's layer, on its LYNTAILOCAL1 note's terms) and the agent-lyntai design's
§7.2 and §7.3 (a row dispatched only on a release; no merged branch, dispatched row or gate building on a pack) and §9.2 (1a waiting on
LQ1's release).
