## D194 — A `daoris` management verb is run by the driver's own program: `daoris driver|agent|plugin|tool …` hands its words to `daoris-driver`, which is the running Daoris's client or acts alone under the home's lease, each change one typed operation in the driver library and one text per verb; the families' TypeScript retires (2026-10-21)

**Decision (PUSH1f2, proposed).** **Status: proposed**, for D191's reads; revised the same day by Codex's read, whose twenty findings
all held and were taken (design §8). The author first judged it changed no foundation. After the read it touches two of D191's
amendment's classes narrowly, concurrency (the long verbs' publication under the lease) and a protocol between processes (the CLI's
hand-off to the host), while no record's data model, wire's shape, lease rule or route answer changes; whether Fable reads it is the
steward's to decide. It answers D182 point 6's alone half and D171's PUSH1f note's *Left*. Read at `49aa46e47`, the read's findings
checked at `ff01a5881`: with no instance, each of the four families still writes with its own TypeScript editor (`service.ts:526-545`,
`door.ts:170-185`), about 18,950 lines with 887 shared and about 16,200 of tests, while every rule they apply has its driver twin and
the route bodies are thin wrappers over it. The contract is `docs/2026-10-21-alone-path-design.md`.

1. **The CLI hands the family to the driver's program.** `daoris driver|agent|plugin|tool …` runs `daoris-driver` with the same
   family and words; its output and exit are the run's. The program is the one `DAORIS_DRIVER_PROGRAM` names (the dev loop's and a
   rehearsal's build), else the one in this package's install at `app/daoris-driver/`; else the verb is refused, exit 2, saying where
   the program is, and nothing is done. Never `PATH`, a checkout's build found by itself, a `.cmd` or `.bat`, or a TypeScript fallback.
   The two are one build, an install's `app/` or a checkout's: a host lacking a family, a sub-verb or a flag says its usage, exit 2.
   It starts through the CLI's one spawn site with the terminal's streams and its environment exactly, not the tools' `PATH`, which
   would change the npm the host's `agent install` finds. A status outside 0, 1 and 2, or an end by a signal, is 2. Ctrl+C leaves the
   CLI waiting for the host, whose family commands each handle it. The doctrine commands reach no spawn and stay offline. A machine
   with the CLI alone, and a checkout naming no program, lose the four families. Design §1.1.
2. **The program is the verb.** Each family is a command in the driver library, as `access` is, routed by the host: its grammar, its
   usage, its switch through `InstanceDoor.PressAsync` (the running Daoris's client, else alone), and its words. A change holds the
   lease from the top and a read none. `DAORIS_DRIVER_CONFIG` names a home the driver family acts on alone; `DAORIS_HARNESS_CONFIG`
   names one for the agents' wiring, accounts, keys and versions, but the rules and their proposals are `DAORIS_HOME`'s and keep its
   door. Design §1.2.
3. **A long verb publishes under the lease.** A download, an agent's own installer or sign-in, and a key read from the person hold
   nothing while they wait; what they make is staged where no reader takes it (a download's `.part`, a sign-in's new account folder,
   made first as the window makes it); its end is published under `HomeLease.ForVerb`, which beside a desktop that started meanwhile
   holds nothing and writes each file under its keep lock, as any route-less change beside an instance does. Design §1.4.
4. **Each change is one typed operation in the driver library**, called by its route and by the command alone: typed input, the facts
   it judges by, a refusal or a write, and the press's own fields. The route keeps its payload's reading, a live process's coordination
   (a plugin stopped before its folder moves), its publication and its answer, `STATE` unchanged and unsplit; the command keeps its
   grammar, its reads and its words, and writes the route's payload from its input, held by a round trip through the route's reading.
   An operation's coded refusal maps to its code through one library table both read. The host does not reference the modules.
   Design §1.3.
5. **A person's press alone acts on the terminal's word**: the lease keeps one writer and is no confirmation, and with nothing running
   the terminal is the person's door (D50). With the window running a route's press is confirmed there; the route-less verbs D171's
   PUSH1f note lists act on the terminal's word as before, retained under D156 point 7. From an environment carrying `DAORIS_SESSION_ID`
   a person's press no instance's confirmation covers is refused, exit 1: advice, whose absence grants nothing (D156 point 4, and its
   rejected positive identity for agents). A gate acting as the person clears the marker and checks the refusal apart. Design §2.
6. **One text per verb**: one words function reading what the command read and the press's own fields, from the route's answer or the
   operation's result; a refusal one line, `{verb}: {sentence} ({code})`. Exits stay today's on both paths: the command's own checks as
   each is today, an operation's or a route's refusal 2, the person's refusal and expiry 1. Held by a modules test running each verb
   both ways over one home, and a table of the CLI's cases run once through the TypeScript verb before it retires. Design §3.
7. **The families' TypeScript retires row by row**, each module in the row that frees its last reader, found by a search recorded in
   the row; its twins row loses the CLI's column then, and a table another twin still reads stays and moves to the driver's fixtures.
   The home's table stays in the CLI, which other verbs read. Two tools that import the agents' resolution ask the host's `agent which`
   first. Design §4.
8. **The rows**: PUSH1f2a, the seam proved by the driver's standing choices; 2b, the driver's workflows and cycles; 2c, the tools; 2d,
   the agents' rules, trust and settings; 2e, the agents' tools and accounts; 2f, the plugins and the last census. Until a family's last
   row the CLI forwards an allow-list of its sub-verbs. Design §5.

**Why.** The judgement was already .NET's; what the TypeScript held besides was each verb's grammar and words, and with them a second
reader of every file, a second pipe client and a second lease, each held to the driver by a table. Making the driver's program the
verb leaves one of each and keeps the words a person types. Moving only the operation, not the route, gives the alone path the same
implementation with every bridge parser, coordination and answer where it is.

**Rejected** (design §6): a TypeScript fallback where the program is missing; the CLI keeping its grammar, reads and words and asking a
host verb for each write; each route's whole body moved into the library with `STATE` split into a `ChoicesAnswer` (the first reading);
the host referencing the modules; a failure category so that domain refusals exit 1 (the first reading); the local service as the alone
path; finding the program on `PATH`, in a checkout's build or by the home's install; a `.cmd` launcher or override; handing the program
the tools' `PATH`; a lease held for a sign-in's or a download's whole run, and a sign-in staged and moved; a named harness file sending
the whole agent family alone; a person's press alone only with the person key; the marker's absence read as the person; folding
`daoris plugin` into the host's `plugins`.

**Amends,** once accepted: D50's as-built note (the management class spawns the driver's program through its one site, with the
terminal's environment, and reaches the network for the service's verbs alone once the agents' and tools' downloads are the host's);
D171's PUSH1f note (the CLI's pipe client, lease and door leave with the families, the host's `InstanceDoor` the one client; its
named-file bullet narrowed to what each file names; its list of verbs that act alone kept); the terminal RPC design §9 (the client sits
in the driver's program, not `service.ts`). D182 point 6 stands and is what this builds; its PUSH1a note's *Left* moves nothing, and its
PUSH1e note's home-table twin stays. While proposed, D50, D171 and D182 carry a note pointing here.

**Held by:** the rows' proofs (design §5), each family's both-ways modules test and text table, the seam's tests, and the family
rehearsal's `daoris` phases, run as a test person.
