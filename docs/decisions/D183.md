## D183 — Ask Daoris runs in an access mode the person chooses: restricted, with access the person configures, or full; and it shows what it was handed (2026-10-19)

**Decision (the owner's direction).** The owner, 2026-10-19, after Ask Daoris answered a request to clean up a tree
Daoris had made with *"I can't change anything on this machine myself … Removing a folder stays your press"* and a list
of commands to run by hand: *"same issue again, I think you're making Ask Daoris too restricted, we'd better take the
approach like Codex does, into modes (restricted + config access, so we need a UI design for this mode, or full access),
and also we do need to show what's been wired for Ask Daoris, because this is blocking me for development."* Earlier the
same day it had lost the browser (HELPPLUG1c), whose approval was not on the page at all. D89 made Ask Daoris a session
that reads and proposes, run in its harness's asking mode so that nothing off its allow-list could act (HELP1a), and every
reach since (checkouts, plugins, the browser) has been one more grant to wire and approve.

1. **Two modes, the person's choice, like Codex's approvals.**
   - **Restricted** is what Ask Daoris is today (D89): it reads, and it proposes changes the person applies with a press.
     On top of that, the person grants **configured access**: named capabilities, each one listed with what it lets the
     agent do and where (HELPMODE1c designs them and their screen).
   - **Full access** runs Ask Daoris in its harness's own unrestricted mode: shell, file edits, Daoris's commands, and
     every plugin server the machine has, with no per-call asking. Mapped per harness: Claude's permission mode that
     skips asking, and Codex's full-access sandbox with no approvals. What the agent does there is its own act, not a
     proposal, so no card stands between it and the change.
2. **Chosen where the person sees it.** The mode is set under Settings → *Daoris's own AI* → Ask Daoris and switched from
   the panel's own chip, as Codex's mode is. It is machine-wide for now (D158's ASKSCOPE1 note, point 7). A switch takes
   effect at the next start, or at once where the harness can change mode mid-conversation. Restricted stays the
   default; full access is never chosen for the person.
3. **Never silent.** The mode a conversation ran under is kept on its record and shown on its panel, in its history row,
   and in the room's first lines, so the agent knows it too. Full access wears a plain warning chip. A conversation
   resumed after the mode changed runs under the new mode and says the change.
4. **What it was handed is shown.** The panel shows what this conversation was wired with: its mode, its agent and
   account, its working folder, Daoris's tools, the plugin servers and whether each is approved, its permission rules,
   and the checkouts it may read. In restricted mode it also shows what it lacks, each with the door that grants it.
   This is read from what the start actually handed, recorded at the start, never derived again.
5. **The doctrine still speaks.** In full access the room still tells the agent that a repository's work is asked for
   through a quest, and that the machine's own housekeeping (Daoris's trees, its home) is its to do. These are words,
   not a gate; the mode is the gate.

**Rejected.**
- **More grants one at a time** (the path since D89: checkouts, plugins, the browser, each its own wiring and approval):
  every gap blocks the person until a row closes it.
- **Full access as the default**, or switched on by anything but the person's press.
- **A mode per workspace now**: settings stay machine-wide until the owner asks (D158's ASKSCOPE1 note, point 7).
- **A wired list worked out again from configuration**: it could disagree with what the agent was actually given.

**Amends D89** (Ask Daoris proposes, and every change is a press: now in restricted mode only; and HELP1a's asking mode,
now restricted mode's), **D107** (no shell: restricted mode only), **D170** (plugins handed to Ask Daoris: every
installed server in full access, approvals in restricted). **Held by:** HELPMODE1a (the mode in the driver and the
record), HELPWIRED1 (what was handed, recorded and answered), HELPMODE1b (the panel's chip, Settings and the wired list on
the page), HELPMODE1c (restricted mode's configured access and its screen, designed first).
