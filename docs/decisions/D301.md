## D301 — An update waits on a run's plugin step in flight: a plugin's attempt recorded, sent or unknown on a run that goes on (2026-11-16)

**Decision (UPDATEINFLIGHT1, STAGENOTNOW1).** Idle, for an install's update, is also no run's plugin step in flight
(`PluginStepsInFlight`, area `install-home-update.md`, rule 39). In flight is an attempt whose step is a plugin's
(`<plugin>/<node>`) in the state `recorded`, `sent` or `unknown`, on a record whose run has not ended, read from the run records
as the runtime keeps them; the updater asks it at each look and never reads the records itself. A publish's `--stage --not-now`
writes the person's *not now* for the build before the build is visible, one act.

**Why.** On 2026-11-16 a staged build installed 22.6 s after staging while a run's release step ran beside it: the drain counted
only driven sessions and turns, so the swap cut the release's call off and its outcome was not known until the restart asked after
it; and a `--stage` followed by `update --cancel` raced the idle install.

**Rejected:** counting a `held` attempt (it waits on the person's word, not its plugin, and would hold the install until they gave it);
counting Daoris's own kinds (a check, a close, a request), which a restart asks after or sends again itself; counting an ended run's
attempt or a record that does not read (nothing moves either, so the drain would wait for good); a deadline past which a sent attempt
stops counting (the plugin may still be performing it; *Update now* is the person's way past a step that never settles); a stage then a
cancel for *not now* (the race itself).

**Left:** a plugin step a pass sends after the apply's second read of the work, just before the close, still meets it; the runtime's
starts during a drain are not changed here.
