## D227 — A place follows a saved graph workflow: Set up… and a fresh place choose a shipped one, new steps workflows are refused, the old records convert only on the person's press, and the place page is lit after its installed sitting (2026-11-02)

**Decision (WORKFLOWCLEAN1, the owner's choices of 2026-11-02 on the steward's inventory, `docs/2026-11-02-workflow-cleanup-inventory.md`).**
1. **A place follows a saved graph workflow by default.** *Set up…* and a fresh repository or workspace choose one of the shipped
   graph workflows as the place's saved workflow, instead of following *Current* drawn from `driver.json`'s landing rule; the
   landing rule stops being where a place's workflow lives. This amends the fabric plan's DEFAULTCONFIG1a and D221's *Set up…*.
2. **New steps (schema-1) workflows are refused.** The step presets, `workflow edit`, `workflow apply <steps>` and Ask Daoris's
   steps door retire; a graph is the only way to save a workflow. A run already bound to a steps version keeps D157's engine to its
   end, as D190 point 1 says.
3. **The old records convert on the person's press.** Daoris offers one reviewed plan that saves each steps workflow, each graph
   version holding the old `handed` step, each `land` saved with `accept`, and each place's rule-drawn *Current* as a graph version;
   nothing changes until the person applies it in the window. This amends D190 point 1's *never by a migration* and the land node
   design's *nothing is migrated* to *never without the person's press*.
4. **The place page is lit after its installed sitting.** SETUPUX1x runs on the owner's install after the next update; what it
   finds is fixed; then `daoris.agents.setup` is on by default and the old Workflow and Setup tabs, the old Roles mode and the
   legacy opener are removed in one wave (SETUPUX1y).

**Why.** The owner found the old workflow logic still showing and asked for it updated and cleaned up, the default setup
included. The inventory found the shipped window on the old surfaces, *Set up…* writing a landing rule and *Current*, steps
workflows still creatable and bound by new starts, and no conversion of any old record.

**Rejected.** Keeping *Current* as the default; lighting the page before its sitting; keeping steps workflows creatable beside
graphs; an automatic migration, and leaving old records unconverted.
