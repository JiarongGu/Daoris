## D230 — A repository owns its context and reconciles with the canon through its own session's model; Daoris manages only the sessions it runs, each scoped to the session (2026-11-03)

**Decision (CONTEXTONE1, the owner's direction and answers of 2026-11-03; designed under D191; round 2, proposed for its reads).** It
follows `docs/2026-11-03-context-one-design.md`, with no second route (D228).

1. **The repository owns its context.** Its rules, skills, knowledge and setup are versioned files that work without Daoris, for any
   developer and any agent. *Doctrine works without a service* stands, and so do D13 and D19: drift is the disk against the lock.
2. **A canon update can be seen, and the canon is reconciled, not imposed.**
   - `daoris status` reports what a sync would update or add, whatever the stamps say.
   - The lock's canon digest orders the canons, and a newer lock is never rolled back.
   - A reconcile is a case of the set-up press. Its brief is composed offline by `daoris reconcile` and worked by a model in the
     repository's own session.
   - That session adopts each item, keeps it (recorded with its reason and the canon digest in `daoris.json`), or proposes it
     upstream (a quest's words to the canon's repository). It commits in its own line.
3. **Daoris manages only the sessions it runs, each scoped to the session.**
   - The driver composes one standing block, handed at the start and at a move, never on a resume. It replaces exactly the routing
     line, the standing answer's preface and the instruction's "where things are" pieces.
   - The whole first prompt is bounded by the native door's single argument.
   - The tools are loaded at the start.
   - The tree's skills and the per-session plugin copy are the skills. Auto-memory is off for the session.
   - No account home, vendor set or person's tool home is written.
4. **The standing answer stays the person's machine choices.** Its lines that state a repository's own rule move into that repository
   through its reconcile (amending D135 §3 for those lines only).
5. **Older shapes are converted by ONEWAY1's rows,** not here.

**Rejected:**
- doctrine served by Daoris alone;
- a sync that overwrites a repository's differences;
- a reconcile beside the set-up press;
- a C# copy of D19's table;
- writing into account homes;
- a block handed again on every resume.

*2026-11-04, CONTEXTONE1b built: the reconcile, the keep and `upstream`'s request.*
- **The keep.** `daoris.json`'s `kept` maps a canonical file's target to `{ "reason", "canon" }`, the canon digest being
  that one file's as `canonDigest` hashes each (`keep.ts`'s `canonFileDigest`); one without a reason or a 64-hex digest is
  refused at the manifest. `sync` and `--force` pass over a kept file and carry its lock entry as it was, so the disk
  against the lock stays what the repository changed; a kept rule's span keeps its text when the region is rebuilt.
  `check` names each keep and never calls it drift; `status` names it apart from an update, with `reopened` once the
  canon's file moves, and lists a keep the canon no longer ships under `keepsDropped`. D19's kept rows, D4 and D71 are
  amended in their files: a core file kept absent is refused, a dropped keep leaves D19's retirement rows to apply, and a
  kept file waits out a move.
- **`daoris reconcile`**, a doctrine command at the root (`cli/reconcile.ts`; `fixtures/command-tree.json` is not in the
  tree yet, so the CLI's table and usage golden carry it). Offline and writing nothing, it prints a brief in the canon's
  words of only the differences: what `planChanges` says a sync would change, add or retire; the copies edited here; a keep
  reopened, held absent for a core file, or dropped; and the set-up gaps `check` reports (the root instruction file over
  32,768 bytes, the budget over, a room or a declared document absent, an own document no index lists, an own skill one
  agent alone reads). Each item has the canon text's path and the keep line with its digest; the brief says the direction
  (behind, or equal versions over another canon, where only the text can say which is newer), the three decisions, and
  the checks kept green. A newer lock is refused as `sync` refuses it; a repository never synced is refused.
- **`upstream`.** Only where the canon it reads sits inside the repository (`insideCanon`) does it write; elsewhere it
  prints a request's words for the repository that keeps the shared doctrine, carrying each file's text whole, and writes
  nothing. The region's preamble and `canon-authoring.md` name the route (neither text lives in `canon/`: the preamble is
  `tierrender.ts`'s, and `canon-authoring.md` is this repository's own); this repository and both examples are synced.
- **The press's case.** `SetupCase.Reconcile`, `SetupQuests.Reconcile` (so one is open per repository, beside any
  set-up), `SetupPress.PlanReconcileAsync` and `ReconcileBrief`. Its rule is `SetupPressRules.ReconcileVerbs`, the
  set-up's verbs with `daoris reconcile` and `daoris upstream --all`. The quest carries each line of the standing answer
  for the session to judge (D135's note). The desktop program has no hand-off that reads the CLI's `status --json`, so the
  case is offered for a repository the registry marks adopted, refused with `not-adopted` otherwise, and its body says one
  that finds nothing closes done.
- **Proof.** `keep.test.ts`, `reconcile.test.ts` and `upstream-request.test.ts` in the CLI, the usage golden;
  `SetupBriefTests` and `SetupPressTests` in the driver. Not built: a door that presses the reconcile (the place's adoption,
  the page), and the install run of one adopter reconciled on the owner's yes.
