## D187 — A builder takes one feature end to end, across the lanes it needs, and hands it back working (2026-10-20)

**Decision (the owner's direction).** The owner, 2026-10-20, asked how development could go faster with so many open rows.
More workers, cloud agents, publishing on each batch and a triage of the backlog were each judged not to be it. The owner
decided that a builder takes one feature as one block and builds it end to end, so the round trips between slices are cut.

The evidence: 162 rows were finished on 2026-10-19 and 2026-10-20, about 72,000 lines with their tests, while the backlog stayed
at 421 open rows. A feature was split by lane into slices of about a hundred turns (the dispatch skill's step 3, D160's cost
evidence), each with its own scout, brief, decision note, README edit, archive entry and merge, and each hand-back proposed
further rows: on 2026-10-20 alone PUSH1c4c, HEAVYRUN1a3, AUTONOMY1b3e, BEFORESTEP1 and PLUGSET1 came from hand-backs. The
person saw a slice only once every slice of its feature had landed (PUSH1c3a, b and c; PUSH1c4a, b and c; HELPMODE1c1, c2a and
c2b), and the Process-trait tests a slice touched ran only in the CI after it merged, so their failures came back as further
rounds.

1. **The unit of work is a feature a person can see working**, named by its outcome (*Codex sign-in works on the install*,
   *Settings uses the pane*), not by a layer. One builder takes it across every lane it needs, driver to page, in one branch,
   and hands it back when the feature works.
2. **One record per feature:** one decision note where something is decided, one archive entry, one merge. Its rows in the
   backlog become one block row when it is dispatched.
3. **No new rows from a hand-back.** A follow-up the work reveals is done in the same branch when the feature needs it, and
   dropped when it does not. A row is filed only from the owner, or for something a person would see broken outside the
   feature.
4. **The builder runs its feature's own real-process tests,** the `Process`-trait classes it adds or changes, filtered to
   those classes, once before it hands back, so a failure there costs no further round. The whole `Process` halves, the
   rehearsals, the window and the publish stay the parent's.
5. **Split only by sub-feature.** A feature too large for one builder's context is split into parts that each work on their
   own and are each seen working, never into a host half and a page half.

**What it changes.** The dispatch skill's step 3 (size by turns, split by lane), the branch-worker's *stay in your lane*, *stop
at the row's proof* and its gate on `Process` classes. Files a branch in flight holds stay out of another's brief, as before.

**Rejected.** Raising the worker count: five already load this machine, where a program start costs 170-470 ms (DEVDRIVE1),
and more made real-process tests flake and froze the owner's window (2026-10-15). Cloud agents for some rows: the owner judged
them no faster, and they need main pushed. Publishing after each batch and a backlog triage: neither shortens a feature's
round trips.

**The cost accepted.** A longer branch costs more per turn, since every turn re-reads its context (D160's square of turns).
That is accepted against the rounds a split costs: a scout, a brief, a merge, the records and a CI pass per slice, and the
owner's wait for the last slice.
