## D275 — A long session record is read through an index in the desktop store, and the file stays the record (2026-11-14)

**Decision (STARTPERF1).** The session records and the quests were already rows of the service's store; what was read whole from files
was the session events. A record over 512 KB has a head in the desktop's store (`session_event_heads`) and every 256th event's byte
offset (`session_event_offsets`), kept by the reader that finds none, or finds the file longer than the head reached, and built again
where the file's last line read no longer stands. The newest page, the page before a number, the events after one, the plan, the
choices and the turns ended read the head and a part of the file. The file stays the record: append-only JSONL, machine-local (D76),
read as it is by a person or a tool. Without the store, or under 512 KB, a read is the whole file.

**Rejected.** *The events as rows*: 517 MB of text in a store of 3 MB, every line written twice or the file given up, and a second way to
read a conversation for the terminal's tail and the person. *The service's store*: the events are this machine's (D76) and the service's
store is what a shared host exchanges. *A head written by the append*: a second writer under the append's lock for what the next reader
brings up by reading the lines since; a crash between the line and the row costs nothing. *Heads in memory alone*: a window's first
open of a session is the read that costs, and a process comes up with none. *Every record headed*: a row's read (about 3 ms) costs
more than the whole parse of a record under about 150 KB.

The quests' change mark (`GET /api/quests/changes`, `QuestListKept`) was built before this and stands as the design's section 3 says.
