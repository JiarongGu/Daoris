## D310 — Ask Daoris is a package on its own ports, developed as the workspace kind `assistant`, and one lock pins every package (2026-11-18)

**Decision (ASSISTPKG1).** The assistant (room, conversation setup, focus and access, second check, capabilities) is to be
`Daoris.Assistant` under `src/Daoris.Assistant/`, on the BCL and `Daoris.Ports` alone. It reaches the rest through nine ports of its
own, which `Daoris.Assistant.Desktop` and the modules implement; the driver names none of it and offers a conversation kind and parts
read from the root's assemblies. Its development is the kind `assistant`, mapped to `tools/workflows/daoris-assistant.json`. Helpers
and partners stay co-working's (`docs/2026-11-17-assistant-package-plan.md`).

Its first two steps are the machinery every later package takes unchanged (`docs/2026-11-17-component-census.md` §4, step 1):

- **The boundary is a lane, counted.** Lane `assistant` holds its files where they lie today, carved out of the driver's, the modules'
  and the web shell's lanes, and the lane table sends each to what its tree's lane reached. The layers census counts the references
  across any lane its list names, both ways per type, a ratchet that only falls as the code moves behind the ports.
- **One lock for every fingerprinted package.** A package is a folder holding `daoris.package.json` under a package root; its suite and
  evaluations run only when its fingerprint moves in `daoris.packages.lock`, which the gate `packages-lock` reads in milliseconds. The
  adapters' lock, tool, manifests and gate became these in one change, their rows carried byte for byte and read as the adapters' tool
  took them (the folder with its manifest under the old name) until each package's next release; a tree still holding
  `daoris.adapters.lock` is refused, naming the merge of main, until `packages.ts carriers` lists no ref that holds it.

**Rejected:** a folder in the driver (no build or test boundary); a service process (D286); its own repository (D300); a second lock
beside the adapters' (two ways for one job); re-releasing the six adapters to move their rows (it reruns suites that passed on the
same sources, and a row would no longer say when its suite last ran); the page as a web package now (32 `work/` imports); helpers and
partners inside (a driven line's port).

**Note, 2026-11-18 (the carved lane's rooms).** A lane carved across build units whose rooms differ lists those rooms as its `room`
(`"room": ["driver", "modules", "web"]` for `assistant`), since its files still compile in their units until the package's steps move
them. The room check places each of its files in the room of the deepest unit holding it among those it lists, refuses one in no unit
of theirs, and joins the rooms it lists into one claim group, since one session works the lane in place in all of them. A list names
two or more rooms once each, and carries no `builds`: a build is one room's. The list gives way to the lane's own room when its
package's unit holds its files. Rejected: the check placing the files of a lane in no room by the unit that holds them (a lane given no
room by mistake would pass unnoticed, and "in no room" would stop meaning what it says); one room for the driver, the modules and the
web (it hides the references the check lists between them, for a lane that lasts a few steps).
