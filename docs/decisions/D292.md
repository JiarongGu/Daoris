## D292 — Sessions share the person's one browser context by default, each through tabs of its own; isolation is a setting per agent, never the default (2026-11-13)

**Decision (BROWSERSHARE1, 2026-11-13, supersedes the plugin's `--isolated` choice under D277).** The in-app browser plugin ran Playwright
MCP `--isolated`, so every session, Ask Daoris included, drove a new in-memory context, and a script copied the person's cookies into
it on each new tab. Local storage, session storage and IndexedDB never came across: on the installed app a site that keeps its
sign-in in local storage opened empty in a session's context (no keys against fifteen in the person's, two contexts listed by the
browser). The owner's direction: isolation is managed; agents may use different profiles where that is set up, and otherwise all use
the one.

1. **The person's context is the default.** Every session drives the browser's own first context, so cookies, local storage,
   IndexedDB and the rest are the person's, shared both ways, exactly as the person's own tabs see them.
2. **Tabs stay the session's own.** Without `--isolated`, Playwright MCP adopts every page the context lists, makes the first its
   current tab (a session would navigate the person's tab) and adopts every page another session opens. The plugin's server is
   therefore a script of the plugin (`browser-server.mjs`) that starts the package's programmatic `createConnection`, handing it
   a scoped view of the context: `pages()` and the `page` event show only pages the session opened through the view and popups
   whose opener is one of them, and closing the view closes only those. The person's context is never closed. The view makes
   its tab itself with `Target.createTarget` on the browser's socket and takes the page announced for that target id:
   Playwright's `newPage` reads the page back the instant the host answers, and a host whose relay announces the tab later
   leaves it nothing to read. Daoris's own browser announces each new default-context tab as an `other` target and turns it into
   a `page` some tens of milliseconds later, and Playwright, which fixes a target's kind when it is announced, drops `other`. So
   the server connects Playwright through a loopback relay (`relay.mjs`, `hold-others.mjs`) that holds an `other` announcement
   for up to 500 ms and announces it as a page when the browser says it became one; a target that stays `other` passes as it was.
   Popups take the same path. Rejected: Playwright's `PW_CHROMIUM_ATTACH_TO_OTHER`, which would attach and instrument the
   browser's own toolbar targets, and a new connection per tab, which attaches every one of the person's pages again.
3. **Isolation is a setting.** `isolation.json` in the plugin's data folder lists the agents that get a context of their own
   (`{"isolated": ["codex", "role:reviewer", "*"]}`); a word is an MCP client name's start, `role:<role>` the role the session
   took, `*` every agent. Nothing set, or a file that cannot be read, means shared. The server learns the agent from the MCP
   `initialize`'s client name and the session role in its environment; Daoris hands a plugin server nothing more of its session.
4. **Isolation is not a sign-out.** An isolated context starts with the person's cookies and the local storage of each origin the
   person has a page open on, and gives nothing back. Session storage and IndexedDB are not copied: neither can be read out of a
   page without running page code per store, and an origin the person has no page on is unknown.

**Rejected.** Keeping `--isolated` and widening the copy to local storage: a snapshot taken per tab, one way, of only the
origins open, still a second profile by default and wrong for any site whose state is in IndexedDB. A shared context through
Playwright MCP's own flags: it has no way to hide the person's tabs from a session. Patching the package: pinned and not ours.
**Left.** A named persistent profile per agent (a context that keeps its own sign-ins across sessions) is a later row
(BROWSERSHARE1 in `TASKS.md`), as is a page in Settings for the isolation list.
