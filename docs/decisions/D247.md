## D247 — Each node kind is one unit, registered once, and the shared runtime reads the registrations (2026-11-06)

**Decision (NODEKIT1; accepted by the owner, 2026-11-06).** The workflow is one flowchart of nodes, and the code's units are
its nodes: every kind of process and monitoring work is one folder, and nothing else declares it. The design is
`docs/2026-11-06-node-kit-design.md`.

1. **A kind is a folder** under `Workflows/Kinds/<Kind>/`: its declaration (`<Kind>Node.cs`, marked `[NodeKind(id, group,
   after…)]`, holding its contract row, the subject a run binds it to, its options, its own save rules, its part on the run view, its
   offer, its terminal title and how the chart draws it), its state logic (observed, started on a door, the person's acts), its door
   or executor, and its tests in the same folder of the test project. A record other areas read stays in its area.
2. **The registration is the parts kit's.** `NodeKindAttribute` is a `PartAttribute`; its phases are the editor's groups and its
   `After` their order, so `docs/index/registered.md` lists the kinds as the palette offers them. `NodeKit` is built once from the
   assembly with no runtime, so the save and the palette read it as the runtime does.
3. **The shared runtime reads the registrations, and the tables go.** The contract table, the option table, the run subjects, the
   observation and start switches, the door properties and their start loops, the person's acts by kind, the palette's arms, the run
   view's map and the terminal's titles each become a read of the kind's unit, deleted in the chunk that moves their last row. What
   stays shared is what is no kind's: the one lifecycle, the wire evaluation with its groups, the `all` join and the `stop` sink, the
   graph's generic rules, the run's keeping and the attempt journal.
4. **A plugin's step meets the same registration.** `NodeKit.Of` returns the one `PluginStep` adapter over a step's declaration,
   and Daoris's half of a step name (`*/pull-request`) registers as a kind does. The runtime has no plugin branch of its own.
5. **The ids stay `NodeKinds`' constants**, the words the saved files, the page and the terminal use; a test holds them and the
   units equal both ways.
6. **The page's kinds are generated** from the declarations by `tools/contracts`, and the catalogues name each kind by its id; the
   names check requires each kind's words in every language.
7. **D245's note is built in the kit first.** A `monitor` watches the one step wired straight into it, through that step's own
   state reading, and its outcomes are that step's states, written in the file (`merged` and `closed` for a pull request). The
   prebuilt set wires `when merged` to `tidy` and `when closed` to a `stop`, which a `when` path reaches as a failure's does; the
   `tidy` starts only on `when merged` and fails on nothing.

**Rejected.**
- **One class per kind with no folder.** Its door, its tests and its words would stay where they are, and a kind would still be
  read in many places.
- **Keeping the tables and adding attributes beside them.** Every row declared twice, which D228 forbids.
- **The id only in its unit, `NodeKinds` deleted.** About 120 files renamed for no behaviour, and the ids are a vocabulary other
  code and the files compare.
- **The page reading the kinds from the palette answer at runtime**, or restating them as it does today. The chart and the run view
  draw with no palette in hand, and a restated list is the 7 web files every kind edits now.
- **A monitor's outcomes derived when a version is read.** The file would no longer describe the graph the chart draws, and the
  digest would move under bound runs.
- **A person's task on the shipped `closed` route.** The `stop` is built end to end and a `human` node's doors are not; the editor
  offers the task.
- **One performing shape for every performed node, now.** Doors that write a record and ports with an attempt journal both stay,
  dispatched one way; making every performed node an attempt is a choice of its own.

**Note (NODEKIT1 2c): the protected order is the kit's one shared rule.** The order before the landing reads the opinion, the look
and the review together, so it is one rule the kit runs once per save beside each kind's own (`ProtectedOrder`, through
`NodeKit.Problems`), and a gate declares its part by `INodeKind.Guard`. Rejected: the rule on each gate's own `Problems`, since every
gate would judge the whole order again and say one fault more than once; and the rule left in `NodeGraphs` naming the three kinds, a
list of kinds kept beside the kit.

**Note (NODEKIT1 2d): the performer asks the unit for the port.** A kind started on a port through the attempt journal says so on its
unit (`IJournalled`, which `check` is), with the perform it gives its nodes; the performer sends its attempts to the door `NodeDoors`
holds for that kind, and takes an attempt as a port's where its sender names such a kind, wired or not. Rejected: the performer holding
one check port, set from the first `ICheckPort` door, with `check` named in its start and its attempts; and an attempt counted a port's
only where a port is wired now, which would send a check recorded by a loop with an executor to a plugin's process named `check` in a
loop without one. The close's own records move with it (`ClosureGraphs`, `QuestReads`); `GraphEnds`, which the modules read, stays.

**Amends:** D245 point 2 and its note (the monitor's reach is an outcome of its watched step's state; the tidy no longer fails on a
closed request); D231 (a kind's new behaviour goes in its own folder).
