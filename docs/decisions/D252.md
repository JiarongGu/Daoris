## D252 — A question asked while git rewrites the packs is git's (2026-11-09)

**Decision.** `gc` after `repack -a` builds the pack it already has, under the same name, and Windows refuses a rename over a file the
library has mapped however libgit2 shares it. Git retries for well under a second; a library call stretched past that by a loaded machine
(measured: `gc --prune=now` exited 128, "renaming pack ... failed: Permission denied", in one pairing run of ten under load) fails the
person's git. The admission now refuses every question to git while git's own files say it is rewriting the packs, the multi-pack index or
the commit graph (`GitLibraryHousekeeping`, reason `housekeeping`), so a call that starts then never maps them; only a call already open
when git began can hold, and it ends within git's rewrite. The hold test counts no reads over a loaded minute, which is the machine's, and
holds that reads ran beside each command.
*Rejected:* a shorter or retried bound in the test, which would hide the refusal git's user meets; setting libgit2's Windows share mode, which
shares delete but does not let a mapped file be replaced; leaving the library on the file and asking git for a longer retry, which git's
delays do not offer.

**Proof:** `GitLibraryHousekeepingTests`, and ten runs of the hold test beside `StructureTests` under a CPU burn.
