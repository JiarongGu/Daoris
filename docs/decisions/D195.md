## D195 — Each kind of thing Daoris writes is kept by one rule, set per kind in the driver's standing choices and shown on This Daoris with its size, its next and its last clean; a tree set aside drops its package folders once it has settled; the look, a free-space floor and the person's press run the rules (2026-10-21)

**Decision (CLEANUP1, accepted 2026-10-21).** **Status: accepted** (the steward, under D191), revised twice under D191: after Codex's
read of round 1 (fourteen blocking findings and eight others, all taken in round 2) and after Fable's read of design §3 and §5 of

removal nobody presses and a lock between processes, and amends decided rules others rest on. Every finding was checked against the
code and taken (design §11). The owner decided point 7 (note below). On 2026-10-21 the install's set-aside trees held 37.4 GB
in 1,982,441 files, 87% of its `data/`, of which 90% of the bytes lay under a build folder's name; in the one folder measured apart, its `node_modules` folders held
52% of the bytes and 77% of the files, `bin/` and `obj/` 35%, git's files 12%. Each kind Daoris keeps cleaned itself by its own rule
or by none, and This Daoris showed sizes and no rule (design §0, §1). The contract is `docs/2026-10-21-cleanup-design.md`.

1. **Every kind has a rule, described in one table.** The design's inventory names every entry of D172's table, its writer and reader,
   its rule today and what may remove it, and marks the kinds with none (§1). A table in the driver library, `KeepKinds`, describes
   each kind's default, what the person may set, its bounds and its words, and runs nothing; each kind's removal is one typed
   operation in the driver library, which the pass, the route and the terminal alone call (D194 point 4). One effective policy is the
   only reader of a kind's days, every reader of the set-aside days among its readers (§2.1).
2. **The person's choice is a standing choice**: `driver.json`'s `keep` (set-aside days and `whole`, downloads' days or `never`, logs'
   days up to 30, history's age, the floor), absent meaning the default, judged by `StandingChoices` on both paths, set at the
   terminal by `daoris driver keep`, which D194 hands to the driver's program, and proposed by Ask Daoris through the `setting` door;
   each choice arrives with the act it governs (§2.2). Only what the disk cannot say again is durable: each kind's last run and when
   each download's current unused stretch began, cleared by a pass that finds it used, in `data/keeping.json`, written only under its
   keep lock; and the slim's manifest beside its folder, with when each path's removal ended (§2.3).
3. **A tree set aside drops its package folders once it has settled.** Before the look takes the repository's hold to move a tree,
   it asks git which folders the tree ignores whole and keeps as droppable only a `node_modules` beside a `package.json` git tracks,
   with no repository and no link in it: its producer discards it whole at every clean install, so nothing kept there outlives the
   next one. Inside the hold, the last look checks that judgement again by the reads it already makes. It writes those paths in a
   manifest beside where the folder will go, before the move. At the first pass an hour after the move, outside every hold, where
   nothing in the folder was written since, it removes exactly those, each checked again to lie inside the folder, never following a
   link, `DeleteNeverFollowing` checking its own argument too. The purge reads what the slim removed as no write, reads the folder
   above a removed path against when that removal ended, and checks each entry's creation time as well as its last-write time. Git's
   tracked files, `bin/`, `obj/` and everything else wait the folder's days; `obj/` may join later on evidence, `bin/` never; where
   anything about a path is unknown, it stays (§5, §7).
4. **Three triggers, one run at a time.** The look's pass, in the tidy's task, runs each rule at its pace (§3.1). Below a free-space
   floor (by default the smaller of 10% of the volume and 20 GB, a trigger and not a reserve, read from the operating system for the
   Daoris folder and for each entry its acts free from, each volume by its own floor) it runs at once only what can be made again, each
   with its own guards: the slims due, unused downloads but never one whose rule is `never`, the browser's caches once in each stretch
   below while the shell says its browser is not running; and says the rest in *What needs you* (§3.2). The person's *Free up
   space…* lists first what each rule takes now and what could go early, then starts a run with an id that removes exactly what was listed, each judged again; the list is open to anyone, the removal is the person's, confirmed in
   the window from a terminal and refused alone from a session's environment (§3.3). Every removal runs under one run lock on the home,
   tried and never waited for, its holder named, bounded, a stop heard between paths (§3.1).
5. **This Daoris shows each kind** on a *Disk space* card: its size with when it was counted, its rule with *Change…* where it is the
   person's, its next and last clean, and a run under way; sizes come from a bounded walk per kind through `WiringSizes`, never a ledger
   and never a walk of the whole home on a look (§4). The terminal twins are `daoris-driver space` and `daoris-driver space free`, which
   reads the run to its end (§4.4).
6. **Safety**: nothing a session uses is removed, judged by what is known of each thing's use and never by a rename's success alone;
   a downloaded version by the binaries each running session resolved, under the use files' keep locks held per version from the
   judgement to the rename, once every writer of those files takes the lock (§3.5); nothing outside the home is touched; only what
   is known to be made again goes by itself before its time; every removal is said; what a clean would remove is seen before it
   runs; each kind has one remover, Tools' delete of a version taking CACHECLEAR1's act; a failure and the unknown keep (§6).
7. **History's age, decided by the owner** (note below). The person may set an age for finished history, default none: the press
   alone. It is cleared through the clear with every refusal holding, and amends the history clearing design §7 once this is accepted
   (§3.6).
