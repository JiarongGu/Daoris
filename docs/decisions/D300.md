## D300 — The adapters' development is a workspace kind with paths, mapped to its own workflow (2026-11-16)

**Decision (ADAPTERROOM1).** The adapters' boundary is the workspace kind `adapter`, whose paths are `src/Daoris.Adapters/**` and
`daoris.adapters.lock`, which this repository maps to `tools/workflows/daoris-adapter.json` (its work releases the package it changed
and commits the lock row; a first check, `adapters-lock`, sends back a change no green run released; then the gates the change reaches,
none an adapter suite). Nothing infers a kind from paths: adapter work is asked as that kind (area `code-structure-and-process.md`, the
adapters row; area `workflows-review-landing.md`, rule 2).

**Why.** The owner decided (2026-11-16) that an adapter is a completed package tested only in its own development, and that the
room/repo design is Daoris's own purpose, so the boundary is declared with Daoris's own place features.

**Rejected:** a room (a room chooses no workflow, and giving it one would be a second way to choose a workflow); a repository of its own
(the kind holds the boundary without splitting the history); inferring the kind from a change's paths (a choice made for the person
that a kind's mapping already makes explicit).

**Left:** no workflow node runs an adapter suite or `adapters.ts release` yet (ADAPTERCHECK1, ADAPTERRELEASE1).
