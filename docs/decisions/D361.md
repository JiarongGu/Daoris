## D361 — A running environment is a shared, versioned resource: sessions that only use it lease the line's instance, a branch that changes it gets its own (2026-11-25)

**Decision (SHAREDENV1; the owner's direction of 2026-11-25; builds on D290's deployables and D349's per-repository frameworks). Provisional:
the brainstorm it was designed by had one maker answer, not two (see *How it was reached*); points 3 to 6 are the ones to hear a second maker on
before slices b to e build on them.**

1. **Why.** A game server, a work project's docker stack or a database is run today by each agent that needs it: a client's gameplay
   change starts its own server, so a machine with many agents holds many copies of one thing, each with its own ports and state, and
   none says which version it is. Collaboration is many agents, not one doing everything, so the environment is the shared thing
   and the agent's use of it is the small thing: an agent leases a running instance; the instance is not the agent's.
2. **An environment and its version.** A repository declares each in its own `daoris.json` under `environments`, beside
   `deployables`: `id`, `inputs` (repository-relative pathspecs, a path or a glob, whose matched content makes it what it is), `start` (its own command; Daoris
   supplies no way to run one, D349), `ports` (names; Daoris gives each instance its own numbers) and `graceSeconds`
   (`EnvironmentDeclaration`). Its version is a 12-digit digest of its id, its start command and the sorted port names and the content id each input
   has at a tree (`EnvironmentVersion`; an input's content id is a digest of the (path, blob id) pairs its pathspec matches there). A version is content, never a counter or a commit: two trees with equal inputs are one version
   wherever they stand, so a commit that touches no input moves nothing and a reverted landing is a move back to a version already known.
3. **Who changes one.** Daoris judges, never the agent: a session of the owning repository whose branch's version differs from the
   version at the commit it forked from, and from the line's tip's, changes the environment; one that only lags a landing that moved the
   inputs, or whose change the line already holds, only uses it and leases the shared instance (`EnvironmentUse.Changes`). A session of
   another repository has none of the inputs and only uses; which environment it needs is read through the deployables' `provides` and
   `consumes` (a later slice).
4. **Leases.** A lease is a machine-local record `(session, environment, instance)` that Daoris takes for a session, not a time-out
   an agent renews: an agent dies without saying so, and Daoris already watches each session's state, so the lease lasts while the
   session does and is let go with it. A session holds one lease for an environment, the last it asked, so one that goes from using to
   changing (or back) is moved by its own next lease. A lease follows its instance: an instance moved to a new version keeps its id and
   its ports, so a leasing agent is told no new address.
5. **A changing team is isolated.** Its instance is keyed by environment and branch, runs on ports taken from the machine's pool and
   is leased only by sessions of that branch: a second agent of the team joins the instance, and a session of any other branch, the
   shared instance's holders included, is never moved onto it. The branch's instance follows the branch's version (a lease asked at a
   new branch version restarts it and its holders follow). A branch whose inputs come back to the line's leases the shared instance,
   and its own goes after its grace. Data an environment keeps is the instance's own namespace, declared with the environment (a later
   slice); the shared instance's data is never a branch's.
6. **Upgrade on landing** (a later slice). The line's tip moves with the merge tool's landing; where that changes the environment's
   version, Daoris starts the new version beside the old on other ports, waits for its health, swaps the shared instance to it and
   re-points every lease at it, then stops the old. A new version that does not come up leaves the old one running, says the shared
   instance is behind the line with the reason, and gives the finding to the landing's session: it is never a question to the owner.
   A reverted landing is the same move to the earlier version.
7. **Failure and cleanup.** The instances and leases are one machine-local ledger, judged again at each start and look: an instance
   whose process is gone is dropped and the next lease starts it, a lease whose session ended is let go, an instance no lease holds is
   stopped once its grace has passed, and a process the ledger no longer names is found by the mark the host gave it and stopped
   (a later slice). A start runs outside the ledger's gate, under a deadline, and a session
   that leases an instance still starting waits on that start; one that fails or runs out of time (a move of a branch's instance
   included, which may have stopped the old process) drops the instance and every lease on it, so the next lease starts it again. A sweep
   stops each instance on its own and says the ones that would not stop.
8. **Admission counts instances, not leases.** Three agents on one server are one process. The machine's admission is told how many
   instances run (`EnvironmentLedger.Count`), and a new instance past what it holds takes out the instance idle longest
   (its grace is a courtesy, not a claim on a place) and is refused, said as such, only where every instance is held; a lease of a
   running one never is. The first slice takes the capacity as a number; the heavy-run admission's own dynamic capacity (ADMITDYNAMIC1, not
   on the line when this was written) reads the count when it lands, and an instance holds no slot of a check's heavy run.
9. **Machine-local and shared.** Processes, ports, docker, the ledger and the leases stay on the desktop and are never in a record
   a shared host answers. A shared host may carry later, with no machine path, only the facts the others plan on: an environment's
   id, the line's version of it and whether the shared instance stands at it.
10. **The first slice** (`Workflows/Environments/`, pure, no process): the declaration, the version, the ledger and `SharedEnvironments` over
    a seam to the machine's processes (`IEnvironmentProcesses`). Its proof, on a stand-in server: two sessions of one repository
    lease one instance and it starts once; a third whose branch changes the inputs gets its own on another port while the first two are
    untouched; its branch-mates join it and another branch never does; what no lease holds stops after its grace; a start that
    fails leaves nothing; admission counts instances.

**How it was reached.** A brainstorm (`sharedenv-1125b`, again as `-1125c` and `-1125d`) was asked of `claude-code-acp` and `codex-acp`; the
second maker's account was cooling all three times, so one maker answered each time and this is not a cross-maker view. Its eight proposals (the
declaration and the content hash, Daoris's own judgement of use and change, machine-local lock-held leases, a branch-keyed instance
with pooled ports, start beside then swap on landing, reconciliation with counted instances, a first slice with a stand-in server, and
the declare/run/shared-host split) are what points 2 to 10 take; it left the real process host, the lease's tie to the session's
state, the landing seam and the heavy-run admission's slots open, which are the later slices.

**Rejected.** *A time-out the agent renews:* silent deaths and a wedged agent hold an instance up, and Daoris already knows a session's
state. *An instance of each agent:* the cost this removes. *The commit or a counter as the version:* each commit would move it and
restart a server for work that touched none of its inputs. *Moving every session onto a changing branch's instance:* it puts the
people on unlanded work. *Counting leases in the admission:* three agents on one server would take three places for one process.
