## D361 — The machine's room for heavy work is measured, never a number: learned costs, the person's measured share, backed-off concurrency, a fair share by project and agent (2026-11-25)

**Decision (ADMITDYNAMIC1; the person's direction of 2026-11-25, widened the same day; replacing OWNERRESERVE1's fixed reserve and
`CheckAdmission.Need`, and `CheckRules.Ceiling` as the auto limit).**

1. **Why.** On 2026-11-24 the default reserve (a third of the memory, 21 GB) left six quests waiting with no check running for over
   two hours while 25 GB stood free; before it three checks at once beside the person's own heavy work timed tests out by the
   dozen. Both are one fault: the room was a number somebody wrote, and a number is wrong on every machine and every hour.
2. **A cost is learned, per repository, kind and gate** (`LearnedNeeds`, `admission/learned.json` in the home). A run's peak
   memory (the job's `PeakJobMemoryUsed`), its mean cores (the job's CPU time over its wall time), its wall time and whether a
   test of it timed out are kept for its last eight runs; where there is no job (off Windows) a run learns nothing and the declared
   cost stands. After `LearnedAfter` (two) runs the
   learned need (the larger of the last runs' peaks, a tenth over; the median cores) replaces the declared one, the declared (the
   kind's default, `LoadKind.Declared`) standing only until then. A gate that has never run asks the declared cost.
3. **The person's share is measured.** Each look beside the admission samples the machine (at most every five seconds, kept in
   `admission/room.json` so every process reads one series): what it holds in use, what Daoris's own processes hold
   (`DaorisShare`), the CPU busy. The person's share is the use outside Daoris; their **headroom** is how far it stood above its
   present in the last ten minutes, plus a margin (2 % of the memory, 1 GB at least). What is kept free is the larger of the
   headroom and the person's floor (point 7).
4. **Admission is free now against the learned need.** A run is admitted when what is free, less what runs still starting will
   take (their need, while their first gate has not ended), less what is kept free, holds the run's learned need. The cores a
   gate keeps busy are learned and shown, and steer the limit through the processors' saturation (point 5), not a wait of their own.
   The first run asks only the floor, so a machine never starves with none of Daoris's runs on it, and a pinned `checks` keeps
   only the floor. A wait names the number that held it (`CheckWait.Reserve`, `Memory`, `Slots`).
5. **Concurrency backs off and grows back** (`RoomPressure`, additive increase, multiplicative decrease, kept in
   `room.json`). The limit starts at the processors' ceiling. Free memory under what is kept, the CPU busy at nine in ten for
   ten seconds, or a run whose tests timed out since the last pressure halves it (one at least, at most once in thirty seconds);
   a minute with none adds one back, up to the ceiling. The person's `checks` pin overrides it, as before.
6. **One admission for every heavy thing Daoris starts, and a fair share of it.** The judgement is `CheckAdmission`'s, so a
   check, an integration's gated line, a session's `run-heavy` and a leased environment or GPU meet one rule. The limit is shared
   by project (a repository) and by agent (a session): a project asking beside another that has asked in the last two minutes
   holds the limit less one seat for each of those, one at least; an agent holds its project's seats less one for each other agent
   of the project that has asked as recently, one at least; where none else has asked a project or agent may use the whole of it, so
   nothing idles. A kind has a bound a repository declares (`loads` in `daoris.gates.json`: `max` at once, `perAgent`, `share`),
   an environment's and a GPU's by default one per agent.
7. **The person's setting is a floor and an override.** `reserve <gb>` is what is kept free **at least**, the measured headroom
   raising it where the person's own work swings; `auto` (the default) has no floor beyond the margin; `checks <n>` still pins the
   concurrency over the backed-off limit. `reserve 0` with `auto` headroom is the measured room alone.
8. **Sharing before starting** (`LoadLeases`, `admission/leases.json`). An environment or a GPU is a lease named by repository, kind
   and name. An agent asks the lease before it starts one: a live lease of the same name whose repository's rule is `share: reuse` is
   joined, never started again (the asking agent is a user of it; the last user to let go says the owner to end it); a lease of
   `share: own` or none live is admitted as a new one by points 4 to 6 and counts against the kind's bound and the limit. A lease
   whose holder's process ends frees its place, as every hold does.
9. **Shown on the reserve's row.** The setting's row and `daoris settings reserve` say why the room is what it is: the machine's
   use, the person's share and headroom, what is kept free and by which of the two, the limit and the signal that set it, and
   the learned or declared need of what waits.

**Rejected.** A better constant (a fraction, 6 GB): the 2026-11-24 default was one, tuned by hand to this machine and wrong on the
next. Declared needs per gate kept beside learned ones: two truths for one number (rule 4); the declared stands only until a
gate has run. Fairness by queue order alone: a project asking for many environments would take every place before another asked;
a seat kept for each project that has asked recently leaves room without idling it. A per-process memory cap on a run (a job
limit): it turns a bad estimate into a killed run, where this one turns it into a wait.
