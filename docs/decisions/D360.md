## D360 — The home learns each gate's timeout from its green wall times, keyed by the main checkout's folder; the overruns journal stays a file of the checkout (2026-11-24)

**Decision (GATESPLIT1c; the build of D355 point 4, which stands).**

1. **Every run that ends a gate green teaches its time.** The merge tool records a gate's wall time into the home's `check-budgets` entry when the gate
   ran whole, ended green and replayed nothing, whatever the run's kind (a merge, the full set, the CI): the only record of
   per-gate wall time before this was the merge record, which holds the fast tier's nine gates and none of the heavy ones (their green times were in no
   record at all; the heavy-run records hold one wall time per run). The gate's budget is its pin, else the nearest-rank ninetieth percentile of its newest
   twenty greens times 1.5, rounded up to a whole minute and never under five, once three greens are kept; else the lane's default. A learned value that
   rises past 1.25 times the one last said is said once in the next run (`check-budgets.ts`, laid over the declaration by `budget-overlay.ts`; the driver's
   `CheckBudgets` answers the same cases, `tools/merge/fixtures/check-budget-cases.json`).
2. **The repository's key is the folder name of its main checkout**, a linked tree's included, and a folder that is no repository's own top is named by itself.
3. **Seeding takes the greens the merge record holds and pins the rest.** The values the declaration held are seeded into this machine's home: a gate with
   greens in the merge record takes them as its history, and keeps its declared timeout as a pin (with its old reason, marked seeded) only where the greens
   teach less than it; a gate with none (every heavy gate) keeps its declared timeout as a pin until it has learned its own, and an owner unpins it.
4. **The older member is read until it is gone.** A repository still holding `timeoutMinutes`, `memoryGb`, `alone`, a set's `timeoutMs`, `treeBaseline`,
   `localInputs`, `devkit` or `sensitive.patternsFile` in its gates file keeps working: the home's value wins, the member is the fallback. The reader ends when
   `declaration split` (GATESPLIT1b) has converted every repository the home knows and the examples.

**Rejected.**

- *The overruns journal in the home's record* (D355's table): its only writer is the merge's verification and nothing reads it but the steward by path, so a
  home record would add a second shape for one appended file; the member that named its path (a machine's tuning that nobody tuned) is gone, and the journal is
  `local/verify-overruns.jsonl` in the checkout, as it was by default.
- *The driver's `DAORIS_REPOSITORY` as the key*: a session's tests inherit it, so a fixture folder read the live record of the repository around it.
- *Pins for every seeded timeout*: the gates with greens would never learn; a pin stands only where the greens teach less.
- *The learned timeout bounded by the lane's default as its floor*: a full run's default of ten minutes would then bound a fast gate's learned five.
