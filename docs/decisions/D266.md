## D266 — The person's settings are merged beneath what outranks them, their memory file is appended to the system prompt, and Codex's home rides its adapter's session configuration (2026-11-11)

**Decision.** D262 left the person's settings file, their memory file, the Chrome switch on the protocol door and Codex's home
unhanded (AGENTFREE1's census row 23). Each now reaches its session by a door kept for one session, each family a default of the
person's rules (`own-settings`, `own-memory`, beside D262's four). The person's `settings.json` is merged into the session's rules file
beneath everything that outranks it, in a run of their own or at the session's start: Daoris's composed rules, the repository's
project settings in the session's folder and the account's own settings. A list joins the lists above it, as the harness joins lists
across its tiers, so the person's denies hold and Daoris's still win; a value comes in only where none of those sets one. What signs
in, sets the mode, names plugins or switches hooks off is never taken, nor a variable the session already holds or any provider's or
Daoris's, and a session shaped for one job takes nothing that widens it. The memory file is appended to the system prompt
(`--append-system-prompt-file` on the native door, the SDK's preset with the text appended on the protocol door), and the Chrome switch
rides the SDK's `extraArgs` there. A Codex session is handed the person's Codex home as codex-acp's `CODEX_CONFIG`, which the adapter
passes as each thread's configuration over the account's: `config.toml` where the account's sets nothing, without the provider, sign-in,
approval policy, sandbox or trusted projects; `AGENTS.md` and the folders of the skills and prompts in `developer_instructions`.

*Rejected:*
- **Merging the person's file into the rules file as it stands.** D262's reason holds: the one command-line tier would raise their
  user settings over the repository's project settings. Merging beneath keeps the order a run of their own has.
- **Leaving the settings and the memory file unhanded.** The person's denies would not hold in a session, and their instructions
  would not reach it (D253 point 7).
- **The memory file in the standing block.** The block rides a start's first prompt only, never a resume, and a compaction can lose
  it; the system prompt is read on every run, as the memory file is by hand.
- **Codex's `-c` overrides or a written `config.toml`.** The adapter starts `codex` itself and takes no flag of Daoris's, and Daoris
  writes no account home (D230).
- **Codex's servers in `CODEX_CONFIG`.** The adapter replaces the configuration's `mcp_servers` with the open's whenever the open
  names any, and Daoris's connector always rides it; they belong in the open's connector plan, not built here.

**Amends** D262 (the settings file and the memory file are handed).

**Note, 2026-11-12 (D284, the access model).** A session shaped for one job takes the person's own allows, folders, hooks and project
server approvals like any other; only a posture its step, rule or pass declares narrows it. The start's mode still outranks the
person's settings.
