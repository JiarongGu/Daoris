## D174 — Which model does what is a living reference by role, with its evidence, read by this development's dispatch and by Daoris's own sessions (2026-10-16)

**Decision (the owner's direction).** The owner, 2026-10-16: *"this is not a fixed say 'Sonnet': we need some kind of
reference or setup for which model is good for what, which version is currently the best, and when to use Codex for
outsourcing decisions; and this is also a kind of logic we need to use in Daoris for a better development cycle."*

1. **Roles, not names.** Work is dispatched by role: steward, orient, build-exact, build-judgement, review,
   decide-support, help. Which harness, model, version and effort fills each role is recorded in
   [`docs/model-roles.md`](../model-roles.md), with the evidence for each choice and the date it was reviewed. The
   dispatch skill reads that reference; no brief names a model except by its role's current entry.
2. **Evidence moves it.** A new model version enters as a trial for a role, is tried on one or two rows of a batch,
   measured (`tools/subagent-usage.mjs`, D160's targets) and judged by its merge; it is promoted, kept on trial or
   retired with the date and the batch. A choice is never changed by impression alone.
3. **Another maker for a different opinion, on one's own initiative.** The reference says when an agent of another
   maker is asked (a decision or design before it is built on, a classification of what may act without the person,
   two plausible shapes, a defect whose cause has not shown, the backlog's order, a merge touching deletion, history or
   secrets) and how its findings are handled (verified, routed, the dropped ones said). Never a step every batch passes
   through (the owner, 2026-10-16).
4. **Daoris uses the same logic.** MODELROLE1 makes these roles Daoris's own per-role setting for the sessions it
   drives, in D98's terms (a harness's model and effort), with D155's second opinion as the review role and the same
   triggers for asking another maker; its reference starts from this one and is measured the same way, once D160's
   targets hold for three batches.

### Rejected

- **Fixed names in the dispatch rule** (D160's first table named Sonnet and Opus outright): a name goes stale with every
  release, and the evidence for it was not kept beside it.
- **Another maker as a mandatory gate**: the owner asked for it as a regular habit of judgement, not a step.
- **Choosing by price or by benchmark alone**: the merge (gates, review findings, the window) is what decides here.

### Amends

- **D160**: its model table becomes the reference's first entries; its targets are the reference's measure.
- **D155**: its second opinion is the reference's review role, for this development and for Daoris.
