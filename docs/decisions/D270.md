## D270 — A system department's plan tool is served by the session's department, not by its work alone (2026-11-11)

**Decision.** The connector's `system_plan` is served only to a quest's session (build, design, exact) whose record's department is
registered as a system: the call layer reads the department's kind from the registration with the work (`SessionWork.InSystem`), lists
the tool to that session alone, and refuses it in words to every other work, Ask Daoris and an intake included. The tool table keeps one
column per work, and a system department's session is that column with `system_plan` beside it.

*Rejected:* serving `system_plan` to every quest's session as one of its work's own tools, which lists its definition at the start of
every repository's and folder's session, where it can only be refused by its box, and puts a build session's served definitions past the
measured budget (CONTEXTONE1d2) that keeps what a harness loads at its start bounded; raising that budget to make room, which spends every
repository session's context on a tool none of them may use; a column of its own per work for a system department, a second copy of three
columns that differ by one tool.

**Amends** the call table's rule that a session is served by its work (from D212, D230). **Held by:** PLACEWORK1h.
