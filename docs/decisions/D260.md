## D260 — A line's later quest that is a run of its own gets a tree and a branch of its own (2026-11-11)

**Decision.** A new quest of a line goes into an earlier part's tree only where that part is of its own run: a chain's step in the same
repository (`QuestRuns`, the chain's first quest there). Any other quest of the line, an ask's sibling quest or a request back from another
repository, starts in a tree and on a branch of its own, a further part of the line, so no two runs work one branch. D167 point 4's
"the entry is what a tree belongs to" now reads "the run is what a tree belongs to"; D259's tolerance of a branch two graph runs share
stays for branches shared before, and a plugin's event on one goes to each run whose own node awaits it there.

**Rejected.** Keeping the line's free tree for every later quest, as D167 point 4 had it, so a sibling's request ran on the work it
depends on: it put two runs' commits on one branch, which neither run's review, landing nor plugin answers could tell apart, and the
install's runs waited on it for good. Splitting the branch while sharing the tree: one tree has one branch checked out, so two runs in one
tree still commit onto one branch.
