## D222 — Words a person writes need no language; Daoris's own words translate through its catalogues, in as many languages as it ships (2026-11-02)

**Decision (the owner's direction, 2026-11-02; I18NOPEN1).** Daoris is not an English-and-Chinese application, so no configuration
asks for a fixed pair of languages.
1. **Authored words** (a role's name, a plugin step's title and about, a saved workflow's name, a kind of task's label, any text a
   person or a plugin writes into configuration) are one value: a string as written, or an object of language tags to text (any tags,
   at least one). Nothing requires a language. A page shows the text in the viewer's language where one is given, else its base
   language's, else the text as written (the string, or the object's first entry). Today's `{ "en": …, "zh": … }` records are valid
   as they are.
2. **Daoris's own words** (the workflows, deliveries, presets, steps and roles it ships, and all chrome) translate through the page's
   catalogues, keyed by id, never by per-language fields in shipped data. The shipped data keeps one English text as the terminal's
   words and the fallback; a census holds every shipped id keyed in every catalogue present.
3. **The catalogues are open.** The languages the page offers are the catalogues it ships (today `en` and `zh`); the parity checks
   hold across every catalogue present, `en` the source. Adding a language is adding a catalogue.

**Why.** Requiring both an English and a Chinese name (`RoleCatalog.cs`'s refusal of a role missing either; a plugin step's
`title`/`about` as `{en, zh}`) makes a person who writes in one language, or in a third, invent text they cannot check, and makes
every new language a schema change. Chrome already translates through catalogues (the brief's rule that authored content stays as
written); this extends the same rule to configuration.

**Rejected.** A fixed `{en, zh}` pair on authored records (today's role names and SETUPUX1f's step words): it is the defect. A
translation map required on authored text: nothing guarantees an author can write it. Per-language names in shipped data: the
catalogues are the one home for Daoris's own words.

**Note, 2026-11-02 (I18NOPEN1, built).** Authored words are read by `AuthoredText` (driver) and `locales/authored.ts` (web), twins: a tag is a language tag (`en`, `zh-TW`), a text is not blank, and a step's `title`/`about` hold 60/240 characters each text. A role's record, the role door's press, `PLACES`' `roleName` and `ROLES`' `name` carry the value as it is stored, so `{ en, zh }` records read and write unchanged; the seeded roles keep their pair until their names move to the catalogues. `role set --name "…"` is the text as written, kept as `en` when `--name-in <tag>="…"` (repeated) adds another language, `--zh` stays as `--name-in zh=…`, and Ask Daoris's `role_propose` takes `name` and `name_in` in place of `name_en` and `name_zh`. The page's languages are the folders under `locales/` (`languages`, `languageName`, `pageLanguage`); `i18n:check` holds every one against `en`, and `names:check` holds the keys the glossary names in each and, where a term gives its name in a tag (`term.<tag>`), that label's wording of it.
