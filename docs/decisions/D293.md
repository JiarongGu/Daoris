## D293 — A session is the work's passage through its workflow; it is done when its workflow is done, and Daoris checks only in a workflow's step (2026-11-14)

**Decision (the owner, 2026-11-14; SESSIONLIFE1).** A session does not mean that an agent started. It is Daoris holding one piece
of work as it goes through its workflow: it begins when Daoris takes the work and ends when the workflow ends, landed, declined
or abandoned. An agent's conversation is something a step does inside it (the work, a fix the check or the opinion asks for), and
the agent saying it is done ends its turn, not the session.

1. **No workflow step runs after a session ends.** The checks, the second opinion, the person's look and the landing all happen
   while the session is open; what they find goes back to the same session, and its done is given at the workflow's end.
2. **Daoris checks only where a workflow says so.** A workflow that wants its work checked declares a `check` step, which reads
   what the work changed and runs the gates it reaches; a workflow without one has none run. No code checks every session
   outside its workflow.

**Why.** On 2026-11-14 every session closed its quest done at hand-back while its checks were still pending, because the
development graph gave the done (`holds`) before `content` and `landing`. Daoris then ran every reached gate for every done
session outside its workflow (`DriverHandbacks`): 541 checks failed on one machine, all of them Daoris's own (the tree gone with
its ended session, a log in use, nothing kept but a wrapper), and DONEREOPEN1 put 98 of them in front of the person as rows to
act on. Builders never heard a check's verdict, because their quests were already done.

**Rejected.** A session as one agent conversation, done at its hand-back, with the workflow's later steps run on its record
afterwards. Hand-back checks Daoris asks for every done session whatever its workflow (D219's observed check): it duplicated the
workflow's `check` step, a second way for one job (D228).

**Left.** The migration is SESSIONLIFE1 in `TASKS.md`: the session's record and states, the steps that wait on a session and
reopen it, the graphs' `holds` moved to the end, the hand-back checks removed (CHECKHAND1 starts it), and what the person's window
shows of a session. Its design goes through a brainstorm with both makers first.
