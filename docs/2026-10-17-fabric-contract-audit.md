# The collaboration fabric's contract audit, with two harnesses' native children measured (FABRIC-C0)

The audit D173 asks for before its first build. Read on 2026-10-16 from this tree at `b37018d74`, and probed the same day
on Claude Code and Codex. §1 maps each concept Daoris already has onto the proposal's primitives (its §3) and names the
store that stays canonical, which is D173's first guard. §2 is what the harnesses did when their native children called a
server, read off the server's own log and the harnesses' own events. §3 says go or no-go for C1 and C2 and reshapes their
rows.

Each claim carries one evidence label:

- **implemented**: read in the code at the cited line.
- **tested with stand-ins**: a test holds it with fakes or fixtures, and no real harness ran.
- **observed on the harness**: seen in §2's runs, from a log a program wrote.
- **unknown**: neither read nor seen. Each is listed where it matters.

**What the matrix says.** Each concept has one store today, and its writers are known. Row 5 has two writers of a
helper's state, but both are the desktop's, in one process. The fabric needs one store that does not exist yet: the binding of a
native child to the part it serves (row 9). Every other primitive has an existing home. Messages map to the channel (row
6) and to a helper's ask and answer (row 5). Commitments map to quests and hand-over (rows 2 and 4). References map to
knowledge ids (row 7). Authority maps to proposal and Apply, and to the handed rules (rows 10 and 11). A session's identity
on every session-scoped tool (`helper_ask`, `channel_post`, `go_ahead_ask`, `quest_respond`, `opinion_give`,
`permission_propose`) is the variable its connector's process was started with (row 9). §2 shows that on both harnesses a
native child calls with that same identity.

## 2. The probe receipts

**Setup.** The scratch repository is `_fixtures/fabric-c0/repo` (gitignored), with one empty commit. Every process started
with `DAORIS_HOME` set to the scratch's own `home/`. The server is a stand-in MCP server (`_fixtures/fabric-c0/probe/`)
with four tools: `probe_read` (allowed), `probe_write` (denied), `probe_unlisted` (named by no rule) and `probe_wait` (it

reports were not used. Seven runs, all on 2026-10-16.

## 3. C1 and C2: go or no-go

**C1a: go, reshaped.** Both harnesses expose the lineage of a child that Daoris did not spawn. On Claude it comes from the
hook and the stream; on Codex, from `_meta` on every call. Neither hands the connector a child identity in its environment.
So the binding is *observed* (L1, the harness's own signal), keyed to the existing part, and never a new session. Its end
is the part's end: a killed root produced no end signal for its child on either harness. The connector needs one new read,
each call's `_meta`, because today it reads its identity once, from the environment (row 9). The lineage it gets must not
travel whole: Codex's `_meta.workspaces` is an absolute path (D46, D47).

**C2a: go, with the identity rule changed.** D173's hazard is observed, not inferred: on both harnesses a native child's
calls carry the parent's `DAORIS_SESSION_ID`. Every session-scoped tool would therefore act as the parent, including
`helper_ask`, `channel_post`, `quest_respond` take and `permission_propose`. Neither harness issues a per-child credential.
Claude's agent-scoped server comes per type, and in one run it was shared by two siblings and closed with the first of them.
Codex's processes all share one entry. So the restricted binding is decided per call from harness-written lineage, never from an argument. Where
that lineage says *child*, read-only tools answer (`daoris.me`, `knowledge_search`, `knowledge_get`) and every
session-scoped mutation refuses. A call whose lineage cannot be read is treated as a child (deny by default). The probes
measured inheritance; they did not decide for C2a whether a hook-to-connector join on Claude is sound under load.

**C2b: go after C2a, on the install's real doors.** It measures what this audit did not: ACP for both harnesses, Codex's
approval through Daoris's own permission answer, and a person's stop.

The reshaped rows, in backlog form:

- [ ] **FABRIC-C1a — a native child bound to its session part, from the harness's own lineage** (service/driver; after C0). Both harnesses name a child's lineage without Daoris's help, Claude through the `PreToolUse` hook's `agent_id` joined to `_meta`'s `claudecode/toolUseId` and its stream's `task_started`, Codex through `_meta`'s `x-codex-turn-metadata`, and neither gives the connector a child identity in its environment (`docs/2026-10-17-fabric-contract-audit.md` §2). So the connector reads each call's `_meta` and the driver records an observed binding (harness, native id, parent id, provenance) against the existing part, never a new session; it ends with the part, unsupported signals stay unknown, and `_meta`'s paths are never stored or sent. Contract: D173's guards; proposal §3–§4, §11. Proof: real child calls on both harnesses tell a child, a grandchild and two siblings apart; a killed root marks its children's bindings lost; canaries 1, 2 and 9.
- [ ] **FABRIC-C2a — a child's calls read-only by their lineage** (service; after C1a). A native child calls with its parent's `DAORIS_SESSION_ID` on both harnesses (audit §2), so the connector decides a restricted binding per call from the harness-written lineage, never from an argument: read-only tools answer (`daoris.me`, `knowledge_search`, `knowledge_get`, ids and ranges as the first references), and every session-scoped mutation (`helper_ask`, `channel_post`, `quest_respond`, `go_ahead_ask`, `opinion_give`, `permission_propose`) refuses a child or a call whose lineage cannot be read. Contract: D173's second guard; D107; D89/D170. Proof: a stand-in harness's child is refused each mutation and served each read; a forged id in arguments changes nothing; the root's calls are unchanged; canaries 3 and 8.
- [ ] **FABRIC-C2b — the two-harness canary on the install's doors** (parent; after C2a). Each harness's native child, over the door Daoris really uses (Claude's pipe and ACP, Codex through codex-acp, with its MCP approval answered by Daoris), reads the same permitted reference and is refused a mutation. Receipts: versioned calls, refusals, a person's stop and a parent's kill, setup steps, time and usage (or *not measured*); helpers and channels rechecked unchanged (canary 10).
